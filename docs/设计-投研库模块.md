# 投研库(Research Library)· 结构设计 v1

> 状态:已实施(2026-10-02)。本文是投研库的**唯一结构契约**,新增研报只写文件、不改代码。
> 一句话:研报是 git 版本化的 Markdown 文档(`docs/research/*.md`,YAML frontmatter 承载结构化元数据),
> 后端只做「解析 + 渲染 + 索引」的薄服务,前端一个列表页 + 一个阅读器,零数据库迁移。

---

## 1. 定位与边界

投研库存放**人写的深度研究**——生意模式、护城河、财务拆解、估值区间、反方证伪——
与现有页面的分工:

| 页面 | 数据性质 | 生产方式 | 更新频率 |
|---|---|---|---|
| 证券列表 / 个股详情 | 量化评分、行情、财务列 | 采集脚本自动化 | 每日 |
| 农价·量价 / 情绪日报 | 行业与市场监测 | 采集脚本自动化 | 每日/每交易日 |
| **投研库** | **长文深度研究 + 结论** | **人(AI 辅助)撰写** | **不定期,按标的** |

边界:投研库**不重复**详情页已有的量化列(评分、分位),专注「解释为什么」;
引用数据必须注明(报告期/时点, 来源),与采集层数据同源时可交叉核对。

## 2. 核心决策:文件即真相,不建表

- 研报是长文档,天然适合 Markdown + git:可 diff、可评审、可回滚,历史版本即 git 历史。
- 零 DDL、零回灌、零迁移——与情绪模块「读时计算」同一哲学:**存储层越薄越稳**。
- 未来若需要「研报结论」参与量化筛选(如按 conclusion 过滤全市场),再考虑落一张
  索引表,由 frontmatter 单向生成;v1 不做。

## 3. 存储规范

### 3.1 目录与命名

```
docs/research/{code}-{名称}-{YYYYMM}.md     # 一份研报一个文件
```

例:`605599-广信股份-202610.md`。同一标的后续深度更新→新文件换月份后缀
(`605599-广信股份-202703.md`),旧版保留;列表 API 按 date 倒序,天然「最新在前」。

### 3.2 Frontmatter 契约(列表页与头卡的渲染依据)

```yaml
---
code: "605599"          # 6 位代码(A股);港股 5 位;美股 ticker。必填
name: 广信股份           # 展示名。必填
title: 广信股份深度研报   # 文档标题。必填
type: deep              # deep=深度研报 | track=定期跟踪 | thesis=专题论点
date: 2026-10-02        # 撰写基准日(数据「as of」)。必填
status: final           # draft | review | final
conclusion: 观察        # 结论档位:买入 | 增持 | 观察 | 回避 | 卖出
price_ref: 14.70        # 撰写时股价(元/港元/美元,与市场一致)
val_low: 11             # 估值区间下限(每股)
val_high: 22            # 估值区间上限(每股)
val_method: 中性E6亿×14x + 悲观E4.5亿×10x   # 区间怎么来的,一句话
tags: [农药, 光气, 周期底部, 高分红]        # 列表页筛选标签
summary: >-             # 一段话核心结论(列表页摘要)
  光气牌照寡头 × 杀菌剂隐形冠军,周期底部盈利仍 8 亿+,
  类现金覆盖市值六成;反方核心在产品单一与景气二底。
---
```

约定:`code` 同时是通往详情页 `#/stock/{code}` 的链接键;`conclusion` 与估值区间
**必须**在正文有推导章节支撑,`val_method` 是防「拍脑袋区间」的自检锚。

### 3.3 正文章节规范(深度研报模板)

固定骨架,反方章节**强制**存在:

1. **生意模式**——赚什么钱、上游下游、定价机制、周期属性归因
2. **护城河**——按供给壁垒/成本/客户粘性/规模分层论证,每条标注「可验证证据」
3. **财务拆骨**——五现金流维度拆解(经营/投资/筹资/分红/资本开支),盈利质量
4. **成长与催化剂**——量的扩张 vs 价的周期,时间表
5. **估值区间**——多种方法交叉(周期股:中性/悲观盈利 × 历史估值带;股息率法;清算/重置底线)
6. **反方观点(证伪章)**——**必须成章**:最强反方论证 + 数据,每条给出「若成立对估值的影响」与「观察哨」指标
7. **数据附录**——所有引用数据的来源清单(URL + 时点)

写作纪律:观点与事实分离;所有数字可溯源到附录;无法验证的推测显式标注「未验证」。结论推演(置信度分级/敏感性/反向指标/验证时点)以「推演注」形式融入正文对应小节、验证时点表并入反方总结算,不设独立自检章(2026-10-03 起)。

## 4. 服务层 `backend/app/api/research.py`

```
GET /api/research/list                 → 全部研报的 frontmatter 索引(date 倒序)
GET /api/research/report/{slug}        → 单篇:meta + markdown 渲染后的 HTML + TOC
```

- slug = 文件名去 `.md`;白名单正则防路径穿越(`^[\w\u4e00-\u9fff.-]+$`,禁 `/` 与 `..`)。
- Markdown 渲染:`markdown` 库 + `tables`/`toc`(unicode slug,中文锚点可读)扩展,
  服务端渲染成 HTML,前端 `v-html` 注入——内容是仓库内自有文档,信任源。
- 研报目录按 `app/main.py` 同款相对定位(`backend/app/api/` → `docs/research/`),
  不引入新环境变量。
- 依赖增量:`markdown>=3.4`、`pyyaml>=6`(纯 Python,无编译)。

## 5. 前端 `frontend/src/views/ResearchView.vue`

- 路由:`#/research` 列表 · `#/research/:slug` 阅读器;顶部导航新增「投研库」。
- 列表页:研报卡片(名称/代码链详情页、结论徽章配色——买入红/回避绿/观察灰,
  估值区间 vs 现价、日期、标签、摘要)。
- 阅读器:头卡(frontmatter 元数据)+ 粘性目录(h2 锚点,窄屏折叠)+ 正文排版
  (表格/引用/标题层级,沿用全站卡片视觉)。
- 移动端(≤600px):目录收进顶部 `<details>`,正文单栏。
