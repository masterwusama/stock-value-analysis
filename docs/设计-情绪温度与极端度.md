# 情绪日报 · 情绪温度 / 极端度 / 连续天数 详细设计 v1

> 状态:待评审(2026-10-02)。实施口径以本文为准,实施后合入《使用说明书》§10.8/§14。
> 一句话:状态机不动,并行加一条 0–100 的连续刻度(温度 T),极强/极弱日给出百分制
> 极端度 E 与档内三带(极端/标准/踩线),外加连续同档天数 streak,补足「强度 × 阶段」两个轴。

---

## 1. 背景与问题

现状四档状态机(极弱>回暖>极强>普通)是**硬阈值 OR 触发**:

```
极弱: R5≤-5% 或 一字跌停≥5 或 (跌停≥30 且 红盘率<25%)
极强: R5≥+4% 或 (涨停≥100 且 红盘率≥60%)
普通: 其余(回暖为转移目标词汇,采集端从未落盘,见 §7)
```

丢失强度信息的位置有两处,不止是展示问题:

1. **判档离散化**:R5=+4.01% 与 +15% 同为「极强」,一字跌停=5 与 =50 同为「极弱」。
2. **档内均值掩盖差异**:转移概率 TRANS 与溢价档 PREMIUM 均按档位取均值(极强次日
   +3.6%/胜率73% 是档内平均),踩线极强与极端极强的次日行为被同一行数字覆盖。

操作层面:极强/极弱日的核心动作是「持有还是兑现 / 抄底还是等确认」,档内高低直接
决定力度,目前页面上无从判断。

## 2. 总体思路:动什么、不动什么

**不动**(均有校准纪律,勿随手感改):

- 状态机阈值 `TH`、转移矩阵 `TRANS`、溢价档 `PREMIUM`;
- `sentiment_daily` / `sentiment_sector` 表结构(零 DDL、零回灌迁移);
- import_legacy 回灌路径(report JSON 键集不变);
- trap(陷阱日)语义。

**新增**:

- 纯函数模块 `collector/scripts/sentiment_score.py`(锚点分位表 + 温度合成 + streak),
  采集端与 API 端共用同一份实现,**单一事实源,杜绝口径漂移**;
- T 全天候计算(读时计算,不落库,理由见 §5.2);采集端为 md 报告与 daily.json
  落一份当时值(时点工件);
- 极端度 E、档内三带、背离检查、streak;
- 前端三处展示(状态卡/走势图/历史明细)。

## 3. 算法详细设计

### 3.1 指标与方向统一

全部输入均为 `sentiment_daily` 现有列(这是「读时计算」可行的根基):

| 指标 | 定义 | 方向 | 权重 |
|---|---|---|---|
| R5 | 国证2000 五日累计(`r5`) | 正向 | 0.35 |
| 红盘率 | `red_rate` | 正向 | 0.20 |
| 涨停家数 | `zt_count` | 正向 | 0.20 |
| 空头强度 | `dt_count + 2×yz_dt_count`(一字含流动性信息,加权) | **反向** | 0.15 |
| 炸板率 | `zha_rate` | **反向** | 0.10 |

R5 权重最高的理由:它就是本体系定义的「平均股价温度计」,其余补广度(红盘率)与
赚钱效应结构(涨停/炸板)。

### 3.2 锚点分位表 static-v1

T 的输入不是原始值线性映射,而是各指标的**历史分位数**——涨停数/跌停数重尾,
原始值刻度会被极端日拉爆;分位数天然把「近一年排第几」变成语义,正是百分制的本意。

原始校准样本(2024-01~2026-09)未在仓库留痕,锚点按三级出处标注:

- 【校准】直接来自现有校准常数,如 `zt_p90=100` 明确即涨停家数 p90;
- 【软锚】由校准阈值反推的近似分位(阈值本身校准过,分位是推断);
- 【插值】补形态的假设点,**待加固**(§4.2 校准脚本或 60 日切换验证)。

```python
# sentiment_score.py —— 锚点表 static-v1(值升序;百分位 0~1)
# 超出首尾锚点即钳制到端点分位(重尾饱和,100 分位按构造不可达,显示永不满百)
ANCHORS = {
    # R5:【软锚】r5_weak=-5%/r5_strong=+4% 为状态机边界,按 OR 触发占比与
    # 国证2000 5日波动(σ≈3.4%)反推分位 ≈ p8 / p92;尾部为【插值】
    "r5":   [(-0.15, 0.005), (-0.10, 0.02), (-0.05, 0.08), (-0.02, 0.25),
             (0.00, 0.40), (0.02, 0.60), (0.04, 0.92), (0.07, 0.98),
             (0.10, 0.995), (0.15, 0.999)],
    # 红盘率:【软锚】red_weak=0.25≈p8、red_strong=0.60≈p78(极强 OR 条件之一,
    # 占比宽于 R5 路径);中位 0.45 为经验值【插值】
    "red":  [(0.15, 0.02), (0.25, 0.08), (0.35, 0.25), (0.45, 0.45),
             (0.55, 0.68), (0.60, 0.78), (0.70, 0.93), (0.80, 0.985), (0.90, 0.999)],
    # 涨停家数:【校准】(100, 0.90) 即 zt_p90;其余为【插值】
    "zt":   [(20, 0.10), (35, 0.25), (50, 0.50), (70, 0.70),
             (100, 0.90), (150, 0.97), (250, 0.995), (400, 0.999)],
    # 空头强度 s=跌停+2×一字:【软锚】dt_panic=30≈p95(恐慌共同条件);其余【插值】
    "short": [(0, 0.10), (3, 0.30), (8, 0.55), (15, 0.80),
              (30, 0.95), (60, 0.985), (120, 0.998)],
    # 炸板率:【插值】(现校准未单列其分位,7 日样本形态佐证)
    "zha":  [(0.10, 0.15), (0.18, 0.40), (0.25, 0.65), (0.35, 0.85),
             (0.50, 0.97), (0.70, 0.998)],
}
WEIGHTS = {"r5": 0.35, "red": 0.20, "zt": 0.20, "short": 0.15, "zha": 0.10}
```

注:近期「北交所入情绪统计」修复后 zt/dt 统计口径新增 339 只北交所,而校准样本
早于该修复,涨停分布有轻微右移——静态表期间略偏严,60 日滚动窗口自纠,可接受。

### 3.3 分位插值

对升序锚点表 `[(v₀,p₀),…,(vₙ,pₙ)]`,输入 x:x≤v₀ → p₀;x≥vₙ → pₙ(饱和钳制);
否则在值空间线性插值。反向指标取 `1 − rank`。

### 3.4 温度合成

```
T = round( 100 × Σ wᵢ · rankᵢ ),  T ∈ [0, 100)
```

50 即历史中性;≥80/≤20 与状态机极强/极弱带基本重合(见 §3.6 背离检查)。
各分量 rank 保留 3 位小数随 payload 下发(极值说明文案引用)。

### 3.5 极端度 E 与档内三带(用户核心诉求)

- **极强日:E = T;极弱日:E = 100 − T**(统一语义「离中性多远」,越高越极端);
  普通/回暖日无 E,只展示 T。
- 档内三带(对称):

| 带 | 判定 | 含义 |
|---|---|---|
| 极端 | E ≥ 90 | 历史极值区,次日大概率高开兑现/恐慌溢出 |
| 标准 | 80 ≤ E < 90 | 典型极强/极弱形态 |
| 踩线 | E < 80 | 单指标驱动的边界触发,综合温度未跟上 |

「踩线」带信息量最大:典型形态如一字跌停≥5 单条件触发极弱但红盘率不差——
这种「单指标极端」与全面冰点的操作含义完全不同(前者结构性风险,后者周期底部)。

### 3.6 背离检查(顺带产出,零成本)

T 与状态机并行,天然可互检:

- `state=极强 且 T<80`:踩线极强,文案指出主导触发指标 vs 综合温度差距;
- `state=极弱 且 T>20`:踩线极弱,同上;
- `state=普通 且 T≥80 / T≤20`:综合温度已达极强/极弱带但状态机未触发
 (罕见,通常是多指标同向但均未过线),页面提示「温度与档位背离,关注次日确认」。

**明确不做**:现在不给 E 配条件转移概率(如「极端过热次日回落概率更高」)。
本项目对数字的纪律是校准说话,条件化 TRANS 需按 E 分桶重算样本,等滚动窗口
攒够再做;当前阶段 E 只做刻画展示(开放问题 Q5 相关)。

### 3.7 连续天数 streak

- 定义:从当日向回数**连续同档**天数,含当日;状态切换即重置,新档 streak=1。
- 计算位置:采集端 main() 从 history 推(与 prev_state 同一数据源);API 端
  /history 一次顺向遍历即得(已升序载入),/daily 单日回看时补一条
  `trade_date≤d 的近 15 行`查询顺带算出。
- 展示:状态卡「极强 · 第 3 日」;历史明细状态列 `极弱·3`(streak≥2 才显示)。
- 意义:TRANS 按当日档位查全局行,极强→极强 49% 隐含平均持续约 2 日,
  第 4、5 日仍用该行明显失真;streak 把「什么档」补成「什么档、多强、第几天」。

### 3.8 空值/饱和/边界

- 任一输入列缺失 → T=None,前端显示 `-`、曲线断点、不带 E(采集端 r5 失败
  本就整单报错,此路径主要为历史脏数据兜底);
- 表端点钳制保证 T∈[0,100) 按构造永不到 0/100(满分即宣称不可能,不给);
- 档带边界 79.5/89.5 四舍五入后判定(显示整数与带判定一致,杜绝 80 显示标准
  但判踩线的错位)。

## 4. 两阶段与切换(冷启动)

现仅积累 7 个交易日(2026-09-21~09-30),滚动分位远不够,静态表要扛约两个半月。

### 4.1 阶段一(现在 ~ 满 60 交易日):static-v1 查表

锚点出处如 §3.2 三级标注,payload 带锚点版本号 `"anchor": "static-v1"` 留痕。

### 4.2 加固(2026-10-02 已执行,结论:static-v1 维持)

`scripts/calibrate_sentiment_score.py` 实测出的数据源边界比设计预期更窄:

- R5:国证2000 指数日线自算——**唯一深历史精确源**(2024-01~2026-09 全窗口 n=666);
- 东财三大池(涨停/炸板/跌停)**均只开放近 ~30 个交易日**,且 akshare 对更早日期
  返回空表不报错(老日期的 0 是假值,绝不能当样本);池子三项只做尾部体检;
- 一字跌停、红盘率:免费源无历史,保持软锚。

首轮结果:R5 十锚点中位绝对偏差 **1.1pt**、尾部锚点 ≤1pt、最差中段锚点 8.7pt,
无一超 10pt 采纳阈值 → **static-v1 维持原样**(改锚会作废已验收的回放基准,
无实证收益不动)。zt/short/zha 的 |偏差|>10pt 旗标全部出自 n=15 的 9 月单边
样本(低锚点在短窗口天然取不到),属样本噪声非错配。报告与逐日序列落盘
`calib_report.json` / `calib_series.json`,留作 60 交易日滚动切换时的对照基线。
深历史涨停家数若未来要硬校准,需走全市场日线涨停价自算路径(重,暂不做)。

### 4.3 阶段二(history ≥60 交易日):滚动 250 日分位

- 窗口 = min(250, 全部历史),**逐日 as-of**(每根 K 线只用其前窗口,无未来函数);
- 与代码既有计划「积累满 60 交易日后应换滚动分位」同一班车,一次切换两口径
  (TH 阈值的滚动化不在本设计范围,另行立项);
- 切换验收:重叠日上 static-v1 vs 滚动分位逐指标对比,分位中位绝对偏差 >10pt
  的指标列入报告,决定是否回调该锚点/权重;
- 因 T 为读时计算,切换后全部历史自动按新口径重算,曲线整体一致,无混拼。

## 5. 数据流与字段变更

### 5.1 共享模块

新文件 `backend/collector/scripts/sentiment_score.py`,纯 stdlib、无 pandas 依赖:
锚点表、`rank_of(key, x)`、`temperature(ind: dict) -> {t, ranks}`、
`extreme_band(state, t)`、`streak_of(states_asc, i)`、`ANCHOR_VERSION`。

- 采集端:`fetch_sentiment.py` 同级 `import sentiment_score`
  (run.py 以 subprocess 直跑脚本,同级 import 恒成立);
- API 端:`from collector.scripts import sentiment_score`
  (uvicorn 自 backend/ 起,collector 为包、scripts 走命名空间包;实施时验证一条
  `python -c "from collector.scripts import sentiment_score"` 即可)。

### 5.2 存储决策:读时计算,不落库

T 是六个现有列的纯函数,**API 在读时计算**,理由:

1. 零迁移:存量的 7 天(及未来未重算的历史)自动有分;
2. 公式演进(阶段切换/权重微调)对全部历史一致生效,不存在「老数据旧公式」混拼;
3. 杜绝存储值与计算值双源漂移(本仓刚做过口径漂移扫尾,此为大忌)。

代价:/history 在阶段二需多载约 370 行指标列(250+120,毫秒级);/daily 单行无代价。

**DB 与 report JSON 均不加键**;import_legacy 零改动。

### 5.3 采集产物(fetch_sentiment.py)

- `daily.json` 增:
```json
"score": {"t": 85, "band": "标准", "extreme": 85, "streak": 2,
          "ranks": {"r5": 0.926, "red": 0.986, "zt": 0.906, "short": 0.300, "zha": 0.557},
          "anchor": "static-v1"}
```
(ranks 为**原始分位**:第几分位就是几分位,方向只体现在权重里)
- `history.json` 条目增 `"t": 85, "streak": 2`(时点工件;API 不读它算分);
- `reports/YYYY-MM-DD.md` 状态行后增一行(§6.4)。

### 5.4 API(app/api/sentiment.py)

- `/daily` 响应增 `score` 对象(t/band/extreme/streak/ranks/anchor,读时算)+
  `streak`;
- `/history` 每行增 `t`(读时算;阶段二同一遍历内完成 as-of 分位)。

## 7. 既有缺口发现(评审时请一并拍板)

`fetch_sentiment.py:159` 注释称「回暖由 main 里用 history 推导后写回」,但
**main() 无此代码**——回暖仅存在于 TRANS/PREMIUM/配色表中,任何一天都不会被
标为回暖(warm 色永不出现;TRANS 的回暖行只作转移目标可达)。推导规则在
《使用说明书》§14.1 有记载(昨日极弱 且 今日国证2000 涨 ≥1%),属「文档有、
代码无」的实现缺口。

本设计**不实现回暖推导**:落地它会改变状态分布,与 trap(昨极弱+今普通)的
边界纠缠——回落进回暖的普通日还算不算陷阱日,直接影响 trap 的校准数字
(+0.55%/50%),拍脑袋实现等于动校准口径。仅随本次改动把失实注释修正为
「回暖为转移目标词汇,采集端不落盘」。是否补实现(含 trap 语义重校准)单独立项。
