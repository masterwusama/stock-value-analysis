# 设计:小微盘投机池(#/microcap,2026-11-10 上线)

## 定位

季报雷暴出清后小微盘是 A 股季节性投机主战场,而小市值恰是 ST/退市雷的重灾区。
本模块是**投机选股工具**:资金热度、热门题材、涨停生态是主菜单;排雷记分卡是
风控亮灯层——亮灯不拦截(trap 标注制同一哲学),因为亏损/戴帽的票常正是投机标的
(摘帽预期/重组博弈),要的是看清自己拿的是什么刀,不是替用户做决定。

## 架构:读时合成 + 两份轻量文件工件

与掘金台同一套「不做采集面、不落新表」纪律,全部读时合成,公式演进对全池即时生效:

| 数据域 | 来源 | 缺失时 |
|---|---|---|
| 池子/行情/动量/换手 | `quote_daily` + `score_daily` 最新日(库) | 底座,永在 |
| 排雷财务 | fin_income/fin_indicator/fin_balance 最新年报+最新披露期(库) | 财务列「—」 |
| gate 旗(审计/立案/简称ST/年报负权益) | `score_daily.gate_flags`(import_legacy.load_gate_facts) | 不亮灯 |
| 涨停生态(连板/封单/炸板) | `data/sentiment/pool_zt|dt|zha_*.csv`(sentiment job 16:30,15 日窗) | 该列「—」 |
| 主力资金流(今日/5日) | `data/heat/flow_*.json`(heat job 16:45) | 资金列「—」+横幅标注 |
| 概念排行+成分 | `data/heat/boards_*.json` + `members.json` | 面板空+横幅标注 |

**降级链纪律**:heat 工件缺失时热度分只含行情因子(涨停/动量/换手),缺数因子按
可用权重归一——绝不缺列冒 0;分数=None 只在连行情底座都判不动时出现。

## 池子口径

- 微盘 = 总市值 <25 亿;小票 = 25 亿 ≤ 总市值 <60 亿(quote_daily 最新日)
- 排北交所(代码前缀 43/82/83/87/88/92,与 scoring 分板线同一张表);
- 剔上市不满 1 年次新(list_date NULL 保留并标注——与掘金台「宁多看不少看」同取舍);
- 2026-11-10 实测:微盘 650 只/小票 1958 只(原始市值分布 914/2033,差额=次新+停牌缺行情)。

## 投机作战面板(2026-11-11:从「雷达」到「作战台」)

以投机买入为用途,原版缺三样:打法指引、赚钱效应度量、身位结构——全部用既有数据合成:

| 块 | 内容 | 数据源 |
|---|---|---|
| 今日打法 | 按情绪状态的**历史校准**次日竞价溢价(极强 +3.6%/73%、炸板 -1.6%、陷阱日禁隔夜) | sentiment daily.json 的 premium_hint/trap(当日新鲜),否则 `_PREMIUM_LOCAL` 按最新状态查表(与 fetch_sentiment.PREMIUM 同源快照) |
| 池内昨日涨停→今日 | n/均涨/红盘率/晋级数——红盘率 ≥60% 赚钱效应在可打板、≤40% 退潮只低吸 | 上一榜单日 zt 池 CSV × 今日行情 |
| 连板梯队(全市场) | 最高板+各板级家数——空间板身位参照,高位断板=退潮信号 | 今日 zt 池 CSV 连板数分布 |

**个股投机语义**:`zt_yesterday`(晋级↑/断板↓)、`concept_lead`(👑 概念内身位最高:
连板优先、热度次序)、`turn_profit`(扭亏/摘帽候:年报亏损或已 ST 且**最新披露期净利转正**
——ST 即摘帽博弈候选、非 ST 即困境反转候选;业绩面信号,非交易所认定)。
**快捷预设**:今日涨停 / 断板观察 / 扭亏摘帽候(board 参数 zt/broke/turn,纯内存过滤)。

已知仍缺(P2,无免费结构化源):龙虎榜席位、竞价分时、可转债/北交所联动。

## 排雷记分卡(规则=2024 退市新规原文要件,逐条独立、取最高级)

| 级别 | 旗 | 判定 | 出处 |
|---|---|---|---|
| 3 确定 | st_named | 简称含 ST/*ST | security.name(日更) |
| | loss_rev_hit | 最新年报利润/扣非孰低<0 且营收<分板线(主板3亿/双创1亿,复用 `scoring._st_board_line`) | fin_income |
| | neg_equity | 最新年报归母权益为负 | gate_flags |
| 2 高危 | audit_qualify | 最新年报审计非标 | gate_flags |
| | case_filed | 证监会立案(3 年窗 self) | gate_flags |
| | loss_rev_near | 亏损且营收<2 倍线(明年触线主候选) | fin_income |
| | face_value | 20 日均价<1.5 元或现价≤1.2 元(面值退市提前量,它不走 ST 程序) | quote 序列现算 |
| | mcap_thin | 总市值<主板 6 亿/双创 4 亿(退市线 5亿/3亿+20% 提前量) | quote_daily |
| | negeq_soft | 仅最新披露期净资产转负(年报仍正的盲区;年报级定性事实才判死) | fin_balance |
| 1 关注 | debt90 | 资产负债率>90%(非金融,同 scoring 剔金融) | fin_indicator |
| | year_loss | 年报亏损但营收在线上 | fin_income |
| | loss2y | 连续两年扣非(孰低)亏——第二年营收再崩即触线 | fin_income 两年报 |
| | q_turn_loss | 最新披露期累计转亏 vs 上年年报盈利(业绩变脸) | fin_indicator |
| (1) | loss_rev_ex | 双创上市不满 4 个完整会计年度的未盈利豁免窗触线,降级关注 | 与 scoring 同口径 |

「确定 ST」的产品语义:年报已触线的票,披露流程走完必然戴帽——未戴帽的正是
「即将戴帽」,这是本模块对「确定 ST 风险」的回答;已戴帽的反而常有摘帽博弈价值,
所以 🔴 不是禁入而是亮灯,与 🔥 热度同时命中时前端标「雷上加热🔥」。

## 热度分 heat_score(0~100,只是排序器,因子列各自独立展示)

| 因子 | 权重 | 封顶 |
|---|---|---|
| 主力净流入强度(今日/流通市值) | 30 | 3% |
| 5 日主力净流入强度 | 15 | 10% |
| 换手自身分位(近 min(120,可用) 交易日,≥20 行才算) | 15 | 100%分位 |
| 连板数 ×8(今日涨停池口径) | 20 | 2.5 板 |
| 5 日/20 日涨幅 | 各 10 | 15%/30% |
| 所属热门概念(top15 板) | 10 | — |

可用权重 <30 不给分(判不动≠0)。

## heat job(fetch_heat.py,交易日 16:45)

东财免费源三步:①个股主力资金流排行(今日/5日两榜,全市场 5300 只,2 请求);
②概念板块资金流排行(滤掉融资融券/股通/重仓系等通道伪板块后取 top15);③热门概念
成分映射(7 天复用,新进榜当日拉;单板失败保留旧映射)。JSON-only 落盘
`data/heat/`(flow/boards/members/latest),无回灌面(NO_IMPORT);幂等三重跳过
(休市/盘中/当日已生成),当日成分缺口走「只补成分」自愈路径。快照留 20 交易日。

**双端拓扑(2026-11-10 定版)**:云端 VM 的 IP 段被东财 **push2 集群 TCP 层拉黑**
(实测 push2 主站+全部数字镜像 000 秒断;datacenter-web/push2ex/gtimg 不受影响,
所以 valuation/sentiment 云端照常)。资金流与概念排行只能由可达侧采集——本地
抓完即 `_ship()` 推工件上云(scp,VA_HEAT_SHIP_TARGET 可覆盖,失败只打日志不失败
job);云端 16:45 的自跑退化为兜底,**全失败时不写 latest.json**(否则会把 ship
推来的真数据盖成「源未更新」)。本地停机日云端自动降级为行情因子形态,横幅诚实标注。

已知坑:东财成分接口在排行分页拉完后会被限流掐断(2026-11-10 首跑实测,5 板全灭,
加长退避+当日补拉后自愈 4 板)——所以成分步骤永远「尽力而为」,缺的板前端亮「成分?」。

## 僵尸 running 行清扫(2026-11-10)

运维重启会把采集子进程连带杀死(本机 stop.ps1 清进程、云端 systemctl restart 杀
cgroup——首日两侧各留一条永远转圈的 running:本地 agro 晚场被 api 重启杀、云端
valuation 跑到 97% 被手工 restart 杀),run.py 只在自己结尾改状态,死后没人收尸。
scheduler 的 `zombie-sweep`(启动即扫+每小时扫)把 running 超过该 job 挂死护栏
(SCRIPT_TIMEOUT)+10 分钟的行判死留痕——护栏内的 running 不动(可能是并发手动跑)。

## 雷暴日历

披露窗模型:年报+一季报(1/1~4/30)→中报(7/1~8/31)→三季报(10/1~10/31),
其余=出清窗口。窗内进度<95% =「雷暴进行中⚡」,进度≥95% 或出清期=「出清窗口✅」
(带上一个收窗报告期的终值进度+下一窗倒计时)。进度分母=全 A(security 计数),
分子=fin_indicator 该报告期披露家数(2026-09-30 期实测 5547/5553)。

出清窗口(11 月~次年 3 月)正是小微盘历史超额时段——这是模块的选时锚,
与「季报雷暴完后小票受益」的主题互为表里。

## 已知缺口(如实记录,不硬造)

- 无历史简称面板 → 不可回测「旗→戴帽」效度(st_validity.py 同款限制);
- 「扣除后营业收入」无字段,用营业总收入代替(口径偏宽松=宁漏勿错,scoring 同款);
- 内控非标意见/质押爆仓无免费结构化源,不设旗;
- 市值退市线需连续 20 日口径,此处单日快照+20% 提前量近似;
- 审计意见依赖年报 PDF 解析,覆盖率非 100%(NULL 不亮灯);
- 概念成分只覆盖热榜 top15(冷门概念不映射个股,面板仍显示排行);
- 龙虎榜/竞价分时无源,未做(P2 候选)。
