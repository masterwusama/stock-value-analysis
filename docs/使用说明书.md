# 价值分析系统 · 使用说明书

> 覆盖范围：全 A 股（沪深京 ≈ 5553 只）+ 港股通标的（≈ 621 只）+ 美股五大指数成分（≈ 765 只）  
> 形态：单机 Windows 服务，一个进程同时提供 API 与网页；MySQL 8 + Python 3.10 + Node 20

本文分两层。**第 1~5 节给看数据的人**：怎么打开、三个页面怎么用、数据什么时候更新。
**第 6 节之后给接手运维的人**：架构、部署、启停、采集、数据口径、故障处置。

## 1. 怎么打开

### 1.1 本机

```
http://127.0.0.1:8000/
```

### 1.2 手机与其他外网设备

```
https://<设备名>.<tailnet>.ts.net/
```

`<设备名>.<tailnet>.ts.net` 是本机在 Tailscale 里的 MagicDNS 名，从管理台设备列表或 `tailscale status --self` 取。两个必须注意的点：

- **一定要带 `https://`**。这个地址的 80 端口由本机 IIS 应答，输入成 `http://` 会看到一个 IIS 默认页，与本系统无关。建议在手机浏览器里直接收藏完整地址。
- **设备要先加入同一个 Tailscale 网络**（tailnet）。没入网的设备解析不了 `*.ts.net`。

后端只监听 `127.0.0.1:8000`，不对外网卡开放，所以 `ts.net` 这个地址是远程访问的唯一入口。这层转发由 Tailscale Serve 承担，配置可以用一条命令核对：

```powershell
& "C:\Program Files\Tailscale\tailscale.exe" serve status
# 期望输出：https://<设备名>.<tailnet>.ts.net (tailnet only) └─ / proxy http://127.0.0.1:8000
```

### 1.3 手机端界面

视口宽度 ≤ 600px 时自动切换为移动版，不需要任何设置：

- 列表页从 23 列宽表改为**一屏一家的卡片**，指标、买卖参考价、定增/回购分块展示（卡片里没有悬浮，所以口径说明直接印在文字里）

转屏或缩放窗口后图表会自适应重绘。桌面版布局不受影响。

## 2. 列表页 `/#/`

全市场近 7000 只，逐页翻不现实，所以操作路径设计成**先缩范围、再排序**。

### 2.1 缩范围

| 控件 | 说明 |
|---|---|
| 市场 tab | 全部 / A股 / 港股 / 美股（切换时清空板块） |
| 板块 tab | 沪主(60) / 深主(00) / 创业(30) / 科创(68) / 北交(92,83,87,43)，按代码前缀判定 |
| 行业下拉 | 选项跟着市场走：A 股国标行业、港股恒生行业、美股东财中文行业 |
| 排除行业 | 反向筛选，多选：点开后是带搜索框的勾选清单，勾中的行业整体从结果里去掉（选几个就排掉几个）。每个行业后面的只数是**该市场该行业的全量口径**，不随其它筛选变化，所以看着跟当页对不上账是正常的。与「行业」下拉同时生效时按 AND 处理——选了某行业又把它排掉，结果就是空集；已被排除的行业在下拉里会标成「（已排除）」。没有行业标注的标的（实测 1 只，美股 LFCR）不属于任何行业，不受排除影响，始终保留。切市场会清空已排除项，因为三个市场是三套行业字典 |
| 关键字 | 代码或名称模糊匹配 |
| 剔除 ST | 名称含 `ST`/`*ST` 的标的是低 PB 假便宜重灾区，默认建议勾上。**只有 A 股判**——港股、美股没有风险警示制度，而美股简称里带 `ST` 的（STAR、Stifel…）实测 88 家不算 |
| 排除门槛 | 勾上即去掉触发**硬门槛**（`gate`）的标的，不勾为不限。门槛是**二元否决**，四项定性事实任一成立即触发：最近一份披露的年报审计意见非标、A 股简称含 `ST`/`*ST`、Wind 事件里有违规/立案/处罚、最新年报归母股东权益为负。它**不进任何分数也不改分数**——四派分只回答「相对本派锚位便不便宜」，而这些事实一旦成立分数再高也不该进买入区；把否决稀释成「扣几分」既拦不住东西也解释不了。实测 6939 只里 344 只触发（非标 127 / 风险警示 203 / 负权益 98 / 违规立案 1，有重叠），其中 24 只四派最高分 ≥70，所以高分前排出现 `⚑` 不是列坏了。一个信号都判不了的（实测 26 只，多为未抓财务）`gate` 为 `NULL`，**勾与不勾都不出现**——`NULL` 不等于「干净」，与市值/净现金那几列「算不出就不进区间」同一语义。四项口径与 SQL 见 §10.3 |
| 市值区间 | 单位**亿**，与列头 `市值(亿)` 同口径 |
| 净现金/市值区间 | 单位 **%**，与列头 `净现金/市值` 同口径（填 20 即 20%，接口收的是小数比率 0.2）。`≥` 那侧筛现金充裕的，`≤` 那侧专门用来捞净负债的。**负数是净负债的真实值，不是非法输入**，所以这两个框不拦负数：`≥0` 表示加权类现金已够覆盖全部负债，`≥100%` 才是格雷厄姆意义上的 net-net——全市场只有个位数且全在美股，A 股 tab 下填 100 必为空。深负集中在预收/合同负债庞大的地产、建筑与 AMC——这列减的是**负债合计**，预收与合同负债都算在里面，所以越是先收款后交房的业态越深，`≤0` 捞到的并不是「便宜的反面」。算不出这列的公司（列面显示 `-`，126 只）不进区间，设任一门槛即被排除。这一列与 §2.3 评分项里的「市值 / 净现金 ≤ 1×」**不是同一个净现金**，两处的家数因此不同；「加权类现金」具体含哪些项、各按多少折算见 §2.3。 |
| PB 十年分位区间 | 单位 **%**（0~100，与列头 `PB十年分位` 同口径，填 5 就是十年最便宜的那一档）。**这一列的数不是我们算的**：分位窗口、样本起点、亏损期是否计入全由外源 Wind 定，我们只做取回与置空，所以它**不参与四派评分与买卖点**，纯粹用来看和筛。`≤20` 是「当前 PB 在自己十年里处于下沿」，`≥80` 则是十年高位。**按口径不刷的标的一律显示 `-`**，三类成因（设任一门槛即被排除）：一是**不在刷池**——美股整市场不刷，A 股/港股里管理分 < 30 或造假分 > 50 的不刷，这类标的已由管理分/造假分两列排除在优质区外，不再占 Wind 额度；二是**还没铺到**（刷池按游标分轮铺，约 1.9 天一轮，具体截止日悬停格子可见）；三是**被判为不可信**（PB 为负或算不出、外源观测日距全表最新一日过久） |
| 财报期龄 | 单位**月**：这批评分所依据的那一期年报的**期末**（`score_daily.report_date`）距本行评分快照日的月数，留空为不限。填 13 就是只要「基准年报还是上一年度」的公司——上一年 12-31 的年报最迟 12 个月龄，超出去就是再上一年度。它是**筛选不是罚分**：财报旧不等于公司差，只是我们给的分旧，所以这一列不改任何分数，只决定谁进结果。列面在名称后标 `期龄N月`（>13 月才标，正常路径不该占屏）。实测 6898 只落在 7~9 月（当前基准期 2025-12-31），只有 15 只超过 13 月，所以这个门槛平时是个几乎不拦人的保险丝；**负值**只出现在 7 家财年不在 12-31 收尾的美股（Copart/Cisco/Intuit 那类，采集层把财年归一化到 12-31 后基准期跑到快照日之后），见 §12 |
| 分数门槛 | 造假 ≤ / 管理 ≥，留空为不限 |
| 买点 | 四派多选 + 折扣 %：现价 ≤ 买参考价 × 折扣即命中 |
| 卖点 | 四派多选：现价 ≥ 公允卖价即命中（公允恒高于保守卖价，等价于两档都越过），缺参考价的公司自动排除 |
| 事件增强分 | 见 §2.4 |

### 2.2 排序

点表头即可，支持 `PE / PB / 市值 / 四派分 / 造假 / 管理 / 周期 / 陷阱 / 成长 / 清算 / 净现金 / PB十年分位`。陷阱与成长两列方向相反：前者降序＝最可疑的在前，后者降序＝过去五年长得最快的在前，口径见 §2.3。

四派参考列的读法：

- **列头按买入性价比排序**：比的不是买价的数字大小，而是现价相对该派买入参考价的**折价深度**（`1 − 现价 / 买价`）。5 元的票并不比 50 元的便宜，折成比例后跨标的才可比。
- 降序（点一次表头的默认方向）第一屏＝相对建议买价打得最深；再点切升序，最前变成现价已远高于买价的那批。
- 当前用于排序的那一列，每格会多出一个 `折NN%` / `溢NN%` 小标签（悬停看精确值），另外三列不显示，所以不额外占表宽。
- 格内三行是 买入价 / 保守卖出价 / 公允卖出价，三档都锚定该流派自己的估值阈值（格攻＝每股净流动资产、格防＝15×每股收益、施洛斯＝每股净资产、巴菲特＝合理市盈率×每股收益），买入价是锚位再打折后的价格；后两档的小字可各自点击，按卖价绝对值排序。
- 现价或买价缺失、买价低到不可成交的行不参与排名（沉底），不会把整屏顶成 `-`。
- **清算列同理**：点表头排的也不是每股清算价值的大小，而是现价相对它的**折价深度**（`1 − 现价 / 清算价值`），排序时格内同样补出 `折NN%` / `溢NN%` 小标签（悬停看精确值）。降序第一屏＝现价已跌破清算价值的那批（格内显示绿色），再点切升序则先看现价高出清算价值最多的；没有清算价值估算（财报科目缺失）的行沉底。每股清算价值 860 的标的现价 6300 时并不比 3 元的票「更便宜」，折成比例才可比。该列与「格进取 买/保/公」的买价同锚（买价＝清算价值×2/3），两列的排名顺序一致，只是一个看清算价值、一个看打折后的买价。

分页每页 50/100/200（默认 50），支持跳页。

### 2.3 列含义

`代码/名称（第二行：行业与 ⚑/中报/期龄 标注）｜现价｜涨跌｜PE(TTM)｜PB｜市值(亿)｜格进取｜格防御｜施洛斯｜巴菲特｜造假｜管理｜周期｜陷阱｜成长｜推荐｜清算｜净现金/市值｜PB十年分位｜定增｜回购｜格进取 买/保/公｜格防御 买/保/公｜施洛斯 买/保/公｜巴菲特 买/保/公`

表头分两级：组标签行（**标的 · 行情 · 四派评分 · 量化评分 · 资产·分位 · 股本事件 · 买卖参考价** 七组，各带浅色底与组间分隔线）+ 列名行，横向滚动时组边界仍可见；数据行斑马纹。行业不再单列（并入名称格第二行），2026-09 起。

后四列是竖排三行。数值颜色：**绿色 = 现价已进入该派的买入区**，**红色 = 现价已达到卖出区**。

几点口径值得记住：

- **市值是本币计价，不折汇率**（A 股人民币、港股港元、美股美元，非 A 股带 `HKD`/`USD` 角标）。所以「全部」tab 下跨市场比市值没有意义，要比体量请切到对应市场分开筛；跨市场比较请用 `PE`/`PB`/评分这类比率列。**列面不折，但评分引擎里折了一处**：格防御那个规模硬门槛（总资产 `1e10`/`5e9`/`3e9` 三档）当年是按 A 股人民币定的，拿港元/美元原值去比等于把体量相当的港美股系统性降 1~2 档，最高档 `1e10` 折过去是 13.99 亿美元 / 108.7 亿港元——ACADIA 医药总资产 15.6 亿美元按原口径拿 0 分、折回人民币应得满档。现在这一项先把本币金额乘上固定汇率（`A` 1.0 / `HK` 0.92 / `US` 7.15，年均量级）再比档，**其余科目仍全是本币原值**。实测折算改动 251 只的格防御分（港股 35 / 美股 216，多数 +11.76 一档），A 股一分不动。取固定年均汇率而不取实时汇率：门槛本就是三档粗刻度，差 3% 的汇率波动不影响分档，而要精确可比就得接汇率源，那是另一个数据面，不该由评分引擎自己算。
- **名称后的 `⚑` 与 `期龄N月` 都只是标注**，不参与排序、不参与着色，也不改任何分数。前者＝触发硬门槛（悬停看命中了哪几项，排除入口在筛选栏「排除门槛」，口径见 §2.1 与 §10.3）；后者＝评分基准年报期距今超过 13 个月，说明新一期年报还没披露（或还没回灌），四派分与买卖参考价都建在再上一年的财报上。
- **表头日期是列表快照日**，取行情与评分两张表各自最新日的交集，两者新鲜度不一致时以较早者为准——不会出现「用今天的价配昨天的分」。而每个标的名后的 `期龄N月` 是相对**本行自己的评分快照日**算的（逐证券各取最近收盘，美股会比顶部那个全局快照日旧一天），悬停可见两个日期同时报出。
- **格进取一列对绝大多数公司落在 0~50**，不是列坏了：该派 100 分里有 50 分是「市值 / 净流动资产 ≤ 0.67×」与「市值 / 净现金 ≤ 1×」两项价格折扣，而 6939 家里分别只有 110 家、140 家能在这两项上拿到分——这正是格雷厄姆 net-net 的苛刻之处。剩下 50 分（流动比率、盈利、负债率、分红）用来给未达 net-net 的公司排财务健康度。想直接捞 net-net 候选，请用「买点」筛选勾格进取，而不是按该列分数排序。
- 上面那句里的「净现金」和列表列 `净现金/市值` **不是同一个数**：评分项那两项用的是 `货币资金 − 有息负债`（只看有息负债，不入库，能拿到分的 140 家）；列表列用的是 `加权类现金 − 负债合计`（全部负债都算进去，入库，所以 ≥100% 只有 4 家）。两个数并存且都对，各自服务各自的口径，别拿 §2.1 那个筛选项的只数去核对这里。
- **`净现金/市值` 的加权类现金**＝`可用货币资金 ×1.0 ＋ 交易性金融资产 ×0.7 ＋ 应收票据 ×0.4 ＋ 其他流动资产中的非存款部分 ×0.3 ＋ 定期存款 ×1.0`，减去**负债合计**后除以快照总市值。前四项取自资产负债表科目，后两项取自财报附注（年报/半年报里的「其他流动资产」明细与「受限资产」明细）——`其他流动资产` 这个科目里可能是三年期定期存款，也可能是留抵税额，科目层分不出来而两者差 3 倍折算系数，附注负责把它们分开。附注里的数只在与该科目合计对得上时才采信，对不上（或该公司没披露这两张表）就整块不采信，此时该家退回按科目整体 ×0.3 计算的口径，数值不受影响（本轮入库的 13972 行带科目锚的附注，与同报告期资产负债表逐行相等）。因此这一列既可能因为「账上其实是定期存款」而比科目粗算高一档，也可能因为「货币资金里有一块是保证金」而低一档。逐家的代入式（含拆出来的定期存款与受限金额、各自的报告期）悬停详情页 ① 快照里的 `净现金/市值` 即可看到。
- **这一列换口径换掉了多少**：A 股 5553 只里 4933 只拿到了附注（其中 770 只披露了定期存款、3328 只有受限货币资金），比值随之变动的 3148 只里 2646 只是**变小**（货币资金里扣掉保证金那块）、502 只是**变大**（存款从 ×0.3 抬到 ×1.0）。多数只挪一两个点，两端很陡：广信股份 5.1%→29.6%（37.02 亿其他流动资产里 36.91 亿是定期存款）、上海钢联 -70.1%→-432.5%（244.03 亿货币资金中 240.91 亿是票据/保理/信用证保证金与司法冻结）。全市场 ≥100% 的家数不变（4 只，全是美股 Biotech），最深与最浅两个端点也不变——它们分别是港股与美股，本轮不重抓。
- **`PB十年分位` 是外源口径，不是我们算的**：值为「近十年内 PB 低于当前值的交易日占比」，窗口长度、样本起点、亏损期是否计入全部由 Wind 那边定，我们不复算也不改。落库前只过三道置空：PB 本身为负或算不出、外源观测日距全表最新一日过久（序列停更）、分位数落在 0~100 之外。**刷池口径**：美股整市场不刷，A 股/港股里管理分 < 30 或造假分 > 50 的不刷，剩下 5340 家按游标滚动铺（一轮 108 次调用、约 1.9 天）；被剔掉的标的保留最后一次取值，到超过陈旧阈值才变回 `-`。悬停该格可见该家的样本交易日数与外源观测日；新上市的公司样本可能只有几百天，分位照样给，样本数就是它的可信度提示。PE / PS 两个分位同理，只是不在列表页占列——PE 分位对亏损公司无意义（置空后整片 `-`），详情页 ① 快照的 `估值分位(10年)` 一格三项齐全。**这一列与四派评分、买卖点参考价完全无关**，它只回答「现在这个 PB 在它自己十年里算什么位置」，不参与任何打分。
- **三档价的算法**：买点 = 该派估值锚打折（格进取 0.67×、施洛斯 0.75× 资产锚；格防御、巴菲特为保守卖价 × 2/3）；保守卖 = 该派核心锚（格进取 每股净流动资产、格防御 15×EPS、施洛斯 每股净资产、巴菲特 合理PE×EPS，合理PE 由净利 5 年 CAGR 定并夹在 8~25 倍）；公允卖 = 保守卖上浮 1.3~1.5 倍。
- **`-` 有两类含义**：账面派（格进取 / 施洛斯）只有两档卖价是 `-`、买点还在，是**该派对这只股票没有卖出意见**——现价已到资产锚 2 倍之外，清算/账面口径从来不是它的估值方法；收益派（格防御 / 巴菲特）三档一起 `-`，才是这只股票的每股盈利锚不可用（亏损、口径异常或盈利不可重复）。买点与「清算」列不受射程影响。
- **收益派按经常性盈利定锚**：A 股用扣非净利润的滚动 12 个月值，不足报告净利润一半时按比例压缩、扣非转负则取消该派参考价；港股、美股不披露扣非，改用「隐含 PE ≥ 3 倍」下限过滤。靠处置资产、政府补助或债务重组收益做正报表的公司因此不会出现在买入区榜首。
- **连续分红年数带断档锚定（2026-09-18 修正）**：格进取 5 分、格防御 15 分、巴菲特护城河 3 分的「连续分红」项，只数真派过**现金**的年份（送股年不算），且 A 股锚定最新年报年——最后现金派现年落在锚年−2 或更早就按断档清零，历史连发不再计入「连续」（此前从最后一次派现年倒推，对最近的削减分红天然失明：实测 634 家 A 股停派 ≥2 年仍拿满该项，万科Ａ停在 2022、倒推 32 年拿 15/15）。同批修正还有三处口径：格防御「近 5 年净利累计增长」改用真 5 年基期（不晚于最新年报−5，与净利 CAGR 同一选基纪律；旧实现 5 行首尾比实为 4 年）、格防御「盈利稳定」项有效行不足 5 年判不动而非当非正年（次新公司不再被压分）、管理分「资本回报」改近 5 年 ROE 中位（单年披露值在薄/负权益处会炸到 ±几千个百分点）。
- **`陷阱` 列是价值陷阱分 T（0~100，与 `造假` 同为「越低越好」）**：把七类各自独立的坏消息证据，按 A 股回测出的危险比加权相加——扣非 < 0.5×报告净利（权重 1.63）、商誉/总资产 ≥ 10%（0.70）、ROE 最新 − 近 5 年中位 ≤ −4pp（0.69）、造假分 > 50（0.51）、近 5 年定增摊薄 > 0（0.49）、毛利率 ≤ −3pp 减速（0.48）、净现比 5 年中位 ≤ 0.80（0.42）。它量的是「坏消息堆了几样」，与四派分（便不便宜、好不好）不在同一个轴上。
- **三处与四派分刻意不同**：① 阈值是**固定绝对值**，不按当日横截面分位取——按分位取的话一家公司的分会被当天其他公司的涨跌改掉，按日入库后就不可复现；② 分母**固定为全部 7 项权重之和 4.92**，缺项记 0 而不按可用项归一——那套归一会让「只查得动 1 项、恰好那 1 项亮灯」的公司拿满 100 分，而这一列最怕的正是「没查到」被读成「没毛病」；③ 口径**只覆盖 A 股**（定增/回购源、扣非科目、减值科目只在这一侧成立），港股、美股整列显示 `-`，那是不适用，不是「查过了没毛病」。
- **因此格子右上角的 `N/7` 与分数同等重要**：`N` 是七项里查得动几项。缺项只压低分数、不会加分，所以**分低不等于没风险**，可能是没查动。压低幅度有界：七项里只有商誉一项稀疏（最新年报未单列那行的 2,854 家，占 14% 分母），其余六项普遍查得动。着色按**档位**而不是分的绝对值（列表侧可见的三档颜色：档 1 绿、档 2 与档 3 琥珀、档 4 与档 5 红），悬停给出该家的档位、未归一的证据合计 C 与可判项数，各档实测发生率在详情页 ⑪。

- **七项分成两块，这个分法决定了这一列能说什么**：吃市值的前三项共 **65 分**（便宜度），不吃市值的后四项共 **35 分**（质量与回报）。回测里**只有那 35 分这一块能拿真实未来结局验收**——按它的五分位，其后净利转亏率 25.5% → 15.0% → 10.6% → 7.3% → 5.8%（最差档比最好档高 19.7pp）、减值≥5% 净资产率 36.7% → 3.8%，三个信号年各自同向。便宜那 65 分不是不重要，是本库量不了「当年买便宜的赚不赚钱」：可用的市值序列只覆盖近期，回测只能用今天的市值去乘当年的年报，而今天的市值里已经装着信号日之后的一切消息。所以详情页那张档位对照表**明写它是前视、只作形状参照**，不是预测。

- **年化口径有两条硬规矩**：三条增速都先夹在 **±50%/年**——五年前净利一百万、今年十亿那种基数游戏最多值到满分锚点，不会因为基期选得小再多拿分；**基期非正时该项判不动**（增速本身没有意义），基期为正而当期转负则记 −50%，那是真实的坏消息而不是算不出。基期取「不晚于最新年报 − 5 年」的最近一期，上市晚、历史不足 5 年的按实际跨度年化，用的哪一期与跨几年写在详情页那行「评分基准」里。
- **三处与四派分刻意不同**：① 锚点是**固定绝对值**，不按当日横截面分位取（同上面陷阱那条，按分位取会让一家公司的分被别的公司涨跌改掉）；② 分母**固定为 7 项权重之和 100**，缺项记 0 而不按可用项归一——按可用项归一等于奖励不披露，披露越少、剩下几项摊到的权重越大；③ **各市场都有分**，七项只读年报的四个科目，不像陷阱分那样依赖只在 A 股成立的定增史与扣非口径。但披露粒度会改上限：美股的指标表没有「每股净资产」这一列，该项在美股恒判不动（实测 765 家无一家七项齐全），分母照旧不缩，所以美股这一列最高只到 85.3。
- **因此格子右上角的 `N/7` 与分数同等重要**：`N` 是七项里查得动几项，缺项只压低分数、不会加分，所以**分低不等于没长**（`-` 才是整分判不动：公开年报不足 3 期，或期次够但各项基期都取不到正的值）。着色按**档位**而不是分的绝对值（档 5 绿、档 3 与档 4 琥珀、档 1 与档 2 红）；档位切点是回测当时的五分位 **16.0 / 28.3 / 47.7 / 69.0**，当期分布整体漂移时占比会变而切点不动——这张表回答的是「这个分数在历史上接着长出多少」，不是「你排第几」。各档实测的未来 2 年与 3 年年化增速、净利转负率在详情页 ⑩。
- **实测分布**（评分日 2026-09-16）：A 股 5,553 家，中位 32.5、p75 54.3、p95 79.2、最高 97.4（东鹏饮料），0 分 130 家、满 100 的一家没有；按档占比 档1 23.4% / 档2 20.4% / 档3 24.6% / 档4 19.3% / 档5 12.4%；七项全查得动 4,112 家，只查得动 4 项及以下的 118 家，平均 6.58/7。港股 621 家（32 家年报不足 3 期而整分判不动）中位 42.7、平均 6.17/7，最高 96.5（02899 紫金矿业）。美股 765 家（4 家判不动）中位 36.3、平均 5.01/7。
- **分值的来历与一处读法注意**（`scripts/g_validity.py`）：A 股 21,926 条「公司 × 信号年」观测，每条只取信号日当天**已披露**的年报，结局看锚点之后公开的真实净利增速（分母做平滑，不让小基数主导）。出厂三条线全过：甲 五分位对 2 年与 3 年两头的平滑增速都单调、ρ ≥ 0.05、净利转负率随档位不升且至少降 10pp（实测 45.2% → 8.7%）；乙 与线上八个分的最大重叠度 |ρ| = 0.723（巴菲特），阈值 0.85；丙 覆盖率与打满/打零分布合格。权重是先验声明后按判别效度复核的，不是对那段历史拟合出来的。读档位表要注意：观测锚点集中在 2021~2023，其后两年正逢 A 股净利普遍下修，所以各档的未来增速中位数普遍为负——**读档与档之间的落差，别读绝对值**。
- **`推荐` 列是综合推荐分 R（0~100，越高越好）＝门槛外的 0.6×V + 0.4×G**：它不引入新分项，是三条已各自过出厂检验的轴收进一个「值得看」的入口。**三道发分门槛**——造假 ≤ 40 · 陷阱 ≤ 20 · **中报恶化 dip ≤ −70%**（判不动的门槛输入按「无证据」放行，港美股陷阱整列不适用、扣非缺失侧 dip 判不动，靠这条拿得到 R）；被拦下的公司整格 `-`，悬停可见原因（`fraud`/`trap`/`interim` 及组合＝不过资格线，`nodata`＝门槛过了但 V/G 至少一条判不动）——**`-` 不是 0 分**。档位切点 24 / 36 / 46 / 56（回测面板含价格五分位，与 V/G 同为固定绝对值）。它的行情节奏跟 V：便宜那部分吃本批行情，所以 A 股这一列每交易日都会跟着 V 挪零点几分。
- **中报恶化 dip（名字后的「中报−xx%」徽标与 R 的第三道门槛）**：评分轴只读年报（12-31），「年报正常、之后中报变脸」的标的会拿着与现况脱节的高分（600866 星湖科技 2026-09 实例：FY2025 年报净利 9.8 亿/ROE 12%，2026H1 扣非同比 −93%，R 曾停在 82.3——财报期龄保险丝防年报缺披露，防不了中报变脸）。dip＝最新一期季报/半年报的**扣非同比**（缺则净利、同比分母 |基期|），≤ −30% 挂徽标（只标注不折分），≤ −70% 拦下 R。门槛阈值出自 `scripts/dip_validity.py`（A 股 78,277 条 interim 观测、可用日=法定期限）：−70% 档其后转亏 lift **7.83×**（旗组 34.3% vs 其余 4.4%）、年报复证（FY 扣非同比 ≤−30%）lift 3.27×（74.0% vs 22.6%）、旗占观测 15.8%。两点如实披露：① 采用线的旗占比上限从预登记的 8% 修到 25%——既有 fraud/trap 门槛本就剔掉约 36% 的 A 股，8% 是拿标注线的直觉套门槛线，修线理由记在脚本文件头；② 旗组前瞻 1 年超额反而 +3.4pp（超跌反弹的风格效应）——R 收益侧本就判 FAIL 非卖点，门槛的存在理由是基本面排雷，此条披露不判决。实测上线截面：1,036 家 dip ≤ −70%，其中 507 家纯因 interim 失去 R。
- **R 的出厂检验**（`scripts/r_validity.py`，A 股面板 2021~2023、事件时信息集、预登记三线）：甲 判别——门槛内按**无价格验收版**（0.6×V 质量块 + 0.4×G）五分位，其后转亏率 16.0%→8.2%→4.9%→2.9%→2.4% 单调（Q1−Q5 +13.6pp）、减值≥5% 净资产率 26.8%→3.3% 单调（+23.5pp）、信号年逐年 3/3 同向；乙 合成价值——两条腿首末差均 ≥ max(V 质量块, G 单轴) − 2pp（转亏腿 13.6pp 还强于两个成分，合成没有稀释）；丙 门槛有效——被剔人群转亏率 19.3% vs 过门 5.8%（z=+24.4）、减值 19.4% vs 9.2%。权重 0.6/0.4 是先验声明不拟合。
- **R 的收益侧检验——结论是负向，警戒由此升格**（`scripts/rr_validity.py`，同一面板配 `data/prices/` 的 hfq 日线、信号日点对点 1/2/3 年收益减同队列中位）：门槛内 R_q 五分位的其后 2 年超额收益 Q5−Q1 = **−10.1pp**（高分组跑输），逐年 0/3 同向；成分单轴同样反向（V 质量块 −6.7pp、G −11.1pp）。这不是 R 独有的缺陷——2021~2023 信号窗的前瞻期正逢 A 股质量/成长风格杀跌（白马下修、微盘占优），无价格的质量+成长证据在那段市场里系统性负向；幸存者偏差还让低分组的真实收益更差（量到的是保守方向）。**读法定格：R 是排雷与选质的入口，不是买点**——它挑「其后不容易变坏」的公司（基本面判别力成立），不挑「其后涨得多」的；按 R 高分直接买入在这段风格里反而跑输。含今天市值的 R_full 在该表列 −25.9pp，但那是前视污染（今天的市值装着信号日后的涨跌），只作形状对照。
- **`定增` 列**显示最近一次已发行定增的**发行价（元/股）／发行年月／发行数量**，一格一行；完整日期、募集资金、发行方式、锁定期、发行前后股本、认购对象见详情页。口径要点：**只认非公开发行**（公开增发与配股不算，所以某家最近一次增发若是公开增发，这一列会显示它更早的一次定增）；发行日缺失取上市日；历史价格未复权。库里现有 **5,468 笔 / 2,678 家**（2010 年以来）。
- **`回购` 列**最多两行，`新`＝最新公告记录、`完`＝最近已完成回购；**同一笔（最新那笔就是已完成那笔）合并成一行**，按 `完` 显示完成日，避免把公告日误当完成日。价、量、金额**各自独立**优先取累计成交值、缺项回退方案值并标出口径：价格标 `成交均价` 或 `方案上限`（后者带 `≤`），数量、金额标 `累计成交` 或 `计划` 区间（单边时显示 `≥`/`≤`）。价格后的 `注销`/`非注销`/`待核` 是按公告里股份用途那句话分的三态——**注销只是公告写的用途，不代表已经办完注销；回购完成也不等于注销完成**，所以三态一律中性着色，判据句与方案原文在详情页可直接核。库里现有 **5,410 笔 / 2,872 家**，其中已完成 4,847 笔；按每家最近一笔分，注销 470 家 / 非注销 1,720 家 / 待核 682 家。
- **这两列只覆盖 A 股**：港股、美股整列显示 `-`（源侧没有对应的两张表）。未收录或本轮未覆盖的也显示 `-`。来源东方财富，**不参与评分、不参与买卖点参考价、不进排序与筛选**，纯展示。

⑨ ⑩ ⑪ 三节恒在。**⑨ 价值综合分与 ⑩ 成长综合分三个市场都有分**（七项只读年报科目，价值分还多吃一笔市值），只是美股的指标表里没有「每股净资产」与逐笔派现，那几项在美股恒判不动、分母不缩，见 §2.3。**⑪ 价值陷阱分**在港股、美股那一份会写明**不适用**（口径只覆盖 A 股），而不是整节消失——「不适用」与「查过了没问题」是两件事。后两节的**编号是动态的**：有 Wind 事件时股本事件是 ⑬，没有时它顶到 ⑫。股本事件整节只在库里有该标的的定增或回购记录时出现，所以 A 股里没抓到记录的也没有——不是页面缺了一块。

几点读法：

- 每个模块的分项都带「当前值 / 标准 / 得分」三列，可以直接看出分数是怎么凑出来的；⑥⑦ 的评分依据是量化红旗信号，**不构成对造假的认定**，需结合审计意见、监管问询等定性信息判断。
- **⑥ 那个分的判别效度实测过**（`scripts/fraud_validity.py`：A 股 5,553 家、T ∈ 2019~2024、33,318 个「公司×年」观测。红旗分只取**信号日当天已披露**的财报，信号日即该期年报的实际披露日（距年末中位 114 天，4.4% 取不到披露日时按法定期限兜底），结局看信号日之后 18 个月内公开的第一份年报）：对「次年净利转负」有判别力——低档 8.50% → 极高档 16.59%（lift 1.68×，z=+5.79，6/6 个 T 年方向一致且四档单调）；对「减值 ≥ 净资产 3%」也有——19.67% → 31.89%（lift 1.45×，z=+6.08，同样 6/6 一致且单调）。把减值线提到 5% 只剩 lift 1.19×、z=+1.85，**过不了 |z|≥1.96**，所以 3% 才是这个分真正吃得准的口径。**对「审计意见非标」没有**——四档发生率 1.79/2.34/1.81/1.51% 几成平线，极高档反而最低（r=+0.0092）。最后那一条恰好是关键：审计非标与红旗分几乎正交，所以**不能拿造假分当审计干净的代理**，§2.1 的硬门槛必须另取审计意见这条事实。前视也单独验过：把信息集从「按披露日截断」换回旧的「只看报告期」、结局窗从事件时换回死盯 T+1 财年，两版四档发生率几乎重合（同一信号日下 32,745 条观测同档率 100%、分差 0.0；结局两边都判得动的 32,197 条里结论相反 0 条），所以上面这些判别力不是提前看到年报算出来的。注意两点局限：极高档只 746 个观测，lift 的置信度有限；z 值把「家×年」当独立观测，同一家在多个 T 上各计一次，因而偏乐观（故每个结论都另列一行不依赖独立性假设的方向一致性）。
- **⑪ 价值陷阱分那张五档发生率表是回测出来的**（`scripts/trap_validity.py`）：人群是 A 股 5,553 家 × T ∈ 2019~2024 的 **32,183 个「公司×年」观测**，每个观测的分只取**信号日当天已披露**的财报，结局看信号日之后 18 个月内公开的第一份年报里有没有那五件事（净利转负、减值 ≥ 净资产 5%、减值 ≥ 净资产 3%、分红中断、每股净资产降 ≥ 10%）。这次把**出厂常数**（固定权重、固定阈值、固定切点）原样重跑了一遍复验：五档之间 **20 组相邻比较只有 1 处倒挂**——「每股净资产降 ≥ 10%」在 档4→档5 从 24.18% 回落到 22.94%（z=−1.6，噪声级），其余四类结局逐档单调不降；表上印的比率与本期实测**最大偏差 1.46pp、中位 0.39pp**，所以那张表可以直接当量级用。两端差得很远：转亏 3.66% → 28.70%，分红中断 5.92% → 24.11%（出厂印值）。两点局限：z 值把「家×年」当独立观测，同一家在多个 T 上各计一次因而偏乐观；表里的比率属于**回测人群**（一家公司在 2019~2024 里可以贡献多个观测），与 §2.3 那组「按档占比」的当前 A 股截面不是同一人群，两者数字不同属正常。
- **⑨ ⑩ ⑪ 各带一张五档表，别看混**：⑨ 印的是各档其后的净利转亏率与减值 ≥5% 净资产率（价值分，越高越好），⑩ 印的是各档其后 2 年与 3 年的净利年化增速中位数、净利转负率（成长分，越高越好），⑪ 印的是五类坏消息各自的发生率（陷阱分，**越低越好**）。三张表的切点都是**回测当时**的五分位，当期分布整体漂移时各档占比会变而切点不动，所以它们回答的是「这个分数历史上接着长出什么」，不是「你今天排第几」；⑨ 与 ⑩ 那两组的数字来历见 §2.3。**⑨ 那张表额外标了前视**：它的五分位里含吃市值的那 65 分，而回测只能拿今天的市值去乘当年的年报，所以那一列只说明形状，不能读成预测（不含价格的 35 分那一块才是验收依据）。
- ③④⑤ 卡片抬头出现「⚠ N 项数据缺失未计分，本卡按有效满分 X/100 折算」时，说明有 100−X 分权重的指标取不到（银行券商普遍缺流动比率与营运资本，港美股常缺股息率与净现比）。**分项基础分**只在取得到的 X 分里折算，上限也是 X：显示 30 分意为「可评的 30 分全部拿满」，不是「30% 质量」。这个折算只往上、不往下——取不到的项不会让本就已经是负数的分变得更负，缺项对分数的影响是中性而不是双向放大。覆盖度差得多的两家公司，分数不宜直接相比。④ 施洛斯卡在基础分封顶之后还要减 9 项风险扣分（净资产/有息负债/营收/毛利率的 5 年变动、扣非亏损年数、商誉与无形占比、应收/营收、存货/总资产、经营现金流对利息的覆盖，合计最深 −37 分），所以它的总分可以低于 X、也可以是负数；扣得越重分越低是这张卡的设计意图，别把负号当数据缺失。③ 的防御型卡也可为负（最低 −30），但那是可负分项本身，不是扣分。
- ② 里的「5年累计净现比」只累加**同年净利润与经营现金流都披露了**的年份，② 卡片与 ⑤ 的分项都会标出实际配对年数（如「2/5 年配对」）。只有单边数字的年份两边都不进分子分母，所以这个比值始终对应一段真实经营期；一年都配不上时该项按缺失处理——不计分也不误扣，⑤ 分项显示 `-`。配对年数少于 5 年时，这个数反映的是这几年而非五年全貌。
- ⑤ 巴菲特卡有两行 ROE，看的是两件事：护城河项（4 分）看**持续**，取近 5 年中 ROE ≥ 10% 的达标年数，5 年全达标才满分；盈利质量项（25 分）看**水平**，取近 5 年 ROE 中位数，≥ 15% 满分、10% 起给分。中位数只落在中间那一年，单一年度因权益变薄而畸高畸低都不会改变结论。
- ⑤ 护城河的「无形资产 / 总资产」**只按无形资产计量，不含商誉**（该行下方的脚注仍会列出商誉金额与其占比，只是不参与打分）。依据是上面同一套 A 股「公司×年」实测：商誉/总资产 ≥10% 的公司，其后出现大额减值（≥ 净资产 5%）的比例是其余公司的 **2.36 倍**（z=20.7），且占比越高分得越开（四档单调）；无形资产 ≥10% 的那组只有 **1.04 倍**，与没过线的没有区别。也就是说商誉账面值高只有风险含义，没有定价权含义——所以它在 ④ 施洛斯卡与 ⑥ 造假分里都是扣分项，在 ⑤ 也不再作为加分证据。
- ③④⑤ 卡头的买/保/公三档与列表页后四列同源同口径，读法见 §2.3：账面派（③ 的进取型卡、④ 施洛斯卡）只有卖价为 `-` 表示现价已出该派射程、买点仍是目标价；收益派（③ 的防御型卡、⑤ 巴菲特卡）三档一起 `-` 才是盈利锚不可用。
- ⑥⑦ 脚注里的 Wind 优化项与 ⑫ 整块，读的是 Wind 事件覆盖层。**没抓过 Wind 事件的标的，⑥⑦ 只有量化分、⑫ 空白，属正常**。⑨ 价值综合分、⑩ 成长综合分与 ⑪ 价值陷阱分都不受影响——它们七项证据全取自财报（价值分还多吃一笔行情市值，陷阱分还多读定增/回购两张表），与 Wind 无关。
- 股本事件那一节把两笔的来源都摊开：定增给发行日（缺失取上市日）、发行价（元/股，未复权）、发行量、募集资金、发行方式、锁定期、发行前后股本、认购价、发行市场与认购对象；回购给两张表——最新公告记录与最近已完成回购，每行是笔/进度/日期/价格（元/股）/数量/金额/是否注销（用途）/用途，每个数值下面那行小字写明它取的是**累计成交值**还是**方案值**（方案上限、计划区间），最后附**判据句**（分类所依据的原文那句话）与可展开的**方案原文**。回购日期按行不同：最新公告那行是公告日（缺失取决议日），已完成那行是完成日（缺失取公告日）；同一笔两行会合并成「最新且已完成」。读这一节要记住：**注销三态是公告里的用途分类，不代表注销已办理；回购完成不等于注销完成**。
- 三大报表切换 tab + 报告期下拉，可以逐季看。A 股的三大报表与指标覆盖**最近 10 年（40 个季度）**；下拉里不足 10 年的绝大多数是 2016 年后上市的次新股，不是缺数。
- ① 快照里 `净现金/市值` 悬停有三行：第一项是代入式（每个加权项的科目金额与系数、减去的负债合计、除以的总市值），第二行是所取的资产负债表报告期，第三行是附注拆分出的定期存款与受限货币资金金额及其披露期。存款构成只在年报与半年报披露，所以最新一期是三季报时用的是上一期的构成——第三行会写明那是哪一期，两期不同属正常。
- ① 快照里的 `估值分位(10年)` 是 `PE / PB / PS` 三项各自的**近十年分位（Wind 口径）**，0~100 越低表示越接近自己十年的低位。窗口取多长、样本含不含极早期点、亏损期计不计都由 Wind 定，我们不复算也不改，所以这一行**不参与四派评分，也不进买卖点参考价**，只当位置感来看。悬停有外源观测日与每项各自的样本交易日数（新股天然不足十年，样本数就不足 2400 上下）。某项是 `-` 有两种原因：该标的还没被这轮铺到，或那个比率当前不可信（PE 为负即公司亏损，亏损期的「PE 分位」没有意义，我们直接置空）。
- 港股/美股的财年被归一化标到 12-31 以便与 A 股同轴对齐，那不是公司自己的财年末；详情页脚注会显示「本公司财年截至 …」。
- 港美股没有定期报告与审计意见（数据源不提供），所以 ⑥ 的审计口径缺失、⑫ 事件区空白。⑨ 价值综合分与 ⑩ 成长综合分在这两个市场照常给分（七项只读年报科目，价值分还要多吃一笔行情市值），只是美股的指标表没有「每股净资产」、分红表没有逐笔派现，那几项在美股恒判不动；⑪ 价值陷阱分写明**不适用**。
- 美股快照没有市净率与分红数据，相关列显示 `-`；市净率缺失不影响评分，评分会用财报每股净资产反推。

## 4. 农价页 `/#/agro`

两条独立的产品线，与股票链路互不影响：

- **农化价格**：6 个化工/农药品种（草甘膦、敌草隆、多菌灵、甲基硫菌灵、邻苯二胺、对硝基氯化苯），来自生意社，每天自动抓两次。
- **行业量价（EDB）**：汽车/铝/航运/轮胎/地产/煤炭/钢铁 7 个分类共 44 个指标，来自 Wind EDB，每周日自动更新一次。

看到「数据截至 …」表示该品种已有一段时间没发布新价格。生意社每周只更新 2~4 次，隔几天是正常的；超过三周会被记为断档并在采集日志里标红，**但旧价格照常入库展示，不影响页面使用**。

Wind 客户端未登录时，行业量价那一轮会失败且不改动任何已有数据——页面继续显示上一次成功抓取的历史序列。

## 5. 数据什么时候更新

理解这一节就能解释绝大部分「为什么这个数字看着是旧的」。

**节奏分两层，因为财务按季披露，没必要每天重抓 1.9GB 明细：**

| 层 | 频率 | 更新什么 |
|---|---|---|
| 行情 | 周一~周六 16:05、22:05 | 现价、涨跌、PE、PB、市值，以及**定增/回购明细**（东财两张表全量重取，约 25 秒），链尾**重算一次全部评分**（不重抓数据，只在输入变了才改分，≈20 秒） |
| 财务 | 周六 09:05 | 四表、指标、分红、报告、审计意见、现金类附注（定期存款/受限货币资金）、**全部评分与买卖参考价** |
| 农价 | 每天 09:05、21:05 | 6 个品种价格 |
| 行业量价 | 周日 20:00 | 44 个 EDB 指标 |
| 估值分位 | 每天 05:05 | PE / PB / PS 近十年分位（Wind 口径，每天铺约 2800 家、约 1.9 天铺完一轮） |

**关键推论：**四派评分、造假分、管理分、成长综合分、价值综合分、12 个买卖参考价是**财务的函数**（价值综合分 V 还多吃一份行情，它是下面那段说的例外之一），只在周六重算。所以「今天是否触发买点」= 今天的现价去比上周算出的参考价，这是有意设计——内在价值不随日内价格波动。

同理，新上市的标的要等到周六那轮才进池；日更只给已在池标的刷行情，不拉新名单。

定增/回购这两列跟着**日更**走（周一~六各两轮），所以新公告当晚就能看到、不用等周六；源侧若撤了公告，库里对应那笔也会跟着删掉（整表重取，按主键对齐）。

**例外有两处：价值陷阱分 T 与价值综合分 V 的市值那一项。** T 的输入里有定增史，所以跟着日更走——新公告当晚就可能点亮或熄灭一个可判项，列表页与详情页的 T 也就和定增列同一天。V 的便宜那 65 分吃市值，那份市值取**本批行情**（与列表页 `市值` 列、详情页顶部同一笔，见 §2.3），所以 A 股那一列每个交易日都会挪零点几分；港股、美股的行情与深抓快照同日，这两侧不动。其余六项与四派分、成长综合分 G、12 个买卖参考价照旧只吃深抓那一刻的快照——G 七项只读年报的四个科目，不含定增史也不含行情，所以它跟四派分一个节奏：新公告当晚不会让它动，要等周六那轮把新的一期年报灌进来。其余分数也按上一段的节奏，日更只是把它们用同一份财务数据重算一遍，而重算本身也可能让个别标的动：四派分里那项「近 1 年每股分红」的窗口是相对跑数日算的，一笔分红过了一年就出局（实测 2026-09-18 那轮 6,939 家里 19 家的施洛斯分只因这件事变，最新一批 A 股 `0/5553` 家成长分变）。所以「日更之后分数没动」不是恒成立的，只是当天没有新公告、新报表或到期的分红窗口时才成立。

运维层面还有三条影响体感的规则：

- 深抓（周六那轮）期间到点的行情 job 会**静默跳过**，这是互斥设计不是故障——深抓本身每只都带当日行情。
- 估值分位只刷过筛后的 5340 家（美股整市场不刷，A 股/港股里管理分 < 30 或造假分 > 50 的不刷），一轮要 108 次 Wind 调用，而单次实测约 13.9 积分、每天 1000 积分最多撑约 72 次，稳态只给它 56 次（余量留给同样吃 Wind 积分的周日 EDB 与手工核对），所以是**按游标滚动铺**的：某家今天还是 `-`、过两天就有了，属正常。这一列不参与评分与买卖点，缺它不影响页面上任何其他数字。
- 想临时补一轮，用 `.\ops\menu.ps1`（菜单选一个维度、当场看进度）或 `.\ops\collect.ps1`（见 §7.2），不必先停调度器；不想记参数就双击 `ops\jobs\run-<job>.bat`（见 §7.3）。

## 6. 系统怎么运转

### 6.1 数据流

```
外部数据源                采集层（collector）              服务层（app）              界面
─────────────           ────────────────────           ──────────────            ──────
腾讯 qt.gtimg.cn  ─┐    scripts/fetch_data.py
东财 datacenter   ─┤ 抓取 scripts/scoring.py      回灌  FastAPI :8000           Vue3 SPA
  （含定增/回购）  ─┤      scripts/fetch_actions.py
巨潮 cninfo       ─┘      scripts/universe.py  ──────→  /api/*        ──────→  （hash 路由）
本地 Wind CLI     ──→  data/companies/*.json           /  托管 frontend/dist
  (EDB/估值分位)       data/index.json            ──→  MySQL db_va (19 表)          ↓
生意社 / Wind EDB ──→  agro-price/scripts/*  ────→  /api/agro  ─────────────→  /#/agro
```

三条要遵守的约定：

1. **采集层产出静态 JSON，MySQL 是它的投影。** `collector/data/` 是真源，`import_legacy.py` 单向灌库——直接改库里的数据，下一次回灌会被覆盖掉。
2. **`index.json` 是全市场入口，不是明细。** 7000 只明细约 1.9GB，任何新代码都不要逐只读文件，只读 `index.json`（≈ 5.5MB）。
3. **数据库是查询层。** 列表的筛选、排序、分页全部由 SQL 完成（`score_daily` + `quote_daily`），这些表上的索引就是性能预算。

GitHub Pages 上的纯静态旧版仍在博客仓库保留，作为回退；以本仓库与 `db_va` 为准。

## 7. 部署与运维

### 7.1 首次部署

前提：Windows + Python 3.10（代码用了 `X | None` 写法）+ Node 20 + MySQL 8 已在 3306 运行。

下文命令里的 `<项目目录>` 指本仓库在你机器上的路径（例如 `D:\code\stock-value-analysis`），照自己的实际位置替换。

```powershell
# 1) 建库
mysql -u root -e "CREATE DATABASE IF NOT EXISTS db_va DEFAULT CHARSET utf8mb4;"

# 2) 装依赖
cd <项目目录>\backend
pip install -r requirements.txt -r collector\requirements.txt

# 3) 配环境
Copy-Item .env.example .env    # 编辑 DATABASE_URL / LEGACY_DATA_DIR / BOND_10Y

# 4) 建表（按 ORM 元数据 create_all，等价 docs/schema.sql）
python -X utf8 -m scripts.create_tables

# 5) 首轮全市场深抓（≈5 小时，可中断续跑）
python -X utf8 -m collector.run deep

# 6) 全量回灌 MySQL
python -X utf8 -m scripts.import_legacy --no-clean

# 7) 构建前端并启动服务 + 调度器
cd ..\frontend; npm install; npm run build; cd ..
.\ops\start.ps1 -Rebuild
```

打开 <http://127.0.0.1:8000/>。第 5/6 步只在首次或换机器时需要，之后交给调度器。

**`.env` 四个键**

| 键 | 例值 | 说明 |
|---|---|---|
| `DATABASE_URL` | `mysql+pymysql://root@localhost:3306/db_va?charset=utf8mb4` | 无密码时不要写 `@` 之外的空字段 |
| `LEGACY_DATA_DIR` | `<项目目录>\backend\collector` | 采集产出根目录，本仓库自给自足，不依赖博客仓库 |
| `BOND_10Y` | `0.017` | 十年期国债收益率，用于 EPV/DCF 折现 |
| `WIND_SKILL_DIR` | `<wind-mcp-skill 目录>` | 只有 `edb` / `events` 两个 Wind 任务用，指向本机 wind-mcp-skill 目录；不配不影响其他 job |

### 7.2 六个运维脚本

双击 `ops\start.bat` / `ops\stop.bat` 也可以，或命令行：

| 命令 | 作用 |
|---|---|
| `.\ops\start.ps1` | 起 FastAPI + 调度器（已在跑则逐个跳过，可重复执行）。`-Rebuild` 先构建前端，`-NoScheduler` 只起服务，`-Lan` 监听 `0.0.0.0` |
| `.\ops\stop.ps1` | 关服务 + 调度器 + 采集子进程。`-Api` / `-Scheduler` 单关；**有采集任务在跑时只用 `-KeepJobs`**（见 §7.5） |
| `.\ops\status.ps1` | 一屏看：MySQL、服务 PID、健康检查、前端产物、采集进程、抓取锁、`index.json` 条数/时间/体积。`-Jobs` 附带最近运行记录 |
| `.\ops\guard.ps1` | 幂等拉起（崩溃自愈）。稳态只查进程表，亚秒返回；`run/.paused` 存在时静默让路 |
| `.\ops\collect.ps1` | 手动补跑采集 job，跑的是调度器同款命令（自动回灌 + 写 `etl_job_log`），不用先停调度器。默认 `daily` = `stock → agro`；`-List` 看 job 表与时刻；`-Background` 让长任务转后台 |
| `.\ops\menu.ps1` | 跑数菜单 + 实时进度表：选一个维度就开跑，当前窗口只当看表（见 §7.3）。`-Job deep` 跳过菜单，`-Watch` 附著到现在正在跑的那一轮，`-NoWatch` 拉起即退出 |

判活按**命令行特征**匹配进程而不是 PID 文件，换机器不会状态错乱。日志落在 `run/*.log`，环境变量 `VA_PORT` / `VA_PYTHON` 可覆盖端口与解释器路径。

`run/.paused` 由 `stop.ps1` 写、`start.ps1` 删。没有它的话手动停机会在 10 分钟内被守护拉起来。

### 7.3 跑数菜单与实时进度表（`menu.ps1` + `jobs/*.bat`）

不想记 job 名与参数时的入口：`ops\jobs\` 下每个维度一个双击文件（`run-stock.bat` / `run-deep.bat` / `run-agro.bat` / `run-edb.bat` / `run-valuation.bat` / `run-events.bat` / `run-import.bat` / `run-daily.bat` / `run-watch.bat`），或 `ops\jobs\menu.bat` 进菜单选。菜单头一屏给全：MySQL/服务/调度器在不在、此刻哪个 job 在跑、每个维度的内容与量级、以及从 `etl_job_log` 读的「最近一次：时间 / OK / FAIL / 用时」（`[Wind]` 那三个会先二次确认，因为积分是日预算制）。

为什么看表要「后台跑 + 前台看」：`run.py` 只在收尾才写 `etl_job_log`，前台跑一半 `Ctrl+C` 会留下一条永不结束的 `running`（2026-09-03 的 id=14 就是这么来的）。所以 `menu.ps1` 一律把采集交给 `collect.ps1 -Background`，自己只负责看：**关窗口或 `Ctrl+C` 只是结束看表，采集进程照跑**，回头 `menu.ps1 -Watch` 再接上。起跑仍走 `collect.ps1`，`.env` / MySQL / 已有采集进程三道前置检查只有一份口径。

看表读的是日志里现成的心跳，不改爬虫：`fetch_data` 每 200 家一行 `[400/6939] … ok=400 part=0 fail=0 ETA=2.0h`、`import_legacy` 每 500 家一行 `[import] 1500/6939`、`fetch_valuation` 每批一行 `批 3/56`。三种口径都扫一遍取**最后一次出现的行号**当当前阶段，所以同一轮里从抓取切到回灌，进度条会自动跟着换。没有可数分母的那两类（`agro` 收尾才吐、`edb` 每指标一行无总数）就只报已跑时长 + 日志最后一行。

三条实测出来的口径，改脚本时不要退回旧写法：

- **「现场」日志有两个文件**：手动 `-Background` 写 `run\collect.<job>.out.log`，调度器触发的那一轮只写 `run\scheduler.out.log`。判断用哪个只看 mtime 是否不早于进程创建时间，都不新时信调度器——拿上一轮遗留的 collect 日志当现场就是假进度（第一版就是漏了这个：从没手动跑过的 job 整轮显示「无日志」）。读调度器日志时还要从本轮那行 `[scheduler] … 触发 <job>` 切起，否则并行另一个 job 的进度会被当成当前进度。
- **静默阈值必须按 job 分档**（`$QuietStall`）：`fetch_prices.py` 整轮中途一个字不吐（品种报告集中在收尾，实测一轮 7 分多钟零输出），给它 3 分钟阈值就是每轮误报；`fetch_data`/`import_legacy` 有几十秒一行的心跳，才用 300~600 秒。
- **取整一律 `Floor`，不用 `[int]`**：PowerShell 的 `[int]` 是四舍五入，151 秒会变 3 分钟（`[int](151/60)=3`），「已跑多久」往大跳一分钟恰好落在「这轮是不是卡了」的判断上。中文在控制台占两格，所以原地重画的截断/补空格也得按格算，按字符数算会超窗自动换行、残掉上半截旧字。

### 7.4 崩溃自拉起

靠 Windows 计划任务每 10 分钟跑一次 `guard.ps1`。本机已注册；**换机器要重跑一次**：

```powershell
schtasks /Create /TN "va-guard" /SC MINUTE /MO 10 /F `
  /TR "powershell -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File <项目目录>\ops\guard.ps1"
# 验证：schtasks /Run /TN va-guard，然后看 run/guard.log 新增一行「服务在线,无动作」
```

三条约束：

- **同一台机器上只保留一个守护任务**。多个任务跑同一个 `guard.ps1` 功能上不出错，但会重复判活并放大误判。
- **部分杀软会把 `guard.ps1` 判为恶意脚本**（隐藏窗口 + `-ExecutionPolicy Bypass` 派生子进程是典型特征），严重时文件被截成 0 字节。若遇到，把 `ops/` 加入排除项后重新保存文件再注册。
- 在受限/沙箱环境里 `Get-CimInstance Win32_Process` 查不到 python 进程，guard 会误判缺失并白拉一次 `start.ps1`（幂等，不会弄坏在线服务）。判活以计划任务自己写出的 `run/guard.log` 为准。

### 7.5 症状 → 处置

| 症状 | 原因 | 处置 |
|---|---|---|
| `[lock] 已有抓取在跑…` + 退出码 2 | 正常互斥 | 不用管。`status.ps1` 显示持锁 PID **已死**时 `Remove-Item backend\collector\data\.fetch.lock` |
| 抓取落盘变慢或停止 | 三种成因外观相同（文件不涨 + CPU 低）：工人在等活（`--chunk` 静态切块导致尾部堆积）、真挂在数据源读上、只是慢（主板 `601xxx` 年报 PDF 单份 30MB+）。注意本任务 I/O 密集，CPU 低不能证明挂死 | 用 `py-spy dump --pid <工人PID>` 看栈顶定性：停在 `queue.get` = 等活，把 `--chunk` 降到 60~100 重跑；停在 `ssl.read` = 真挂起 |
| 父进程没了但 CPU 仍在烧 | 孤儿 spawn 工人 | `.\ops\stop.ps1`（已匹配 `multiprocessing\.spawn\|fetch_data\.py`） |
| 服务起不来，`run/api.err.log` 有连接错误 | MySQL 没起 / `.env` 密码错 | 启 MySQL；`Test-NetConnection 127.0.0.1 -Port 3306` |
| 页面空白但 API 正常 | `frontend/dist` 不存在或过旧（启动时才探测） | `.\ops\start.ps1 -Rebuild` 后重启服务 |
| 手机打开是 IIS 默认页 | 用了 `http://` 或没入 tailnet | 换成完整的 `https://…ts.net/`，见 §1.2 |
| 列表筛「创业/科创」数量为 0 | 深抓按代码升序推进，该段还没抓到 | 等 `deep` 跑完，或 `fetch_data --codes …` 定向补 |
| 财务数据看着没更新 | 按季披露，日更本来不碰 | 看 `deep` 最近一次 `etl_job_log` |
| 页面上某个数字永远是旧值 | 尚未回灌，或需要一次全量重灌才能刷进修订值 | `python -X utf8 -m collector.run import` |
| `etl_job_log` 里一条 `running` 永不结束 | 跑 job 期间用了不带 `-KeepJobs` 的 `stop.ps1`，采集子进程被连带杀掉，没机会写终态 | 幂等重跑那轮；按 `scripts/job_status` 提示补一条终态 |
| 想立刻补抓失败股票 | `data/crawl_failed.json` 有清单 | `fetch_data --codes <粘贴> --audit-scope full` 再 `import_legacy --no-clean` |
| 推送 GitHub 失败 | 本机需走代理 | `git -c http.proxy=http://127.0.0.1:1080 push origin main`（临时指定，不改全局配置） |

### 7.6 日志与现场

`run/api.{out,err}.log`、`run/scheduler.{out,err}.log`、`run/guard.log`、`backend/collector/data/crawl_all.log`（tqdm 进度写 stderr 且用 `\r`，抓摘要看 `grep '^\['`）。

服务每次启动前会把上一轮的输出流改名成 `run/<流名>.<yyyyMMdd-HHmmss>.log`，每条流只保留最近 10 份，空日志不留副本。这样「错过触发」这类问题还能回查现场。

两个容易误判的点：

- **`api.out.log` 是 0 字节不代表服务没在跑**——Python 的 stdout 被重定向后是块缓冲，要攒满才落盘。确认真实状态请用 `status.ps1` 而不是看日志尾部。
- **抓取进度看这三样**：`collector/data/index.json` 的 mtime、`.fetch.lock` 的内容（持锁 PID）、日志尾部。SQL 只能看到**已回灌**的部分。

判断本轮是「慢」还是「停」要拿增量而不是总文件数（总数会把上一轮的成品算进来）：

```powershell
cd backend\collector; $t = Get-Date '2026-09-05 20:00'   # 换成本轮启动时刻
(Get-ChildItem data\companies\*.json | Where-Object { $_.LastWriteTime -gt $t }).Count
Start-Sleep 90
(Get-ChildItem data\companies\*.json | Where-Object { $_.LastWriteTime -gt (Get-Date).AddMinutes(-2) }).Count
# 近 2 分钟落盘数应为个位数以上
```

需要手工重启抓取时，**只杀抓取进程组**（裸 `stop.ps1` 会连带关掉 API 与调度器），且**只杀父进程会留下若干孤儿工人**：

```powershell
$lock = 'backend\collector\data\.fetch.lock'
$pp   = Get-Content $lock                                   # 持锁父 PID
$kids = Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
        Where-Object { $_.ParentProcessId -eq [int]$pp }
Stop-Process -Id (@([int]$pp) + @($kids.ProcessId)) -Force
Remove-Item $lock
# CIM 被权限拒绝时：先杀父，再按 StartTime 同一秒筛选补杀工人
```

长任务要**后台启动**，前台进程会随会话结束被连带杀掉。

进度体检 SQL：[`backend/scripts/progress.sql`](../backend/scripts/progress.sql)（8 条只读查询，覆盖回灌完成率、各表覆盖只数与缺口、最近写库距今、报告期覆盖、运行记录、MySQL processlist、全库体量）。

## 8. 采集任务

统一入口 `python -m collector.run <job>`（在 `backend/` 下执行），每个 job 的产出都写 `etl_job_log`。

### 8.1 任务一览

| job | 内容 | 参数 | 耗时 |
|---|---|---|---|
| `stock` | 全市场行情快照 + 定增/回购明细 + 评分重算（只重算，不重抓） + 增量回灌 | `fetch_data --all-market --snapshot-only --quiet` → `fetch_actions.py`（东财两张表全量重取，约 25 秒）→ `_refresh_scores.py`（≈20 秒）→ `import_legacy --only-fresh 26 --no-clean` | ≈3~5 分钟（2026-09-16 并入重算后实测 302 秒，其中重算 20 秒） |
| `deep` | 全市场财务四表/指标、分红、定期报告、审计意见与现金类附注（年报＋半年报都解析）、评分重算、新标的进池 | `fetch_data --all-market --hk-connect --us-indexes --workers 4 --resume --max-age 6 --chunk 400 --flush-every 200 --audit-scope full --quiet` → `_refresh_scores.py`（把 `--resume`/`--max-age` 跳过、本轮没重抓的那些公司的分数一并重算） | ≈6 小时 |
| `agro` | 生意社 6 个产品价格 + 回灌（不碰 Wind） | `agro-price/scripts/fetch_prices.py` → `import_legacy` | 分钟级 |
| `edb` | 44 个行业量价指标（Wind EDB） | `agro-price/scripts/fetch_edb.py`（默认增量窗口，`--dry-run` 零成本看本轮计划）→ `import_legacy` | 单次 7 次 Wind 调用 |
| `valuation` | PE / PB / PS 近十年分位（Wind），滚动铺 A 股/港股过筛标的 | `fetch_valuation.py --calls-cap 56`（`--probe N` 只验一批、`--reset` 丢弃游标重铺、`--calls-cap 0` 一轮铺完）→ `import_legacy` | 每天 ≈56 次 Wind 调用（≈780 积分），一轮 108 次 ≈1500 积分、≈1.9 天铺完 |
| `events` | Wind 结构化事件 + 股东结构，重算 `wind_*` 覆盖层 | `fetch_events.py [--codes …\|--force\|--recompute\|--limit N]` | 手动，不进调度 |
| `import` | 只回灌，不抓取 | `import_legacy --no-clean` | 秒~分钟 |

多步 job（如 `stock` 是 `fetch_data` → `fetch_actions`）按表里顺序依次跑，**尾部透传参数只作用于首个脚本**，后续脚本一律按自身默认参数跑（所以 `collect.ps1 stock --codes 600519` 只改行情抓取范围，不影响定增/回购的全表重取）。

`edb` 与 `valuation` 两个自动任务依赖本机 Wind 客户端（要客户端登录、按调用耗积分），所以各自单独排时刻：`edb` 周日 20:00，`valuation` 每天 05:05——避开 16:05/22:05 两个行情 job 与周六深抓、周日 EDB。`valuation` 一轮要 108 次调用，而单次实测约 13.9 积分、每天 1000 积分最多约 72 次，稳态只给它 56 次（约 780 积分，余量留给周日的 `edb`），所以它靠 `data/valuation/state.json` 记游标跨天续跑，**跑到当日上限属于预期收尾（退 0）**，不会把 `etl_job_log` 天天记红；只有连续多批取数失败才退 1。`events` 覆盖 A 股事件与股东、一次要跑几千只，按量计费不适合无人值守，保持手动。这三者失败都只记日志，不会污染已有数据。

`deep` 的两个关键参数：`--resume` 跳过 `mtime` 在 `--max-age`（6 天）内的明细，中断后重跑同一命令即可从断点续抓；`--audit-scope full` 把定期报告 PDF 解析范围放到年报＋半年报——审计意见只在年报里，而 `净现金/市值` 依赖的存款构成（`其他流动资产` 明细、受限货币资金）这两份里都有。同一份 PDF 抽过就不再重下（结果记在该公司的明细里），所以这份开销主要是首轮一次，之后只在有新半年报/年报披露时发生。`annual`（只解析年报）与 `none`（完全不解析）是两档降级开关。首轮那个量级可以这样预算：A 股 5553 家不带 `--resume`、年报＋半年报全量重抽，4 进程实测 4.5 小时（≈21 家/分钟），全程只在下 PDF 的那几秒打巨潮静态站点。

### 8.2 抓取互斥锁

`fetch_data.py` 启动时抢 `data/.fetch.lock`（内容 = 父进程 PID）：

- 锁存在、持锁 PID 存活、锁文件 45 分钟内被刷过 → 打印 `[lock] 已有抓取在跑`，退出码 2
- 抓取过程中会 `touch` 锁文件作心跳，只有真卡死才会被 45 分钟超时接管
- `run.py` 侧同口径判活，把「锁被占」记成 `etl_job_log` 里的 `skipped` 而不是失败

### 8.3 `fetch_data.py` 参数

| 参数 | 含义 |
|---|---|
| `--all-market` | 名单取 `universe.py`（交易所 + 新浪交叉校验 ≈5553 只） |
| `--hk-connect` | 只跑港股通标的（≈621 只）；可与 `--all-market` 同给合为一轮 |
| `--us-indexes` | 只跑美股五大指数成分并集（≈765 只）；可与上两项同给 |
| `--codes 600011,HK.00700` | 只抓指定代码（补抓失败清单走这个）；带 `HK.`/`US.` 前缀可跨市场混写，不带前缀时市场由 `--codes-market` 决定（默认 `A`） |
| `--workers 4` | spawn 进程池并发（必须 spawn，不能用 fork） |
| `--chunk 400` | 每个池任务处理的股票数，也是崩溃隔离粒度。**静态切块**，尾部容易堆积，卡住时优先降到 60~100 |
| `--flush-every 200` | 每 200 只落一次 `index.json` |
| `--resume` / `--max-age N` | 跳过 N 天内已抓过的（默认 1 天） |
| `--snapshot-only` | 只刷 `index.json` 里的行情，不重写明细 → 明细 `mtime` 不变，`--resume` 判据仍是「财务新鲜度」 |
| `--audit-scope full\|annual\|none` | 定期报告 PDF 解析范围：`full`＝年报＋半年报，`annual`＝只年报，`none`＝完全不解析。同一份下载既出审计信息（事务所＋意见类型）也出现金类附注（定期存款／受限货币资金，`净现金/市值` 用它拆构成）；季报不审计也不单列附注，所以只有 `full` 才拿得齐构成 |
| `--shard i/N` | 分片并行，如 `2/4` 只抓第 2 片 |
| `--limit N` | **调试专用**：会把 `index.json` 重建成部分公司，勿在生产工作目录使用 |
| `--quiet` | 只打摘要 |

### 8.4 `fetch_edb.py` 参数

| 参数 | 含义 |
|---|---|
| `--only alu` | 只抓某一类（7 个分类 id：`auto/alu/shipping/tire/realestate/coal/steel`） |
| `--begin` / `--end` | 显式窗口，人工回填历史就靠它（给 `--begin` 即绕过增量窗口与封顶） |
| `--buffer-days 45` | 含累计差分/月均口径的分类往前多拉的天数，只用于算窗口首点，不写进产物 |
| `--max-span-days 120` | 增量模式下单次往前多拉的上限，某条序列断更半年也不会自动引出一次大抓取 |
| `--dry-run` | 只打本轮计划（几次调用 / 几个指标 / 多少天窗口），一次 Wind 也不调、不写盘 |

Wind 不回报积分余额，所以可审计的量只有两个：**调用次数**（一个分类一次批量传码，全量 7 次）与**时间窗口**（增量模式下各分类合计约 265 天）。控成本先从 `--dry-run` 看这两个量，降频或减分类都比重跑历史便宜。

**EDB 历史点删了补不回来**，所以写盘前有两道防线，任一命中就退出且不覆盖旧文件：与旧 `edb.json` 合并出现任何异常（包括旧文件存在但读不动）；合并结果点集比旧文件小。本轮 Wind 空返回**不算失败**，退 0 且旧序列原样保留——只有「会把历史洗掉」才拦。分类的 `range` 一律按真实点位回写，不按本轮抓取窗口，下游拿它做删除防线。

统计局口径的「年初至今」累计值不能当全期累加算差分。修正存量用 `python -X utf8 scripts/fix_edb_cumulative.py`，它带 2~3 倍量级比阈值会自动拒绝年末交付潮这类误判，建议先 dry-run。

## 10. 数据库口径（`db_va`，19 张表）

通用约定：

- **`security.sid` 是唯一内键**，所有子表用 `sid` 外联，不用 `(code, market)` 复合键。
- **金额一律为元、比率一律为小数**（`0.35` = 35%），与 JSON 服务口径一致。
- **中文长尾科目进 `extras` JSON**，只有核心评分/展示科目才建实体列。
- **主键即幂等**：除三张标注「无自然唯一键」的表外，回灌都是 `INSERT … ON DUPLICATE KEY UPDATE`。
- DDL 存档在 [`docs/schema.sql`](schema.sql)，与 `app/models/entities.py` 同构。

### 10.1 主数据与行情

**`security`** — 证券主表 | PK `sid` | UK `(code, market)`  
`code/market`（`A/HK/US`）、`name`（ST 前缀原样保留）、`industry`、`exchange`、`currency`、`status`、`list_date`、`updated_at`。退市股不会被自动删除——名单源只含在市标的，需要人工清理。

**`quote_daily`** — 每日行情快照 | PK `(sid, trade_date)`  
`price, change_pct, pe_ttm, pb, market_cap, float_market_cap, turnover_rate, fetched_at`。八个字段全部来自腾讯批量行情，PE 为 TTM 口径，市值为本币元。**每票每交易日一行**，是「历史」唯一的积累处，本表自 2026-09-02 起才有数据。

**`valuation_pctile`** — PE / PB / PS 近十年分位（外源 Wind 口径）| PK `sid`  
`pe_pctile / pb_pctile / ps_pctile`（0~100）、`pe_days / pb_days / ps_days`（外源实际用了多少个交易日，新股天然不足十年）、`trade_date`（外源那一行自己的观测日，各市场节假日不同而错开）、`source`（逐指标的 Wind 回码、观测日与所属轮次）、`updated_at`。索引 `idx_list_pb_pctile(pb_pctile)` 服务列表页那一列的筛选与排序。

这是子表里唯一一张以 `sid` 为单主键的表（其余子表都带报告期或交易日）：它是外源截面，约 1.9 天铺完过筛池一轮（美股与管理分 < 30／造假分 > 50 的标的不在刷池内）、铺到就整行覆盖，留着历史等于把别人的口径当我们的历史存。分位窗口多长、样本含不含极早期点、亏损期计不计入都由 Wind 决定，本项目不复算，所以**这一列不参与四派评分与买卖点**。可信性判断全在采集侧做完（比率为负、外源日期过旧、分位数越出 0~100 一律置空），因此**落库的行即可信行**；三项分位全空的标的整行不落，让「铺到但没有效值」与「根本没铺到」在数上分得开。

### 10.2 财务明细（PK `(sid, report_date)`）

| 表 | 内容 | 关键列 |
|---|---|---|
| `fin_indicator` | 同花顺口径摘要指标，**评分主要输入** | `revenue, net_profit, eps, bps, gross_margin, net_margin, roe, current_ratio, quick_ratio, debt_ratio, ocf_per_share, revenue_q, net_profit_q, extras` |
| `fin_income` | 利润表 | `revenue_total, operating_profit, net_profit, deducted_net_profit(扣非), extras` |
| `fin_balance` | 资产负债表，评分核心科目全部实体化 | `total_assets, cash, trading_fin_assets, notes_receivable, other_current_assets, total_liabilities, equity_parent, equity_total, paid_in_capital, short_loan, long_loan, bond_payable, lease_liability, noncurrent_due_1y, extras` |
| `fin_cashflow` | 现金流量表 | `ocf, capex, cash_received_from_sales(销售收现), extras` |
| `fin_note` | 现金类构成附注（定期报告 PDF 解析），`净现金/市值` 靠它把 `其他流动资产` 里的定期存款与留抵税额分开 | `term_deposit(定期存款), restricted_cash(受限货币资金), source(出自哪份披露：公告日/类别/PDF 直链)` |

`fin_balance` 里那一长串借款/债券/租赁列是为**净现金**和**格雷厄姆数字**服务的，不是冗余列。季度报告期统一按自然季末日；港美股财年归一化到 12-31 只为与 A 股同轴对齐（见 §3 读法）。金额一律本币原值不折汇率。

### 10.3 `score_daily` — 每日评分快照

PK `(sid, trade_date)`，`report_date` 记录这批评分基于哪期财报的**报告期期末**（不是跑数日，也不是公告日）：评分引擎按「最新年报」建模，所以它取 `compute_scores.reportDate`（与 `annual_rows` 只取 12-31 同一口径），算不出才退 `net_cash_calc.report`，两者都无才落跑数日。**旧写法只认后者**，算不出净现金的公司就整片回落成跑数日（回落行数在 2026-09-08~09-11 那几轮是 110~126 行，2026-09-12 那轮直接顶到 5095/6939——附注一漂就整片失去报告期），于是报告龄与「这批分用的哪一期财报」双双无法回答；修口径后回灌一轮（2026-09-13），回落行数 5095→0。列表页的 `期龄N月` 就是 `TIMESTAMPDIFF(MONTH, report_date, trade_date)`，按**行自身的** `trade_date` 算（逐证券各取最新一行，三个市场的日期本就错开，拿全局最新日算会给美股多算一天）。列表页所有筛选/排序/买卖点判定都在这张表 + `quote_daily` 上完成 SQL，`idx_list_fraud/mgmt/cycle/trap/growth/value/gate/graham_agg/graham_def/schloss/buffett` 这十一条 `(trade_date, 该列)` 索引服务的是**单日截面直查**：`WHERE trade_date=某天 [AND 该列 比较] ORDER BY 该列` 实测 `type=ref` + `Using index`（降序那侧多一个 `Backward index scan`），`gate` 那列按 `=1` 查只捞到 344 行、`=0` 捞 6569 行。`trap`、`growth` 与 `value` 三条两种形状都测过：只排序不比较时 `type=ref` + `Using index`（覆盖索引出 6939 行，`trap` 1.67 ms、`growth` 1.23 ms、`value` 3.9 ms），带上 `trap > 50`、`growth > 70`、`value > 50` 这种比较时优化器改走 `type=range` 的 covering index range scan（`trade_date = 那天 AND 比较`，分别 168 行 0.06 ms、825 行 0.21 ms、1037 行 0.40 ms，降序仍带 `Backward index scan`），六种组合都不落 filesort。

**列表接口本身却用不上它们**（满量 EXPLAIN 实测）：那个形状先由 `(sid, MAX(trade_date))` 的派生表定下「每家最新那一行」——MySQL 8 走的是主键上的 covering index skip scan（24 ms 出 6939 行），再按主键 `eq_ref` 逐行回表，评分列的过滤只作为回表后的 `Using where`，列索引没有插手的余地；按分数列排序时在派生结果上做 `Using temporary; Using filesort`（5273 行入排序，整条 `EXPLAIN ANALYZE` 103 ms），只有默认的按代码排序能靠 `security` 的 `uk_code_market` 有序扫描免掉 filesort。所以给 `gate` 补这条索引对列表页的实测收益是 0（`market=A` 无门槛 147 ms → 带 `gate=false` 192 ms，那 45 ms 是多一次比较的开销，不是索引缺失），保留它是为了跟其余十条同形（`trap`、`growth` 与 `value` 三条同样是这个理由）、并服务上面那种截面直查与导出类查询；`期龄` 门槛是 `TIMESTAMPDIFF(...)` 表达式，任何索引都吃不到，同样只在回表后过滤。

| 列组 | 列 | 含义 |
|---|---|---|
| 四派分 | `score_graham_agg / _def / score_schloss / score_buffett` | 0~100，越高越符合该流派标准；有指标取不到时按有效满分折算（量纲随之变小），详情页卡片抬头会标注该有效满分 |
| 辅助分 | `fraud` / `mgmt` / `cycle` | 造假可能性（**越低越好**）/ 管理层水平 / 周期位置；配套 `cyclical`、`cycle_trend` |
| 陷阱分 | `trap` / `trap_c` / `trap_eval` | 价值陷阱分 T（**越低越好**，算法与口径见 §2.3）/ 未归一的证据合计 `C = Σ ln(lift)×亮灯项`（0~4.92）/ 七项里判得动几项。三列由 `compute_scores` 一次算出，与前端那份权威实现逐项对账（`_score_check.py` 对 `_score_check_node.js`）。`NULL` 有两类：非 A 股整列不适用（实测 1386 行全 `NULL`），与 A 股但年报序列本身算不出（`trap_eval=0` 且无评分基准，实测最新一批 5553 家 A 股里 0 行）。档位着色查 `trap_c` 而不是 `trap`：分数舍入到一位小数后正好落在档位边界上会串档，两侧就会给出不同的档；`trap_c` 不建索引，因为它与 `trap` 同序，排序走 `trap` 那条就够 |
| 成长分 | `growth` / `growth_eval` | 成长综合分 G（0~100，**越高越好**，与 `trap` 方向相反；算法与口径见 §2.3）/ 七项里判得动几项。两列同样由 `compute_scores` 一次算出，与前端那份权威实现逐项对账。覆盖项数必须并列存：G 也是固定分母（ΣW=100），缺项只压低分数不重新归一，七项齐全的 60 分与只有三项算得出的 60 分不是一回事。`NULL` 只有一类含义——年报序列本身判不动（公开年报不足 3 期，或期次够但各增速项基期都取不到正的值），实测最新一批 A 股 0 行、港股 32 行、美股 4 行为 `NULL`；七项只读年报科目，所以**不存在陷阱分那种「非 A 股整列不适用」**。档位着色查 `growth` 这个显示分本身（不额外存未归一原值）：列表页与详情页读的是同一个数，两页不会各说一套 |
| 价值分 | `value` / `value_eval` | 价值综合分 V（0~100，**越高越好**，与 `growth` 同向；算法与口径见 §2.3）/ 七项里判得动几项。两列同样由 `compute_scores` 一次算出，与前端那份权威实现逐项对账，覆盖项数并列存的原因与 G 相同（固定分母 ΣW=100，缺项只压低不重归一）。`NULL` 也只有一类含义——年报序列或市值与质量项一起判不动，实测最新一批 A 股 0 行、港股 29 行、美股 1 行为 `NULL`。**这一列与上面三列不同：它是唯一一个把行情市值当输入的入库分数**，前 65 分要吃到市值，而它吃的是**本批行情那一笔**（与响应 `market_cap`、详情页顶部同一个数，日更链尾重算时刷新），不是深抓那一刻的快照——所以 A 股这一列每个交易日都会动，港股、美股的行情停在周六故不动（见 §2.3、§5）。也正因为这一步，它与同一张表里 `net_cash_calc.mcap`（净现金/市值用的那份市值，随深抓快照走）**不再同源**：实测最新一批两家都有的 5,509 家里 5,424 家这两个市值不同、多数差在 1~3%。这是 §5 那两条节奏并存的结果（便宜度按当批行情读、内在价值与参考价不随日内价格波动），不是漏改；拿 `value` 反推 `net_cash_ratio` 或反过来，都会差这几个点。`value_eval` 在这几列里最要紧，只算得动 35 分质量项的公司也能显出一个不低的分。档位着色与 G 同形，查 `value` 这个显示分本身 |
| 价值锚 | `fair_liq` / `net_cash_ratio` / `net_cash_calc` | 清算价值每股 / 净现金占市值 / 净现金计算过程 JSON（科目金额、附注拆出的定期存款与受限货币资金及其期次、负债合计与总市值，可复算） |
| 推荐分 | `recommend` / `recommend_gate` | 综合推荐分 R（0~100，**越高越好**）＝门槛外的 0.6×`value` + 0.4×`growth`（口径与出厂检验见 §2.3）/ 无分原因。`recommend_gate`：`pass` / `fraud`·`trap`·`interim`（中报恶化 dip ≤ −70%）及其 `+` 组合 / `nodata`（门槛过了但 V/G 判不动）——列表页的 `-` 靠它区分「不过线」与「算不出」。行情节奏跟 `value`（0.6 权重吃本批行情）；门槛输入不含行情，`recommend_gate` 只随财报与定增快照动 |
| 中报恶化 | `interim_dip` | 最新一期季报/半年报的扣非（缺则净利）同比，**分母 |基期|**。`NULL`＝最新一期已是年报或双期缺一，不是「没恶化」；≤ −0.3 前端挂「中报−xx%」徽标（只标注不折分）。评分轴只吃年报，这一列是「年报正常、之后中报变脸」盲区的探针（实例与阈值回测见 §2.3） |
| 价格参考 | `buy_<派>` / `sell_cons_<派>` / `sell_fair_<派>`（12 列） | 买入价 / 保守卖出价 / 公允卖出价，算法见 §2.3。`NULL` 有两种：账面派出射程只空两档卖价（买点照给），收益派盈利锚不可用则三档一起空。卖点筛选要求现价同时不低于保、公两档，`NULL` 一律不命中 |
| Wind 增量 | `wind_fraud_delta` / `wind_mgmt_delta` / `wind_flags` / `wind_overlay` | 事件对基础分的加减；标签数组；`events/index.json` 的 `byCode` 条目全量透传（详情页 ⑥⑦⑫ 读它） |
| 硬门槛 | `gate` / `gate_flags` | 二元否决位与命中项。**不是采集产物**（`index.json` 里没有），而是回灌时拿库里已导入的定性事实贴标（`import_legacy.load_gate_facts`，在两条回灌路径上都在财务表回灌**之前**跑，用的是上一轮的权益与审计意见——年报口径一年只变一次，滞后一轮不影响判断，真要当场反映就再跑一次 import）。四项取值：`audit_qualify`＝最近一份**披露**的年报（`periodic_report.report_date` 是公告日，`MAX` 即最近那份）审计意见不在 `标准无保留意见`/`无保留意见` 之内；`risk_warning`＝`market='A'` 且简称含 `ST`（风险警示是 A 股专有制度，不限定市场会误命中 88 家美股）；`case_filed`＝`wind_event.etype` 有违规/立案/处罚/ST；`neg_equity`＝最新年报（12-31 那行）`equity_parent`（缺则 `equity_total`）< 0。三值语义：命中 `TRUE` / 可判而未命中 `FALSE` / 一个信号都判不了 `NULL`，所以 `gate=true|false` 两个方向都不会带出 `NULL` 那批，与市值/净现金「算不出就不进区间」同一口径。实测 344 触发 / 6569 未触发 / 26 判不了 |

### 10.4 报告与分红

**`periodic_report`** | PK `id` | UK `(sid, report_date, category)`  
**`report_date` 存的是公告日**（源 JSON 的 `date`，即巨潮那张公告页的披露日期），**不是报告期期末**——期次只能从 `title` 读。两个后果：① `MAX(report_date)` 的那一份年报正好是「最近披露的那份年报」，硬门槛要的正是这个口径（一份从未披露的旧年报的否定意见不算现行红旗），不必再推期次；② 它与 `score_daily.report_date`（报告期期末）**同名列不同义**，两者不可互推，拿一边去校另一边只会双双判定对方错了。`category` ∈ 年报/半年报/季报/业绩预告；`pdf_url` 巨潮官方直链；`detail_url` 公告页；`audit_firm`、`audit_opinion` **只从年报 PDF 解析**，覆盖率约 1/4 行——这直接决定了 `gate` 里有 26 只一个信号都判不了。库内最大的表（≈151 份/票，满量外推 ≈80 万行），只按 `sid` 单家查，不参与列表 JOIN。

**`dividend`** | PK `id` | UK `(sid, div_year, div_type)`  
`bonus_per_10`（每 10 股派息，元）、`transfer_per_10`（转增）、`announce/record/ex/pay_date` 四个日期。

### 10.6 股本事件 `share_action`（定增 / 回购）

一表两族，`kind` 取 `seo` / `buyback`，**自然主键 `(sid, kind, src_id)`**，回灌按主键 upsert；源是全市场权威快照，所以本轮快照里没再出现的 `(kind, src_id)` 会跟着删（源侧撤公告时不留孤儿）。仅 A 股。

| 列组 | 内容 |
|---|---|
| 通用 | `kind`、`src_id`（源侧记录号拼出的稳定键）、`notice_date`、`updated_at`、`detail` JSON（方案的其余原文字段：发行方式/锁定期/认购对象/回购目的原文…） |
| 定增 | `issue_date`、`listing_date`、`price`（发行价 元/股）、`num`（发行量 股）、`raise_funds`（募集资金 元） |
| 回购：方案列 | `plan_price_cap`、`plan_num_lower/plan_num_cap`、`plan_amount_lower/plan_amount_cap`（拟回购数量/金额的区间两界） |
| 回购：成交列 | `done_price`（成交均价）、`done_num`、`done_amount`（累计成交数量/金额），方案阶段整组为空 |
| 回购：状态列 | `progress_label`（东财进度文案）、`finished`（是否实施完成）、`cancel_type`（`注销/非注销/待核`）、`finish_date`（完成日） |

几个口径点：

- **成交列与方案列不是一回事，不能混**：`done_*` 只有真买过才有值，方案阶段为空；展示时价/量/金额**各自独立**优先取 `done_*`，缺项才回退 `plan_*`，所以同一行可能价取成交、量取方案（API 用三个 `*_actual` 布尔逐列标明取的是哪族）。
- **`cancel_type` 是从回购目的原文里判出来的三态**，不是源侧的开关字段（源的 68 列里没有这个标记）：判据是**逐句**的——含「未能/届时/三年内/使用完毕」等兜底从句的整句丢掉，同句里注销与别的去向并列判 `待核`。三态只是**公告写的用途**，不代表注销已办理。
- **`src_id` 是采集侧拼的稳定键**（定增取 `代码|发行日|发行量|发行价`，回购取源记录号），因为定增侧没有天然唯一键（源里存在全字段一致的重复行）。键里日期缺失时退到上市日 → `nodate`。
- 「最近一次」不在采集侧筛：一次抓取存全表，取哪一笔由查询侧的窗口函数决定（定增按发行日、回购按公告日；已完成那笔按完成日），所以日后改口径不用重抓网络。

农价断档会被计成失败但不拦回灌：单个品种序列末日距今超过 **21 天**即计入 stale，`fetch_prices.py` 退码 3、job 记 failed 且 message 带品种名单。阈值取 21 而不是 7 是因为生意社每周只更新 2~4 次，季节性停更本身就是信号。**旧价格仍照常入库**，页面显示「数据截至 …」，所以看到 agro 红一条先看品种名单而不是先查链路。EDB 侧同族退码是 **4**（合并异常 → 不写盘）。

### 10.9 量级与回灌行为

行数自查（`table_rows` 是估算值，看量级足够）：

```sql
SELECT table_name, table_rows FROM information_schema.tables
WHERE table_schema='db_va' ORDER BY table_rows DESC;
```

| 表 | 满量（按密度外推） | 增长 |
|---|---|---|
| `security` | ≈7000（A + 港股通 + 美股成分） | 周六 `deep` 增量 |
| `quote_daily` / `score_daily` | 7000 × 交易日数 | **各 ≈7000 行/交易日**（≈175 万行/年） |
| `fin_*` 四表 | ≈22 万（实测 31.8 期/票） | 只在周六随财报季变动 |
| `fin_note`（现金类附注） | ≈1.4 万行（实测 14090 行 / A 股 4933 家） | 只在 `deep` 有新年报/半年报披露时增长 |
| `periodic_report` / `dividend` | ≈80 万 / ≈8 万 | 周六增量 |
| `valuation_pctile` | ≈5300（过筛标的一行；美股与低分标的的旧行留着不再刷新） | 不增长，≈1.9 天一轮整行覆盖 |
| `wind_event` / `wind_holder` | 手工范围，百级 | 仅 `events` |

`quote_daily`/`score_daily` 是唯一会持续膨胀的两张表，多年后如需控量按 `trade_date` 分区或归档即可——业务查询都带最新日条件。

**回灌注意事项：**

- `import_legacy` **默认是「清空重灌」，只有 `--no-clean` 才安全**；`--only-fresh` 必须配 `--no-clean`（否则 argparse 直接报错退出）。`--only-scores` 只刷 `score_daily`，自带不清空。
- `fin_*` 五表 + `dividend` + `periodic_report` 按唯一键 upsert，所以数据源的修订值与后加字段能刷进库。超列宽的长文会被截到列宽、定点列越界值置 NULL（真值无损保存在 `extras` 里），崩溃批次退回逐行只丢装不下的行，计数在 `<表>.clipped` / `.out_of_range` / `.bad_rows`。
- **`valuation_pctile` 是覆盖式 upsert，唯独它不走 COALESCE**：采集侧给出的 NULL 是判定结果（亏损、序列停更、值域越界），保留旧值等于把已经判死的假分位放回列表。读的是 `data/valuation/latest.json` 而不是公司明细，所以 `--only-fresh` 那个 `companies/*.json` 的 mtime 增量窗与它无关——任何回灌路径都会带上它。
- **农价/EDB 两族例外**：即使 `--no-clean`，也会跟着源做删除（按主键差集清掉源里已不存在的行，计数在 `agro_price_stale_deleted` / `edb_value_stale_deleted`）。因为采集端会主动丢弃「本轮窗口内却没重新解析到」的日期，只 upsert 不删会永久背离。

```powershell
cd backend\collector
python -X utf8 scripts\_refresh_scores.py --dry-run    # 先看会改多少家，不写盘
python -X utf8 scripts\_refresh_scores.py              # 只替换 index.json 各家的 scores 块
cd <项目目录>\backend
python -X utf8 -m scripts.import_legacy --only-scores  # 只重写 score_daily（≈26 秒 / 6939 行）
```

`--only-scores` 自带「不清空」，也不会写 `security`/`quote_daily`/`fin_*`；这批分的评分日沿用 `index.json` 的 `updated_at`，所以刷完列表页的「快照日」与行情仍是同一天。重算时 V 那份市值取的就是 `index.json` 里现成的那笔批次行情（见 §2.3），因此这条路径不联网也能把这一列刷成与 `市值` 列一致。

三条写分路径（日更、周六深抓、上面的手动刷新）共用同一道**评分批次护栏**：`score_daily` 落库前会拿这一批和库里上一批比分布，命中下面任一条就**整批不写**——

- `fraud` / `trap` / `growth` / `value` 的「零值家数」或「NULL 家数」同时涨过 2 倍且多出 500 家；
- 这一批的行数少于上一批的 90%。

四列共用一把尺子是因为它们各自的异常方向不同：`fraud` 与 `trap` 越低越干净，明细被覆写成空时集体掉到 0；`growth` 与 `value` 方向相反（越高越好），同一起事故会让它们七项全算不出而整列变 `NULL`。所以零值与 NULL 两端都要盯。

要设这道卡，是因为上游抓取只要有一次抖动，就可能把几千家已经落好的明细覆写成空，重算出来的就是一大片假的 0 分——比算错分更坏，因为筛选会放过本该拦住的标的，而链路上每一步都写着 success。两个阈值都故意定得比日常抖动宽，正常批次不会撞上。

被扣住时的表现：行情与财务明细照常回灌，只有分数停在上一批那一天（列表页表头的快照日取行情与评分两张表最新日的交集，所以会看到它没跟上当日），`score_daily` 里查不到当日这一批；回灌输出里会先打一行 `⚠ 评分批次护栏触发…`，写明是「哪一列、从多少涨到多少」以及对比的是哪一批，`import_legacy` 随即非零退出，`etl_job_log` 里这次回灌记为 `failed`、message 开头就是那句原因。**看到这条记录不要直接重跑**——先去 `backend/collector/data/companies/` 抽查几家，确认财务明细还在（被清空的话护栏只是挡住了假分，不会把数据补回来）。

某一列刚上线、上一批整列还没有值时，该列本轮不参与比对，否则首批一定会被判成异常。

前端改动后 `cd frontend; npx vite build`，产物由 FastAPI 托管，重启服务生效。

`verify_filters` 的 FAIL 形态本身就是诊断信息：

| 形态 | 含义 | 处置 |
|---|---|---|
| `local` 明显大于 `api` | 库落后于源——深抓还在推进，或该回灌了 | `import_legacy --no-clean`（不带 `--only-fresh`）后复验 |
| `api` 大于 `local` | 库里有源已删除的行，或口径漂移 | 全量 clean 重灌（源即权威） |
| 个别字段值不等 | 该列在库里为空，多为增量窗口没覆盖到 | 同上，全量重灌 |

深抓进行中 `verify_filters` 大面积 FAIL **属预期**（源已几千只而库还是上一轮的子集），不要据此判定功能坏了。两条已验证的口径不要改回旧写法：行情/评分期望值以 `index.json` 为准（明细会比它旧）；任何验证逻辑都不要逐只读文件。

## 12. 已知边界

看页面时遇到下列情况都是正常的，不是坏了：

1. **没有历史行情**：`quote_daily` 自 2026-09-02 起才有数据，此前只有最新快照，所以 K 线、回撤、年化波动类功能暂无数据基础。缺的只有行情——财务报表有最近 10 年（见 §3）。
2. **分数改一次要等到下一次采集**：日更（周一~六 16:05、22:05）与周六深抓都会在链尾重算一遍评分，所以改了算法或补了明细，最迟第二天就能看到；只是四派分、造假分、管理分、成长综合分 G、价值综合分 V、12 个买卖参考价是财务的函数，只有周六那轮才会真的改变它们（见 §5）。例外有两处：**价值陷阱分 T** 的输入含定增史，跟着日更走；**价值综合分 V** 的便宜那 65 分吃市值，而那份市值取本批行情，所以 A 股那一列每个交易日都会挪零点几分（挪动幅度与跨页一致性见 §2.3）。港股、美股因为现价停在最后一次周六（见下面第 5 条），这两侧的 V 与行情一样不动。G 与其余分数只吃深抓那一刻的快照，新公告当晚不会让它们动，要等周六那轮带来新的一期年报。
3. **新上市标的要等周六**才进池。
4. **港股范围 = 港股通（≈621 只），美股范围 = 五大指数成分并集（≈765 只）**，都不是全市场。名单外的标的（含 TSM/ASML 这类在美上市的外国公司）需要手工 `--codes` 补。`--all-market` 只作用于 A 股。
5. **港美股现价停在最后一次周六**：日更快照走的腾讯接口字段位是 A 股专用。
6. **美股没有 PB、分红与定期报告**：数据源不提供，相关列显示 `-`。PB 缺失不影响评分（用财报每股净资产反推）。
7. **港股没有定期报告与审计意见**：详情页 ⑥ 审计口径缺失、⑫ 事件区空白。⑪ 价值陷阱分则是**写明不适用**（口径只覆盖 A 股），不是空白也不是「查过了没问题」。⑨ 价值综合分与 ⑩ 成长综合分两个市场都照常给分（七项只读年报科目，价值分还多吃一笔行情市值），只是美股的指标表没有「每股净资产」、分红表没有逐笔派现，那几项在美股恒判不动、分母不缩，所以美股这两列的上限分别是 82.2（V）与 85.3（G）。
8. **审计意见覆盖率 <100%**：部分东财 PDF 解析会静默失败，字段留空，不阻断抓取。
9. **金额不折汇率**：跨市场比数值会误读，只有角标提示。跨市场请用比率列。
10. **美股报告期只有年报口径**，统一归一到 12-31，单季字段留空 → 详情页季视图退化成报告期序列。金融/REIT 类美股的每股收益留空（口径不可比）。
11. **Wind 相关覆盖有限**：事件是一次性手动抓取，只覆盖少量标的，所以详情页 ⑫ 与列表页增强分大片 `-`。详情页 ⑨ 价值综合分与 ⑩ 成长综合分不吃 Wind 数据，不受这一条影响。自动使用 Wind 额度的任务有两个（`edb` 周更、`valuation` 每天 05:05），都受每日积分上限约束；估值分位只刷过筛的 5340 家（美股与管理分 < 30／造假分 > 50 的不刷），一轮 108 次调用、每天只放 56 次，要 ≈1.9 天铺完，所以某一列的 `-` 多半只是还没轮到或按口径不刷，不是取不到。
12. **跨零点收口的轮次会让「快照日期」比行情日期大一天**，不影响排序/筛选/评分（都取最新快照），下一次日间回灌自然归位。
13. **账面派两档卖价大片为 `-`**：现价在资产锚 2 倍之外时格进取、施洛斯不给卖出参考（该口径对成长中的公司本就不是估值方法），买点与清算列不受影响。想要「该卖」信号，请看收益派两档。
14. **经常性盈利只有 A 股有**：扣非净利润是 A 股披露科目，港股、美股没有，那侧的一次性收益靠「隐含 PE ≥ 3 倍」下限拦，粒度比 A 股粗。实测该门槛压缩 297 家、取消 3 家。
15. **券商、保险的投资浮盈抓不到**：公允价值变动损益按准则不计入非经常性损益，所以这类公司 TTM 盈利被市场涨跌撑高时，收益派两档卖价与买点会整体偏高（中国人寿、中国太平即属此类）。想排除请加行业筛选，别看参考价。
16. **港美股 EPS 与快照 PE 差 10 倍以内都算可信**：年报窗口口径的容忍度取 10 倍（收到 5 倍会连带砍掉 Merck、太古这类真实转折公司），所以个别小市值标的会出现买价明显高于现价，属锚偏松而非算法坏了。
17. **⑥ 里四项「5年变动」读的不是 5 年窗**：「净资产5年变动」「有息负债5年变动」「营收5年变动」「毛利率5年变动」的基期是**该公司财报序列里最早的那一份年报**——A 股现在是 10 年，美股长到 20~32 个年报。所以这几项跨市场并排读会误读。四派分里只有 ④ 施洛斯用它们：A 股历史从 8 年补到 10 年那一次实测，5553 家里 2069 家（37%）的施洛斯分跟着变，多数只在 1~3 分内（P90 3 分、P99 7 分、最大 15 分），另外三派与造假/管理分一分不动。拿旧截图对比分数时，差异多半就出在这里。
18. **`PB十年分位` 的口径不自主**：十年窗口怎么切、样本含不含上市初期的极端点（平安银行十年 PB 序列里含 108 倍那一段）、亏损期计不计入分位，全部由 Wind 侧决定，我们既看不到它的算法也无法复算。所以这一列**只用于展示与筛选，不进四派评分与买卖参考价**；跨市场横向比尤其要小心，三个市场的样本规则都在对面手里。需要的是「我们自己定义的低位」时，请用 §2.3 的清算/净现金两列。
19. **`gate` 只能回答「触发了哪几项」，不能回答「没触发就是干净的」**：四个信号里审计意见只从年报 PDF 解析（覆盖约 1/4 行，见 §10.4）、Wind 事件只覆盖手工抓过的少量标的（目前唯一命中是 601899 紫金矿业），两者都判不了的 26 只（未抓财务）干脆置 `NULL` 不装懂。另外它在回灌时序上跑在财务表之前，用的是**上一轮**库里的权益与审计意见——年报一年只变一次，滞后一轮不影响门槛判断，但指望它当场反映刚抓到的新年报就是错想（再跑一次 import 即可）。
20. **造假分低不等于干净**：回测（见 §3 与 `scripts/fraud_validity.py`）显示它对「次年转负」「大额减值」有判别力，但对「审计意见非标」几乎没有（r=+0.0069）。所以看一只票是否踩过雷，要看名称后有没有 `⚑`，不要只看 ⑥ 那一列的分数低。
21. **财报期龄会出负数**：美股有 7 家财年不在 12-31 收尾（Copart/Cisco/Intuit/Palo Alto/SanDisk/Seagate/Western Digital），采集层为了与 A 股同轴把期次归一到 12-31，于是它们的基准期跑到快照日之后（-3~-4 月）。这是**预存在的归一化口径**而不是新 bug，`report_age_max` 只卡上限所以不会误拦它们；真正受影响的是拿 `MAX(report_date)` 当「最新财报」的地方要记得美股这一期是推算值。同理，格防规模项的折算用的是**固定年均汇率**（`HK` 0.92 / `US` 7.15）而不是实时汇率，换汇率源之前它就是这个精度。
22. **定增/回购只有 A 股、且只认源侧有的记录**：这两列是东财数据中心的两张表（定增 5,468 笔、回购 5,410 笔），港股、美股整列 `-`；定增口径**只认非公开发行**，公开增发与配股不算——所以某家最近一次增发若是公开增发（如 601899 紫金矿业 2019 年那笔 80 亿），这一列显示的是它更早的一次定增，不是漏抓。回购的 `注销/非注销/待核` 是按公告里股份用途那句话分的三态，**不代表注销已办理**，回购完成也不等于注销完成。源侧撤掉公告时库里那笔会跟着删（整表重取、按主键对齐）；采集侧还有一道行数守卫，整表掉到上一轮 70% 以下就拒绝覆盖，避免半张表让「最近一次」悄悄回退成旧一笔。
23. **上游报表接口整体挂一次，采集轮就会把已经抓好的明细覆写成空**：`fetch_data.py` 每个数据块都是 `except → result[key] = []`，然后整档盖回 `companies/<代码>.json`，所以一次限流就能抹掉该块的全部历史。2026-09-12 那轮实测：新浪三大报表接口整批返回空 body（`errors: "balance: Expecting value: line 1 column 1"`），4832 家（A 股 4831 家，占 A 股 87%）的 `balance/income/cashflow` 被清空，`indicators` 走同花顺所以一家没掉；同轮 `fetch_info` 失败还把 7 家（300542/300543/300545/300546/300547/300548/300549）的 `industry` 在 `index.json` 里置空——`verify_filters` 那 7 处 `industry` FAIL 就是它的余波（库里这 7 家的行业由 upsert 的 `COALESCE` 保留了旧值，所以列表页的行业归属与筛选一直照常生效，红的只是拿源文件重建的本地副本）。**后果不在库里而在分上**：回灌是 upsert，`fin_*` 历史一行没少（被清空的公司多数仍有 40~49 行），但接着的重算失去三大表输入，`fraud` 为 0 的家数从 647 涨到 2956（2288 家从正分掉到 0、95 家转 `NULL`）。所以在明细补回来之前，**列表页那一大片 0 分不是「变干净了」**，`verify_import` 第 5 项与 `verify_api` 的明细行数对比也会直接报停（答案是空列表）。库里历史完好且该接口现在能通（单拉 600309 资产负债表 106 行 OK），但**不是重跑一轮就能补回来**：那一轮 5553 家 A 股里只有 529 家的三大表拿到了数（457 家 ≥30 期 + 72 家 1~29 期），即成功率 9.5%，而且失败点散布在所有代码段（000 段 76/412、002 段 86/919、300 段 169/936、688 段 18/615……）——是逐请求随机限流，不是跑到某处才挂。所以直接重跑只是拿剩下的 90% 再赌一次，赌输的就是再洗一遍已存明细。这道护栏现已落地：财务表整张抓失败时沿用上一轮的成功行（`keep_last_good`），不再把整档盖成空，配套的一次性恢复脚本也把这轮洗掉的明细补了回来——现在 6,939 家的 `balance/income/cashflow` 一家不缺，`fraud=0` 的家数回到 647。这种被洗出来的假 0 分在写库前还有**评分批次护栏**整批扣住（见 §10、下面第 24 条），列表页不会再看到一片假 0。
24. **列表页的分数可能停在上一批**：评分写库前有一道批次护栏，分布异常时整批不写（口径与处置见 §10）。那种日子里行情列是当天的、分数列是上一批的，表头的快照日也跟着停在上一批那一天——这是护栏在拦假分，不是采集断了。

## 13. 二次开发约定

- **加字段**：先考虑 `extras` / `wind_overlay` 这类 JSON 列能不能装；必须建实体列时，同步改 `app/models/entities.py` → **`python -m scripts.create_tables`**（不可手改 `docs/schema.sql`，它是这个脚本从 `entities.py` 导出的存档）→ `import_legacy` 的列名单（多数表由 `KEYS` 元组控，`score_daily` 那类没传名单的直接从模型推）→ `verify_*`。
- **改完 `entities.py` 必需跑 `create_tables`，光跑回灌不够**：`metadata.create_all` 只对**缺失的表**生效，已存在的表新增列它静默无动作，于是新字段抓得到、算得出、就是进不了库（列表页整列 `-`，回灌报 1054 Unknown column）。补结构是 `create_tables.sync_schema` 的活：它只**做加法**（缺列 `ADD COLUMN`、缺索引 `CREATE INDEX`），不改类型、不删列、不碰主键与唯一约束——那些得先评估数据怎么搬，不该被一个脚本悄悄做掉（改类型请走删表重建 + 全量回灌）。新增列记得同一次把 `(trade_date, col)` 索引加在 `entities.py` 的 `__table_args__` 里，否则 `schema.sql` 与真库会一边有一边没有。
- **`extras` 不要做白名单裁剪**：详情页的财务表是用 `Object.keys(row)` 反黑名单渲染的，`extras` 里每个中文科目名都是一张看得见的列——砍字段等于直接删表。
- **加筛选列**：`score_daily`/`quote_daily` 上新的排序/过滤列，列表页要用就**必须补 `(trade_date, col)` 索引**，并在满量规模下 EXPLAIN 一遍。例外是 `valuation_pctile`：它每个标的一行、没有 `trade_date` 轴，索引只建 `(pb_pctile)` 单列，照抄复合索引反而用不上。
- **不改前端为「逐只取数」**：列表字段全在 `SecurityItem` 里，新增列请扩 `SecurityItem` 而不是让前端二次请求。
- **详情页渲染在 `frontend/src/lib/stockLegacy.js`**（靠 DOM id 对接），改结构比改 Vue 危险，动手前先确认 `renderDetail` / `show()` 的契约。
- **`stockLegacy.js` 会被 Node 整体 import 做评分双实现比对**，禁止引入任何顶层浏览器 API（`ResizeObserver`、`navigator.*`、`document.documentElement`、顶层 `echarts` 调用），也不得 `import 'vue'`——否则 parity 直接崩。需要视口判断就在函数体内读 `mqMobile.matches`。
- **移动端断点是 600px，四处同步**：`lib/useMediaQuery.js` 的 `MOBILE_QUERY`、`stockLegacy.js` 的 `mqMobile`、`assets/stock.css` / `assets/agro.css` / `style.css` 的 `@media`。漏一处就会出现 CSS与 JS 判断不一致。
- **抓取脚本别用 `print` 打进度**：`--quiet` 语义要保留，长任务统一用 `tqdm` + `flush_every`。
- **提交前**：§11 的验证全绿，且不带进 `companies/`、`index.json`、`.env`、`run/`。
