# 价值分析系统 · 使用说明书

> 覆盖范围：全 A 股（沪深京 ≈ 5553 只）+ 港股通标的（≈ 621 只）+ 美股五大指数成分（≈ 765 只）  
> 形态：单机 Windows 服务，一个进程同时提供 API 与网页；MySQL 8 + Python 3.10 + Node 20

本文分两层。**第 1~5 节给看数据的人**：怎么打开、三个页面怎么用、数据什么时候更新。
**第 6 节之后给接手运维的人**：架构、部署、启停、采集、数据口径、故障处置。

## 1. 怎么打开

### 1.1 本机

```
http://127.0.0.1:8000/
```

### 1.2 手机与其他外网设备

```
https://<设备名>.<tailnet>.ts.net/
```

两个必须注意的点：

- **一定要带 `https://`**。这个地址的 80 端口由本机 IIS 应答，输入成 `http://` 会看到一个 IIS 默认页，与本系统无关。建议在手机浏览器里直接收藏完整地址。
- **设备要先加入同一个 Tailscale 网络**（tailnet `<tailnet>`）。没入网的设备解析不了 `*.ts.net`。

后端只监听 `127.0.0.1:8000`，不对外网卡开放，所以 `ts.net` 这个地址是远程访问的唯一入口。这层转发由 Tailscale Serve 承担，配置可以用一条命令核对：

```powershell
& "C:\Program Files\Tailscale\tailscale.exe" serve status
# 期望输出：https://<设备名>.<tailnet>.ts.net (tailnet only) └─ / proxy http://127.0.0.1:8000
```

### 1.3 手机端界面

视口宽度 ≤ 600px 时自动切换为移动版，不需要任何设置：

- 列表页从 20 列宽表改为**一屏一家的卡片**，指标与买卖参考价分块展示
- 筛选栏与排序栏收成两个折叠按钮，按需展开
- 顶栏不再吸顶，只保留详情页的模块导航吸顶
- 图表高度与坐标轴留白按窄屏收紧，导航条与行业切换条可横向滑动

转屏或缩放窗口后图表会自适应重绘。桌面版布局不受影响。

### 1.4 三个页面

| 地址 | 内容 |
|---|---|
| `/#/` | 全市场列表：筛选、排序、买卖点命中 |

## 2. 列表页 `/#/`

全市场近 7000 只，逐页翻不现实，所以操作路径设计成**先缩范围、再排序**。

### 2.1 缩范围

| 控件 | 说明 |
|---|---|
| 市场 tab | 全部 / A股 / 港股 / 美股（切换时清空板块） |
| 板块 tab | 沪主(60) / 深主(00) / 创业(30) / 科创(68) / 北交(92,83,87,43)，按代码前缀判定 |
| 行业下拉 | 选项跟着市场走：A 股国标行业、港股恒生行业、美股东财中文行业 |
| 关键字 | 代码或名称模糊匹配 |
| 剔除 ST | 名称含 `ST`/`*ST` 的标的是低 PB 假便宜重灾区，默认建议勾上 |
| 市值区间 | 单位**亿**，与列头 `市值(亿)` 同口径 |
| 分数门槛 | 造假 ≤ / 管理 ≥，留空为不限 |
| 买点 | 四派多选 + 折扣 %：现价 ≤ 买参考价 × 折扣即命中 |
| 卖点 | 四派多选：须同时达到保守价与公允价才算命中 |
| 事件增强分 | 见 §2.4 |

### 2.2 排序

点表头即可，支持 `PE / PB / 市值 / 四派分 / 造假 / 管理 / 周期 / 清算 / 净现金`。

四派参考列的读法：

- **列头按买入性价比排序**：比的不是买价的数字大小，而是现价相对该派买入参考价的**折价深度**（`1 − 现价 / 买价`）。5 元的票并不比 50 元的便宜，折成比例后跨标的才可比。
- 降序（点一次表头的默认方向）第一屏＝相对建议买价打得最深；再点切升序，最前变成现价已远高于买价的那批。
- 当前用于排序的那一列，每格会多出一个 `折NN%` / `溢NN%` 小标签（悬停看精确值），另外三列不显示，所以不额外占表宽。
- 格内三行是 买入价 / 保守卖出价 / 公允卖出价；后两档的小字可各自点击，按卖价绝对值排序。
- 现价或买价缺失、买价低到不可成交的行不参与排名（沉底），不会把整屏顶成 `-`。

分页每页 50/100/200（默认 50），支持跳页。

### 2.3 列含义

`代码/名称｜行业｜现价｜涨跌｜PE(TTM)｜PB｜市值(亿)｜格进取｜格防御｜施洛斯｜巴菲特｜造假｜管理｜周期｜清算｜净现金/市值｜格进取 买/保/公｜格防御 买/保/公｜施洛斯 买/保/公｜巴菲特 买/保/公`

后四列是竖排三行。数值颜色：**绿色 = 现价已进入该派的买入区**，**红色 = 现价已达到卖出区**。

两点口径值得记住：

- **市值是本币计价，不折汇率**（A 股人民币、港股港元、美股美元，非 A 股带 `HKD`/`USD` 角标）。所以「全部」tab 下跨市场比市值没有意义，要比体量请切到对应市场分开筛；跨市场比较请用 `PE`/`PB`/评分这类比率列。
- **表头日期是列表快照日**，取行情与评分两张表各自最新日的交集，两者新鲜度不一致时以较早者为准——不会出现「用今天的价配昨天的分」。

### 2.4 事件增强分

筛选栏最左的切换档（只在「全部 / A股」出现），把 `造假` / `管理` 两列从**基础财报分**切换为**基础分 + Wind 事件增量**，结果钉在 0~100。选择记在浏览器本地，下次进来还在。

- 切换后这两列的排序与门槛筛选同步跟随，不会「按增强分排、按基础分筛」
- 没有事件条目的公司两列显示 `-`，且会被门槛筛选自动排除
- Wind 事件目前是**手动抓取、只覆盖少量标的**，按市值排序时整屏 `-` 属正常。想看增强分，请按「造假」列降序或直接搜代码

### 2.5 布局说明

桌面版 20 列在 ≥ 1240 CSS px 的视口下不需要横向滚动；装不下时（高分屏高缩放比）首列会吸在左边，表头随滚动保持可读。

## 3. 详情页 `/#/stock/<代码>`

九个模块，数据来自 `/api/securities/{code}`：

| | 模块 | 看什么 |
|---|---|---|
| ① | 基础财务信息 | 主数据、最新行情、快照日 |
| ② | 通用价值标准 | 跨流派共用的估值锚 |
| ③ | 格雷厄姆烟蒂标准评判 | 分项打分明细 |
| ④ | 施洛斯烟蒂标准评判 | 分项打分明细 |
| ⑤ | 巴菲特芒格价值标准评判 | 分项打分明细 |
| ⑥ | 财报造假可能性分析 | 0~100，**越低越好** |
| ⑦ | 管理层管理水平评分 | 0~100，越高越好 |
| ⑧ | 周期位置 · 周期性行业判定 | 周期股才有内容，非周期股该模块为空 |
| ⑨ | 公司事件与股东结构 | 增减持/并购/违规/诉讼/ST、股东名册、解禁 |

几点读法：

- 每个模块的分项都带「当前值 / 标准 / 得分」三列，可以直接看出分数是怎么凑出来的；⑥⑦ 的评分依据是量化红旗信号，**不构成对造假的认定**，需结合审计意见、监管问询等定性信息判断。
- ⑥⑦ 脚注里的 Wind 优化项与 ⑨ 整块，读的是 Wind 事件覆盖层。**没抓过 Wind 事件的标的，⑥⑦ 只有量化分、⑨ 空白，属正常**。
- 三大报表切换 tab + 报告期下拉，可以逐季看。
- 港股/美股的财年被归一化标到 12-31 以便与 A 股同轴对齐，那不是公司自己的财年末；详情页脚注会显示「本公司财年截至 …」。
- 港美股没有定期报告与审计意见（数据源不提供），所以 ⑥ 的审计口径缺失、⑨ 事件区空白。
- 美股快照没有市净率与分红数据，相关列显示 `-`；市净率缺失不影响评分，评分会用财报每股净资产反推。

## 4. 农价页 `/#/agro`

两条独立的产品线，与股票链路互不影响：

- **农化价格**：6 个化工/农药品种（草甘膦、敌草隆、多菌灵、甲基硫菌灵、邻苯二胺、对硝基氯化苯），来自生意社，每天自动抓两次。
- **行业量价（EDB）**：汽车/铝/航运/轮胎/地产/煤炭/钢铁 7 个分类共 44 个指标，来自 Wind EDB，每周日自动更新一次。

看到「数据截至 …」表示该品种已有一段时间没发布新价格。生意社每周只更新 2~4 次，隔几天是正常的；超过三周会被记为断档并在采集日志里标红，**但旧价格照常入库展示，不影响页面使用**。

Wind 客户端未登录时，行业量价那一轮会失败且不改动任何已有数据——页面继续显示上一次成功抓取的历史序列。

## 5. 数据什么时候更新

理解这一节就能解释绝大部分「为什么这个数字看着是旧的」。

**节奏分两层，因为财务按季披露，没必要每天重抓 1.9GB 明细：**

| 层 | 频率 | 更新什么 |
|---|---|---|
| 行情 | 周一~周六 16:05、22:05 | 现价、涨跌、PE、PB、市值 |
| 财务 | 周六 09:05 | 四表、指标、分红、报告、审计意见、**全部评分与买卖参考价** |
| 农价 | 每天 09:05、21:05 | 6 个品种价格 |
| 行业量价 | 周日 20:00 | 44 个 EDB 指标 |

**关键推论：**四派评分、造假分、管理分、12 个买卖参考价是**财务的函数**，只在周六重算。所以「今天是否触发买点」= 今天的现价去比上周算出的参考价，这是有意设计——内在价值不随日内价格波动。

同理，新上市的标的要等到周六那轮才进池；日更只给已在池标的刷行情，不拉新名单。

运维层面还有两条影响体感的规则：

- 深抓（周六那轮）期间到点的行情 job 会**静默跳过**，这是互斥设计不是故障——深抓本身每只都带当日行情。
- 想临时补一轮，用 `.\ops\collect.ps1`（见 §7.2），不必先停调度器。

## 6. 系统怎么运转

### 6.1 数据流

```
外部数据源                采集层（collector）              服务层（app）              界面
─────────────           ────────────────────           ──────────────            ──────
腾讯 qt.gtimg.cn  ─┐    scripts/fetch_data.py
东财 datacenter   ─┤ 抓取 scripts/scoring.py      回灌  FastAPI :8000           Vue3 SPA
巨潮 cninfo       ─┘      scripts/universe.py  ──────→  /api/*        ──────→  （hash 路由）
本地 Wind CLI     ──→  data/companies/*.json           /  托管 frontend/dist
                       data/index.json            ──→  MySQL db_va (16 表)          ↓
生意社 / Wind EDB ──→  agro-price/scripts/*  ────→  /api/agro  ─────────────→  /#/agro
```

三条要遵守的约定：

1. **采集层产出静态 JSON，MySQL 是它的投影。** `collector/data/` 是真源，`import_legacy.py` 单向灌库——直接改库里的数据，下一次回灌会被覆盖掉。
2. **`index.json` 是全市场入口，不是明细。** 7000 只明细约 1.9GB，任何新代码都不要逐只读文件，只读 `index.json`（≈ 5.5MB）。
3. **数据库是查询层。** 列表的筛选、排序、分页全部由 SQL 完成（`score_daily` + `quote_daily`），这些表上的索引就是性能预算。

GitHub Pages 上的纯静态旧版仍在博客仓库保留，作为回退；以本仓库与 `db_va` 为准。

### 6.2 目录

## 7. 部署与运维

### 7.1 首次部署

前提：Windows + Python 3.10（代码用了 `X | None` 写法）+ Node 20 + MySQL 8 已在 3306 运行。

```powershell
# 1) 建库
mysql -u root -e "CREATE DATABASE IF NOT EXISTS db_va DEFAULT CHARSET utf8mb4;"

# 2) 装依赖
cd <项目目录>\backend
pip install -r requirements.txt -r collector\requirements.txt

# 3) 配环境
Copy-Item .env.example .env    # 编辑 DATABASE_URL / LEGACY_DATA_DIR / BOND_10Y

# 4) 建表（按 ORM 元数据 create_all，等价 docs/schema.sql）
python -X utf8 -m scripts.create_tables

# 5) 首轮全市场深抓（≈5 小时，可中断续跑）
python -X utf8 -m collector.run deep

# 6) 全量回灌 MySQL
python -X utf8 -m scripts.import_legacy --no-clean

# 7) 构建前端并启动服务 + 调度器
cd ..\frontend; npm install; npm run build; cd ..
.\ops\start.ps1 -Rebuild
```

打开 <http://127.0.0.1:8000/>。第 5/6 步只在首次或换机器时需要，之后交给调度器。

**`.env` 四个键**

| 键 | 例值 | 说明 |
|---|---|---|
| `DATABASE_URL` | `mysql+pymysql://root@localhost:3306/db_va?charset=utf8mb4` | 无密码时不要写 `@` 之外的空字段 |
| `LEGACY_DATA_DIR` | `<项目目录>\backend\collector` | 采集产出根目录，本仓库自给自足，不依赖博客仓库 |
| `BOND_10Y` | `0.017` | 十年期国债收益率，用于 EPV/DCF 折现 |
| `WIND_SKILL_DIR` | `<wind-mcp-skill 目录>` | 只有 `edb` / `events` 两个 Wind 任务用，指向本机 wind-mcp-skill 目录；不配不影响其他 job |

### 7.2 五个运维脚本

双击 `ops\start.bat` / `ops\stop.bat` 也可以，或命令行：

| 命令 | 作用 |
|---|---|
| `.\ops\start.ps1` | 起 FastAPI + 调度器（已在跑则逐个跳过，可重复执行）。`-Rebuild` 先构建前端，`-NoScheduler` 只起服务，`-Lan` 监听 `0.0.0.0` |
| `.\ops\stop.ps1` | 关服务 + 调度器 + 采集子进程。`-Api` / `-Scheduler` 单关；**有采集任务在跑时只用 `-KeepJobs`**（见 §7.4） |
| `.\ops\status.ps1` | 一屏看：MySQL、服务 PID、健康检查、前端产物、采集进程、抓取锁、`index.json` 条数/时间/体积。`-Jobs` 附带最近运行记录 |
| `.\ops\guard.ps1` | 幂等拉起（崩溃自愈）。稳态只查进程表，亚秒返回；`run/.paused` 存在时静默让路 |
| `.\ops\collect.ps1` | 手动补跑采集 job，跑的是调度器同款命令（自动回灌 + 写 `etl_job_log`），不用先停调度器。默认 `daily` = `stock → agro`；`-List` 看 job 表与时刻；`-Background` 让长任务转后台 |

判活按**命令行特征**匹配进程而不是 PID 文件，换机器不会状态错乱。日志落在 `run/*.log`，环境变量 `VA_PORT` / `VA_PYTHON` 可覆盖端口与解释器路径。

`run/.paused` 由 `stop.ps1` 写、`start.ps1` 删。没有它的话手动停机会在 10 分钟内被守护拉起来。

### 7.3 崩溃自拉起

靠 Windows 计划任务每 10 分钟跑一次 `guard.ps1`。本机已注册；**换机器要重跑一次**：

```powershell
schtasks /Create /TN "va-guard" /SC MINUTE /MO 10 /F `
  /TR "powershell -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File <项目目录>\ops\guard.ps1"
# 验证：schtasks /Run /TN va-guard，然后看 run/guard.log 新增一行「服务在线,无动作」
```

三条约束：

- **同一台机器上只保留一个守护任务**。多个任务跑同一个 `guard.ps1` 功能上不出错，但会重复判活并放大误判。
- **部分杀软会把 `guard.ps1` 判为恶意脚本**（隐藏窗口 + `-ExecutionPolicy Bypass` 派生子进程是典型特征），严重时文件被截成 0 字节。若遇到，把 `ops/` 加入排除项后重新保存文件再注册。
- 在受限/沙箱环境里 `Get-CimInstance Win32_Process` 查不到 python 进程，guard 会误判缺失并白拉一次 `start.ps1`（幂等，不会弄坏在线服务）。判活以计划任务自己写出的 `run/guard.log` 为准。

### 7.4 症状 → 处置

| 症状 | 原因 | 处置 |
|---|---|---|
| `[lock] 已有抓取在跑…` + 退出码 2 | 正常互斥 | 不用管。`status.ps1` 显示持锁 PID **已死**时 `Remove-Item backend\collector\data\.fetch.lock` |
| 抓取落盘变慢或停止 | 三种成因外观相同（文件不涨 + CPU 低）：工人在等活（`--chunk` 静态切块导致尾部堆积）、真挂在数据源读上、只是慢（主板 `601xxx` 年报 PDF 单份 30MB+）。注意本任务 I/O 密集，CPU 低不能证明挂死 | 用 `py-spy dump --pid <工人PID>` 看栈顶定性：停在 `queue.get` = 等活，把 `--chunk` 降到 60~100 重跑；停在 `ssl.read` = 真挂起 |
| 父进程没了但 CPU 仍在烧 | 孤儿 spawn 工人 | `.\ops\stop.ps1`（已匹配 `multiprocessing\.spawn\|fetch_data\.py`） |
| 服务起不来，`run/api.err.log` 有连接错误 | MySQL 没起 / `.env` 密码错 | 启 MySQL；`Test-NetConnection 127.0.0.1 -Port 3306` |
| 页面空白但 API 正常 | `frontend/dist` 不存在或过旧（启动时才探测） | `.\ops\start.ps1 -Rebuild` 后重启服务 |
| 手机打开是 IIS 默认页 | 用了 `http://` 或没入 tailnet | 换成完整的 `https://…ts.net/`，见 §1.2 |
| 列表筛「创业/科创」数量为 0 | 深抓按代码升序推进，该段还没抓到 | 等 `deep` 跑完，或 `fetch_data --codes …` 定向补 |
| 财务数据看着没更新 | 按季披露，日更本来不碰 | 看 `deep` 最近一次 `etl_job_log` |
| 页面上某个数字永远是旧值 | 尚未回灌，或需要一次全量重灌才能刷进修订值 | `python -X utf8 -m collector.run import` |
| `etl_job_log` 里一条 `running` 永不结束 | 跑 job 期间用了不带 `-KeepJobs` 的 `stop.ps1`，采集子进程被连带杀掉，没机会写终态 | 幂等重跑那轮；按 `scripts/job_status` 提示补一条终态 |
| 想立刻补抓失败股票 | `data/crawl_failed.json` 有清单 | `fetch_data --codes <粘贴> --audit-scope annual` 再 `import_legacy --no-clean` |
| 推送 GitHub 失败 | 本机需走代理 | `git -c http.proxy=http://127.0.0.1:1080 push origin main`（临时指定，不改全局配置） |

### 7.5 日志与现场

`run/api.{out,err}.log`、`run/scheduler.{out,err}.log`、`run/guard.log`、`backend/collector/data/crawl_all.log`（tqdm 进度写 stderr 且用 `\r`，抓摘要看 `grep '^\['`）。

服务每次启动前会把上一轮的输出流改名成 `run/<流名>.<yyyyMMdd-HHmmss>.log`，每条流只保留最近 10 份，空日志不留副本。这样「错过触发」这类问题还能回查现场。

两个容易误判的点：

- **`api.out.log` 是 0 字节不代表服务没在跑**——Python 的 stdout 被重定向后是块缓冲，要攒满才落盘。确认真实状态请用 `status.ps1` 而不是看日志尾部。
- **抓取进度看这三样**：`collector/data/index.json` 的 mtime、`.fetch.lock` 的内容（持锁 PID）、日志尾部。SQL 只能看到**已回灌**的部分。

判断本轮是「慢」还是「停」要拿增量而不是总文件数（总数会把上一轮的成品算进来）：

```powershell
cd backend\collector; $t = Get-Date '2026-09-05 20:00'   # 换成本轮启动时刻
(Get-ChildItem data\companies\*.json | Where-Object { $_.LastWriteTime -gt $t }).Count
Start-Sleep 90
(Get-ChildItem data\companies\*.json | Where-Object { $_.LastWriteTime -gt (Get-Date).AddMinutes(-2) }).Count
# 近 2 分钟落盘数应为个位数以上
```

需要手工重启抓取时，**只杀抓取进程组**（裸 `stop.ps1` 会连带关掉 API 与调度器），且**只杀父进程会留下若干孤儿工人**：

```powershell
$lock = 'backend\collector\data\.fetch.lock'
$pp   = Get-Content $lock                                   # 持锁父 PID
$kids = Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
        Where-Object { $_.ParentProcessId -eq [int]$pp }
Stop-Process -Id (@([int]$pp) + @($kids.ProcessId)) -Force
Remove-Item $lock
# CIM 被权限拒绝时：先杀父，再按 StartTime 同一秒筛选补杀工人
```

长任务要**后台启动**，前台进程会随会话结束被连带杀掉。

进度体检 SQL：[`backend/scripts/progress.sql`](../backend/scripts/progress.sql)（8 条只读查询，覆盖回灌完成率、各表覆盖只数与缺口、最近写库距今、报告期覆盖、运行记录、MySQL processlist、全库体量）。

## 8. 采集任务

统一入口 `python -m collector.run <job>`（在 `backend/` 下执行），每个 job 的产出都写 `etl_job_log`。

### 8.1 任务一览

| job | 内容 | 参数 | 耗时 |
|---|---|---|---|
| `stock` | 全市场行情快照 + 增量回灌 | `fetch_data --all-market --snapshot-only --quiet` → `import_legacy --only-fresh 26 --no-clean` | ≈1~2 分钟 |
| `deep` | 全市场财务四表/指标、分红、定期报告、审计意见（只解析年报）、评分重算、新标的进池 | `fetch_data --all-market --hk-connect --us-indexes --workers 4 --resume --max-age 6 --chunk 400 --flush-every 200 --audit-scope annual --quiet` | ≈6 小时 |
| `agro` | 生意社 6 个产品价格 + 回灌（不碰 Wind） | `agro-price/scripts/fetch_prices.py` → `import_legacy` | 分钟级 |
| `edb` | 44 个行业量价指标（Wind EDB） | `agro-price/scripts/fetch_edb.py`（默认增量窗口，`--dry-run` 零成本看本轮计划）→ `import_legacy` | 单次 7 次 Wind 调用 |
| `events` | Wind 结构化事件 + 股东结构，重算 `wind_*` 覆盖层 | `fetch_events.py [--codes …\|--force\|--recompute\|--limit N]` | 手动，不进调度 |
| `import` | 只回灌，不抓取 | `import_legacy --no-clean` | 秒~分钟 |

只有 `edb` 自动依赖 Wind 客户端（要本机客户端登录，按量耗积分），所以它单独排周日 20:00；`events` 覆盖 A 股事件与股东、一次要跑几千只，按量计费不适合无人值守，保持手动。两者失败都只记日志，不会污染已有数据。

`deep` 的两个关键参数：`--resume` 跳过 `mtime` 在 `--max-age`（6 天）内的明细，中断后重跑同一命令即可从断点续抓；`--audit-scope annual` 把最贵的年报 PDF 解析只用在年报上，约省 40% 时间。

### 8.2 抓取互斥锁

`fetch_data.py` 启动时抢 `data/.fetch.lock`（内容 = 父进程 PID）：

- 锁存在、持锁 PID 存活、锁文件 45 分钟内被刷过 → 打印 `[lock] 已有抓取在跑`，退出码 2
- 抓取过程中会 `touch` 锁文件作心跳，只有真卡死才会被 45 分钟超时接管
- `run.py` 侧同口径判活，把「锁被占」记成 `etl_job_log` 里的 `skipped` 而不是失败

### 8.3 `fetch_data.py` 参数

| 参数 | 含义 |
|---|---|
| `--all-market` | 名单取 `universe.py`（交易所 + 新浪交叉校验 ≈5553 只） |
| `--hk-connect` | 只跑港股通标的（≈621 只）；可与 `--all-market` 同给合为一轮 |
| `--us-indexes` | 只跑美股五大指数成分并集（≈765 只）；可与上两项同给 |
| `--codes 600011,HK.00700` | 只抓指定代码（补抓失败清单走这个）；带 `HK.`/`US.` 前缀可跨市场混写，不带前缀时市场由 `--codes-market` 决定（默认 `A`） |
| `--workers 4` | spawn 进程池并发（必须 spawn，不能用 fork） |
| `--chunk 400` | 每个池任务处理的股票数，也是崩溃隔离粒度。**静态切块**，尾部容易堆积，卡住时优先降到 60~100 |
| `--flush-every 200` | 每 200 只落一次 `index.json` |
| `--resume` / `--max-age N` | 跳过 N 天内已抓过的（默认 1 天） |
| `--snapshot-only` | 只刷 `index.json` 里的行情，不重写明细 → 明细 `mtime` 不变，`--resume` 判据仍是「财务新鲜度」 |
| `--audit-scope full\|annual\|none` | 审计意见 PDF 解析范围 |
| `--shard i/N` | 分片并行，如 `2/4` 只抓第 2 片 |
| `--limit N` | **调试专用**：会把 `index.json` 重建成部分公司，勿在生产工作目录使用 |
| `--quiet` | 只打摘要 |

### 8.4 `fetch_edb.py` 参数

| 参数 | 含义 |
|---|---|
| `--only alu` | 只抓某一类（7 个分类 id：`auto/alu/shipping/tire/realestate/coal/steel`） |
| `--begin` / `--end` | 显式窗口，人工回填历史就靠它（给 `--begin` 即绕过增量窗口与封顶） |
| `--buffer-days 45` | 含累计差分/月均口径的分类往前多拉的天数，只用于算窗口首点，不写进产物 |
| `--max-span-days 120` | 增量模式下单次往前多拉的上限，某条序列断更半年也不会自动引出一次大抓取 |
| `--dry-run` | 只打本轮计划（几次调用 / 几个指标 / 多少天窗口），一次 Wind 也不调、不写盘 |

Wind 不回报积分余额，所以可审计的量只有两个：**调用次数**（一个分类一次批量传码，全量 7 次）与**时间窗口**（增量模式下各分类合计约 265 天）。控成本先从 `--dry-run` 看这两个量，降频或减分类都比重跑历史便宜。

**EDB 历史点删了补不回来**，所以写盘前有两道防线，任一命中就退出且不覆盖旧文件：与旧 `edb.json` 合并出现任何异常（包括旧文件存在但读不动）；合并结果点集比旧文件小。本轮 Wind 空返回**不算失败**，退 0 且旧序列原样保留——只有「会把历史洗掉」才拦。分类的 `range` 一律按真实点位回写，不按本轮抓取窗口，下游拿它做删除防线。

统计局口径的「年初至今」累计值不能当全期累加算差分。修正存量用 `python -X utf8 scripts/fix_edb_cumulative.py`，它带 2~3 倍量级比阈值会自动拒绝年末交付潮这类误判，建议先 dry-run。

| 文件 | 内容 | 谁写 | 谁读 |
|---|---|---|---|
| `data/companies/<code>.json` | 单家全量（快照 + 四表 + 分红 + 报告 + 评分 + 审计），≈350 KB | `fetch_data` | `import_legacy`（按 `mtime` 增量）、详情页兜底 |

## 10. 数据库口径（`db_va`，16 张表）

通用约定：

- **`security.sid` 是唯一内键**，所有子表用 `sid` 外联，不用 `(code, market)` 复合键。
- **金额一律为元、比率一律为小数**（`0.35` = 35%），与 JSON 服务口径一致。
- **中文长尾科目进 `extras` JSON**，只有核心评分/展示科目才建实体列。
- **主键即幂等**：除三张标注「无自然唯一键」的表外，回灌都是 `INSERT … ON DUPLICATE KEY UPDATE`。
- DDL 存档在 [`docs/schema.sql`](schema.sql)，与 `app/models/entities.py` 同构。

### 10.1 主数据与行情

**`security`** — 证券主表 | PK `sid` | UK `(code, market)`  
`code/market`（`A/HK/US`）、`name`（ST 前缀原样保留）、`industry`、`exchange`、`currency`、`status`、`list_date`、`updated_at`。退市股不会被自动删除——名单源只含在市标的，需要人工清理。

**`quote_daily`** — 每日行情快照 | PK `(sid, trade_date)`  
`price, change_pct, pe_ttm, pb, market_cap, float_market_cap, turnover_rate, fetched_at`。八个字段全部来自腾讯批量行情，PE 为 TTM 口径，市值为本币元。**每票每交易日一行**，是「历史」唯一的积累处，本表自 2026-09-02 起才有数据。

### 10.2 财务明细（PK `(sid, report_date)`）

| 表 | 内容 | 关键列 |
|---|---|---|
| `fin_indicator` | 同花顺口径摘要指标，**评分主要输入** | `revenue, net_profit, eps, bps, gross_margin, net_margin, roe, current_ratio, quick_ratio, debt_ratio, ocf_per_share, revenue_q, net_profit_q, extras` |
| `fin_income` | 利润表 | `revenue_total, operating_profit, net_profit, deducted_net_profit(扣非), extras` |
| `fin_balance` | 资产负债表，评分核心科目全部实体化 | `total_assets, cash, trading_fin_assets, notes_receivable, other_current_assets, total_liabilities, equity_parent, equity_total, paid_in_capital, short_loan, long_loan, bond_payable, lease_liability, noncurrent_due_1y, extras` |
| `fin_cashflow` | 现金流量表 | `ocf, capex, cash_received_from_sales(销售收现), extras` |

`fin_balance` 里那一长串借款/债券/租赁列是为**净现金**和**格雷厄姆数字**服务的，不是冗余列。季度报告期统一按自然季末日；港美股财年归一化到 12-31 只为与 A 股同轴对齐（见 §3 读法）。金额一律本币原值不折汇率。

### 10.3 `score_daily` — 每日评分快照

PK `(sid, trade_date)`，`report_date` 记录这份评分基于哪期财报。列表页所有筛选/排序/买卖点判定都在这张表 + `quote_daily` 上完成 SQL，**它的索引就是性能预算**：`idx_list_fraud/mgmt/cycle/graham_agg/graham_def/schloss/buffett`，均为 `(trade_date, 该列)`，让「取最新日 + 按某列过滤或排序」走覆盖索引（EXPLAIN 应为 `ref` + `Backward index scan`）。

| 列组 | 列 | 含义 |
|---|---|---|
| 四派分 | `score_graham_agg / _def / score_schloss / score_buffett` | 0~100，越高越符合该流派标准 |
| 辅助分 | `fraud` / `mgmt` / `cycle` | 造假可能性（**越低越好**）/ 管理层水平 / 周期位置；配套 `cyclical`、`cycle_trend` |
| 价值锚 | `fair_liq` / `net_cash_ratio` / `net_cash_calc` | 清算价值每股 / 净现金占市值 / 净现金计算过程 JSON（可复算） |
| 价格参考 | `buy_<派>` / `sell_cons_<派>` / `sell_fair_<派>`（12 列） | 买入价 / 保守卖出价 / 公允卖出价 |
| Wind 增量 | `wind_fraud_delta` / `wind_mgmt_delta` / `wind_flags` / `wind_overlay` | 事件对基础分的加减；标签数组；`events/index.json` 的 `byCode` 条目全量透传（详情页 ⑥⑦⑨ 读它） |

### 10.4 报告与分红

**`periodic_report`** | PK `id` | UK `(sid, report_date, category)`  
`category` ∈ 年报/半年报/季报/业绩预告；`pdf_url` 巨潮官方直链；`detail_url` 公告页；`audit_firm`、`audit_opinion` **只从年报 PDF 解析**，覆盖率约 1/4 行。库内最大的表（≈151 份/票，满量外推 ≈80 万行），只按 `sid` 单家查，不参与列表 JOIN。

**`dividend`** | PK `id` | UK `(sid, div_year, div_type)`  
`bonus_per_10`（每 10 股派息，元）、`transfer_per_10`（转增）、`announce/record/ex/pay_date` 四个日期。

### 10.5 Wind 事件与股东

**无自然唯一键 → 按 sid 先删后插**（`INSERT IGNORE` 在这两张表不生效）。

| 表 | 列要点 |
|---|---|
| `wind_event` | `etype`（增减持/并购/违规/诉讼/ST）、`event_date`、`title`、`detail` JSON |
| `wind_holder` | `holder_type`（`top10/top10_float/institution/controller/unlock`）、`report_date`、`rank_no`、`holder_name`、`shares`、`pct` 及变动；已透视成「每家每期每名次一行」 |

只覆盖手工抓过 Wind 的少量标的，全市场需要单跑 `events`。

### 10.6 农价与 EDB

`agro_product`（6 个产品，`config` 存抓取源配置）｜`agro_price`（PK `(product_id, price_date, source)`，**同日多源共存**，靠 `source` 区分不覆盖）｜`edb_indicator`（44 个指标，`freq` day/week/month、`display_group` 前端分组）｜`edb_value`（PK `(edb_code, data_date)`）。

农价断档会被计成失败但不拦回灌：单个品种序列末日距今超过 **21 天**即计入 stale，`fetch_prices.py` 退码 3、job 记 failed 且 message 带品种名单。阈值取 21 而不是 7 是因为生意社每周只更新 2~4 次，季节性停更本身就是信号。**旧价格仍照常入库**，页面显示「数据截至 …」，所以看到 agro 红一条先看品种名单而不是先查链路。EDB 侧同族退码是 **4**（合并异常 → 不写盘）。

### 10.7 `etl_job_log`

`job_name, started_at, finished_at, status(running/success/failed), message, stats JSON`，索引 `idx_job_name(job_name, started_at)`。**查任何一次采集是否成功、灌了多少行，第一站就是它**：

```powershell
cd backend; python -X utf8 -m scripts.job_status -n 30
```

抓取失败也会回灌已落盘的数据。

### 10.8 量级与回灌行为

行数自查（`table_rows` 是估算值，看量级足够）：

```sql
SELECT table_name, table_rows FROM information_schema.tables
WHERE table_schema='db_va' ORDER BY table_rows DESC;
```

| 表 | 满量（按密度外推） | 增长 |
|---|---|---|
| `security` | ≈7000（A + 港股通 + 美股成分） | 周六 `deep` 增量 |
| `quote_daily` / `score_daily` | 7000 × 交易日数 | **各 ≈7000 行/交易日**（≈175 万行/年） |
| `fin_*` 四表 | ≈22 万（实测 31.8 期/票） | 只在周六随财报季变动 |
| `periodic_report` / `dividend` | ≈80 万 / ≈8 万 | 周六增量 |
| `wind_event` / `wind_holder` | 手工范围，百级 | 仅 `events` |

`quote_daily`/`score_daily` 是唯一会持续膨胀的两张表，多年后如需控量按 `trade_date` 分区或归档即可——业务查询都带最新日条件。

**回灌注意事项：**

- `import_legacy` **默认是「清空重灌」，只有 `--no-clean` 才安全**；`--only-fresh` 必须配 `--no-clean`（否则 argparse 直接报错退出）。
- `fin_*` 四表 + `dividend` + `periodic_report` 按唯一键 upsert，所以数据源的修订值与后加字段能刷进库。超列宽的长文会被截到列宽、定点列越界值置 NULL（真值无损保存在 `extras` 里），崩溃批次退回逐行只丢装不下的行，计数在 `<表>.clipped` / `.out_of_range` / `.bad_rows`。
- **农价/EDB 两族例外**：即使 `--no-clean`，也会跟着源做删除（按主键差集清掉源里已不存在的行，计数在 `agro_price_stale_deleted` / `edb_value_stale_deleted`）。因为采集端会主动丢弃「本轮窗口内却没重新解析到」的日期，只 upsert 不删会永久背离。

`verify_filters` 的 FAIL 形态本身就是诊断信息：

| 形态 | 含义 | 处置 |
|---|---|---|
| `local` 明显大于 `api` | 库落后于源——深抓还在推进，或该回灌了 | `import_legacy --no-clean`（不带 `--only-fresh`）后复验 |
| `api` 大于 `local` | 库里有源已删除的行，或口径漂移 | 全量 clean 重灌（源即权威） |
| 个别字段值不等 | 该列在库里为空，多为增量窗口没覆盖到 | 同上，全量重灌 |

深抓进行中 `verify_filters` 大面积 FAIL **属预期**（源已几千只而库还是上一轮的子集），不要据此判定功能坏了。两条已验证的口径不要改回旧写法：行情/评分期望值以 `index.json` 为准（明细会比它旧）；任何验证逻辑都不要逐只读文件。

## 12. 已知边界

看页面时遇到下列情况都是正常的，不是坏了：

1. **没有历史行情**：`quote_daily` 自 2026-09-02 起才有数据，此前只有最新快照，所以 K 线、回撤、年化波动类功能暂无数据基础。
2. **评分一周算一次**：四派分、买卖参考价是财务的函数，只在周六 `deep` 重算（见 §5）。
3. **新上市标的要等周六**才进池。
4. **港股范围 = 港股通（≈621 只），美股范围 = 五大指数成分并集（≈765 只）**，都不是全市场。名单外的标的（含 TSM/ASML 这类在美上市的外国公司）需要手工 `--codes` 补。`--all-market` 只作用于 A 股。
5. **港美股现价停在最后一次周六**：日更快照走的腾讯接口字段位是 A 股专用。
6. **美股没有 PB、分红与定期报告**：数据源不提供，相关列显示 `-`。PB 缺失不影响评分（用财报每股净资产反推）。
7. **港股没有定期报告与审计意见**：详情页 ⑥ 审计口径缺失、⑨ 事件区空白。
8. **审计意见覆盖率 <100%**：部分东财 PDF 解析会静默失败，字段留空，不阻断抓取。
9. **金额不折汇率**：跨市场比数值会误读，只有角标提示。跨市场请用比率列。
10. **美股报告期只有年报口径**，统一归一到 12-31，单季字段留空 → 详情页季视图退化成报告期序列。金融/REIT 类美股的每股收益留空（口径不可比）。
11. **Wind 事件覆盖有限**：一次性手动抓取，只覆盖少量标的，所以详情页 ⑨ 与列表页增强分大片 `-`。Wind 积分是硬约束，`edb` 是唯一自动使用它的任务。
12. **跨零点收口的轮次会让「快照日期」比行情日期大一天**，不影响排序/筛选/评分（都取最新快照），下一次日间回灌自然归位。

## 13. 二次开发约定

- **加字段**：先考虑 `extras` / `wind_overlay` 这类 JSON 列能不能装；必须建实体列时，同步改 `app/models/entities.py` → `docs/schema.sql` → `import_legacy` 的列白名单 → `verify_*`。
- **`extras` 不要做白名单裁剪**：详情页的财务表是用 `Object.keys(row)` 反黑名单渲染的，`extras` 里每个中文科目名都是一张看得见的列——砍字段等于直接删表。
- **加筛选列**：`score_daily`/`quote_daily` 上新的排序/过滤列，列表页要用就**必须补 `(trade_date, col)` 索引**，并在满量规模下 EXPLAIN 一遍。
- **不改前端为「逐只取数」**：列表字段全在 `SecurityItem` 里，新增列请扩 `SecurityItem` 而不是让前端二次请求。
- **详情页渲染在 `frontend/src/lib/stockLegacy.js`**（靠 DOM id 对接），改结构比改 Vue 危险，动手前先确认 `renderDetail` / `show()` 的契约。
- **`stockLegacy.js` 会被 Node 整体 import 做评分双实现比对**，禁止引入任何顶层浏览器 API（`ResizeObserver`、`navigator.*`、`document.documentElement`、顶层 `echarts` 调用），也不得 `import 'vue'`——否则 parity 直接崩。需要视口判断就在函数体内读 `mqMobile.matches`。
- **移动端断点是 600px，四处同步**：`lib/useMediaQuery.js` 的 `MOBILE_QUERY`、`stockLegacy.js` 的 `mqMobile`、`assets/stock.css` / `assets/agro.css` / `style.css` 的 `@media`。漏一处就会出现 CSS与 JS 判断不一致。
- **抓取脚本别用 `print` 打进度**：`--quiet` 语义要保留，长任务统一用 `tqdm` + `flush_every`。
- **提交前**：§11 的验证全绿，且不带进 `companies/`、`index.json`、`.env`、`run/`。
