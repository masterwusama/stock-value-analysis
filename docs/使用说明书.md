# A 股价值分析系统 · 使用说明书

> 更新时间：2026-09-03 ｜ 适用规模：全 A 股（沪深京 ≈ 5553 只）+ 港股通标的（≈ 621 只）+ 美股五大指数成分（≈ 765 只），名单全部自动拉取

## 0. 一分钟看懂：数据怎么流

```
外部数据源                    采集层（collector）              服务层（app）              界面
─────────────                ────────────────────            ──────────────            ──────
腾讯 qt.gtimg.cn   ─┐        scripts/fetch_data.py
东财 datacenter    ─┤  抓取   scripts/scoring.py       回灌    FastAPI :8000           Vue3 SPA
巨潮 cninfo        ─┘   ↓    scripts/universe.py       ↓      /api/securities        （hash 路由）
本地 Wind CLI      ──→ data/companies/*.json  ──→  scripts/import_legacy.py ──→  db_va(MySQL 20 表)
                        data/index.json                    ↓                          ↓
                    portfolio/data/*.json ←─ portfolio_engine.py ─────────→ /api/portfolio
                    生意社 / Wind EDB      ──→ agro-price/scripts/*  ────→ /api/agro  ─→ /#/agro
```

三条铁律，理解了就不会用错：

1. **采集层产出静态 JSON，MySQL 只是"服务层投影"**。`collector/data/` 是真源，`import_legacy.py` 单向灌库；库里改东西下一次回灌会被覆盖。
2. **`index.json` 是全市场时代的入口，不是明细**。5500 只明细约 1.9 GB，任何新代码都不许"逐只读文件"，只读 `index.json`（≈ 5.5 MB）。
3. **节奏分两层**：日更只刷行情（分钟级），财务/报告/审计一周一次（周六，小时级）。见 [§4](#4-数据从哪来采集层)。

## 2. 首次部署

前提：Windows + Python 3.10（代码用了 `X | None` 联合类型写法，3.10 起支持）+ Node 20 + MySQL 8 已安装，MySQL 服务在 3306 运行。

```powershell
# 1) 建库
mysql -u root -e "CREATE DATABASE IF NOT EXISTS db_va DEFAULT CHARSET utf8mb4;"

# 2) 装依赖
cd <项目目录>\backend
pip install -r requirements.txt -r collector\scripts\requirements.txt

# 3) 配环境
Copy-Item .env.example .env    # 然后编辑：DATABASE_URL、LEGACY_DATA_DIR、BOND_10Y

# 4) 建表（按 ORM 元数据 create_all，等价 docs/schema.sql）
python -X utf8 -m scripts.create_tables

# 5) 首轮全市场深抓（≈5 小时，可中断续跑）
python -X utf8 -m collector.run deep

# 6) 全量回灌 MySQL
python -X utf8 -m scripts.import_legacy --no-clean

# 7) 构建前端并启动服务 + 调度器
cd ..\frontend; npm install; npm run build; cd ..\backend
cd ..; .\ops\start.ps1 -Rebuild
```

浏览器打开 <http://127.0.0.1:8000/>。第 5/6 步只在首次或换机器时需要，之后交给调度器。

**`.env` 三个键**

| 键 | 例值 | 说明 |
|---|---|---|
| `DATABASE_URL` | `mysql+pymysql://root@localhost:3306/db_va?charset=utf8mb4` | 无密码时不要写 `@` 之外的空字段 |
| `LEGACY_DATA_DIR` | `<项目目录>\backend\collector` | 采集产出根目录。本仓库自给自足，**不再依赖博客仓库** |
| `BOND_10Y` | `0.017` | 十年期国债收益率，用于 EPV/DCF 折现 |

## 3. 日常使用

### 3.1 四个运维脚本

| 命令 | 作用 |
|---|---|
| `.\ops\start.ps1` | 起 FastAPI + 调度器（已在跑则逐个跳过）。`-Rebuild` 先构建前端，`-NoScheduler` 只起服务，`-Lan` 监听 `0.0.0.0` |
| `.\ops\stop.ps1` | 关服务 + 调度器 + 采集子进程。`-Api` / `-Scheduler` 单关，`-KeepJobs` 保留正在跑的抓取。会写 `run/.paused` 让守护让路 |
| `.\ops\status.ps1` | 一屏看：MySQL、服务 PID、健康检查、前端产物、采集进程、**抓取锁**、**index.json 条数/时间/体积** |
| `.\ops\guard.ps1` | 幂等拉起（崩溃自愈）。稳态只查进程表，亚秒返回；缺失才派生 `start.ps1`；`run/.paused` 存在时静默让路 |

进程识别按**命令行特征**匹配（不是 PID 文件），换机器不会状态错乱。崩溃自拉起靠 Windows 计划任务，本机已于 2026-09-03 注册（每 10 分钟一次，只登录模式）；**换机器要重跑一次这条命令**：

```powershell
schtasks /Create /TN "va-guard" /SC MINUTE /MO 10 /F `
  /TR "powershell -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File <项目目录>\ops\guard.ps1"
# 验：schtasks /Run /TN va-guard 后看 run/guard.log 新增一行“服务在线,无动作”，
#     以及 schtasks /Query /TN va-guard /V /FO LIST 的“上次结果 = 0”
```

两个坑：

- **杀软会盯上 `guard.ps1`**（隐藏窗口 + `-ExecutionPolicy Bypass` 派生子进程，典型恶意脚本特征）。2026-09-03 实测：文件被实时防护截成 **0 字节**，而且读它会报 `ERROR_VIRUS_INFECTED`（Python 侧看是 `OSError 22 Invalid argument`）——症状像“文件被别的进程锁住”，但内容其实没丢（编辑器缓冲区里还在）。处置：关掉防护或把 `ops/` 加排除项 → 重新保存文件 → 再注册任务。
- **受限上下文里不能拿 guard 的判活结果当真**：沙箱里 `Get-CimInstance Win32_Process` 查不到 python 进程，guard 会误报 `缺失(api=0 scheduler=0)` 并白拉一次 `start.ps1`（`Start-Svc` 幂等，不会弄坏在线服务）。以计划任务自己跑出来的 `run/guard.log` 行为准（实测计划任务上下文能正确识别两个服务）。

`run/.paused` 这个停机标记由 `stop.ps1` 写、`start.ps1` 删（以前只有文档里提过、脚本里并没实现，2026-09-03 补齐：没它的话手动 `stop.ps1` 会在 10 分钟内被守护复活，等于关不掉）。

双击用：`ops\start.bat` / `ops\stop.bat`。

### 3.2 列表页 `/#/`（主战场）

全市场 5500 只下"逐页翻"不现实，所以筛选被拆成**先缩范围、再排序**：

- **市场 tab**：全部 / A股 / 港股 / 美股（切换时清空板块）
- **板块 tab**：全部板块 / 沪主(60) / 深主(00) / 创业(30) / 科创(68) / 北交(92,83,87,43)——按代码前缀判定，纯 SQL 下推
- **行业下拉**：字典跟着市场走（A 股国标行业、港股恒生行业、美股东财中文行业），走 `/api/securities/industries?market=`，只数也是本市场口径
- **剔除 ST**：名称含 `ST`/`*ST` 的低 PB 假便宜重灾区
- **关键字**：代码或名称模糊匹配（输入防抖）
- **分数门槛**：造假 ≤ / 管理 ≥（空 = 不限；`周期` 只能作为排序列，暂无门槛输入框）
- **市值区间**：市值 ≥ / 市值 ≤（筛选栏数字框，**单位是亿**，与列头 `市值(亿)` 同口径；接口参数 `cap_min`/`cap_max` 接受**本币元**，前端 ×1e8 换算并 `Math.round` 掉浮点尾差）。只筛 `quote_daily.market_cap`，无最新行情的公司（列显示 `-`）不进区间。 重要口径：**市值是本币计价（A 股人民币、港股港元、美股美元），不折汇率**——汇率源未落地，拿估算值折算只会让人误以为是可比口径；故“全部”tab 下三个市场的数值在同一门槛里混比没有意义，要跨市场比体量就切到对应市场 tab 分开筛
- **事件增强分切换档**（筛选栏最左，只在「全部 / A股」tab 出现）：把`造假`/`管理`两列从**基础财报分**切到**基础分 + Wind 事件增量**（`score_daily.wind_fraud_delta` / `wind_mgmt_delta`，结果钉 0~100），档位记在 `localStorage.va_wind`。
  切换后**两列的排序与门槛筛选同步跟随**（后端 `_wind_score()` 与前端 `dispScore()` 是同一公式，不会出现“按增强分排、按基础分筛”的错位），代价是这两列排序不再命中 `idx_list_*` 覆盖索引；
  无事件条目的公司两列显示 `-`、并被门槛筛选自动排除。Wind 事件是一次性手动抓取、目前只覆盖 21 家 A 股，故按市值排序时整屏 `-` 属正常，想看增强分就按「造假」列降序或直接搜代码。
  响应里 `fraud` / `mgmt` **恒为基础分**（不随 `wind` 变），另给 `wind_hit` / `wind_fraud_delta` / `wind_mgmt_delta` / `wind_flags` 四个溯源字段供前端算显示值与悬停提示
- **买点**：四派多选 + 折扣 %（现价 ≤ 买参考价 × 折扣即命中）
- **卖点**：四派多选（须同时达保守价与公允价才算命中，口径同原静态站）
- **排序**：点表头，`PE/PB/市值/四派分/造假/管理/周期/清算/净现金` 均可，走 `score_daily` 上的覆盖索引；
  四派参考列沿用原站语义——**列头按买入价排**，格内保守/公允两档小字各自点击排对应卖价，
  高亮箭头归一到列头（升序时 NULL 沉底，避免参考价缺失时一屏 `-`）
- **分页**：每页 50/100/200（默认 50）+ 跳页输入框
- **布局**：`.page` 随视口铺开（`width: min(100%, 1780px)`，旧值 `max-width: 1280px` 装不下 20 列）；
  列表表宽靠三项压缩到 ≈ 1141px（表头可折行、单元格 `padding: 6px`、行业名 `max-width: 112px` + `title` 截断，
  改造前 ≈ 1612px），≥ 1240 CSS px 视口即无横向滚动；仍装不下（高分屏高缩放比）时首列`position: sticky` 吸左兜底

列含义：`代码/名称｜行业｜现价｜涨跌｜PE(TTM)｜PB｜市值(亿)｜格进取｜格防御｜施洛斯｜巴菲特｜造假｜管理｜周期｜清算｜净现金/市值｜格进取 买/保/公｜格防御 买/保/公｜施洛斯 买/保/公｜巴菲特 买/保/公`。最后四列是**竖排三行**：买入价 / 保守卖出价 / 公允卖出价。

## 4. 数据从哪来：采集层

### 4.1 任务一览

统一入口 `python -m collector.run <job>`（在 `backend/` 下执行），每个 job 的产出都写 `etl_job_log`：

| job | 内容 | 参数（`run.py` 内 `JOB_DEFAULTS`） | 规模耗时 |
|---|---|---|---|
| `stock` | ①全市场行情快照 ②组合按交易日调仓 ③增量回灌 | `fetch_data --all-market --snapshot-only --quiet` → `portfolio_engine` → `import_legacy --only-fresh 26 --no-clean` | **≈1~2 分钟**（行情 58 秒） |
| `deep` | 全市场财务四表/指标、分红、定期报告、审计意见（只解析年报）、评分重算、新标的进池 | `fetch_data --all-market --hk-connect --us-indexes --workers 4 --resume --max-age 6 --chunk 400 --flush-every 200 --audit-scope annual --quiet` | **≈6 小时**（港股通 621 只 + 美股成分 765 只都走 `fetch_company_hk`/`_us`，不碰 PDF；2026-09-02 实测港股 621 只 / `--workers 6 --chunk 60` 只 7 分钟，2026-09-03 实测美股 765 只同参数 13 分钟；`--workers 4 --chunk 400` 各按 30 分钟估） |
| `agro` | 生意社 6 产品价 + 44 个 EDB 指标 + 回灌 | `agro-price/scripts/fetch_prices.py`、`fetch_edb.py` → `import_legacy` | 分钟级 |
| `events` | Wind 结构化事件（增减持/并购/违规/诉讼/ST）+ 股东结构（前十/流通/机构/实控人/解禁），重算 `wind_*` 覆盖层 | `fetch_events.py [--codes …\|--force\|--recompute\|--limit N]` | 手动，不进调度 |
| `import` | 只回灌（不抓取） | `import_legacy --only-fresh 26 --no-clean` | 秒~分钟 |

`deep` 的两个关键参数：`--resume` 跳过 `mtime` 在 `--max-age`（6 天）内的明细文件，所以中断/重跑都不重复劳动；`--audit-scope annual` 把最贵的年报 PDF 解析只用在年报，周六一轮约省 40% 时间。

### 4.2 时刻表（`scheduler.py`）

| 时间 | 任务 | 说明 |
|---|---|---|
| 周一~周六 16:05、22:05 | `stock` | 原 Actions cron `0 8,14 * * 1-6`（UTC）顺延 5 分钟等数据源落库 |
| 周六 09:05 | `deep` | 全市场财务重抓，避开工作日行情时段 |
| 每天 09:05、21:05 | `agro` | 生意社每周更新 2~4 次，一天两次足够 |

改节奏直接编辑 `scheduler.py` 的 `add_job` 后重启调度器。不想常驻就用 Windows 计划任务直接调 `python -m collector.run <job>`（`schtasks` 示例见 `scheduler.py` 文档串）。

### 4.3 抓取互斥锁（务必理解这一条）

`fetch_data.py` 启动时抢 `data/.fetch.lock`（内容 = 父进程 PID）：

- 锁存在且持锁 PID **存活**、且锁文件在 45 分钟内被刷过 → 打印 `[lock] 已有抓取在跑（PID …，持锁 N 分钟），本次退出`，**退出码 2**
- 抓取过程中 `save_index()` 会 `touch` 锁文件作心跳；只有真卡死才会被 45 分钟超时接管
- `run.py` 侧同口径判活，把"锁被占"翻译成 `etl_job_log` 里的 `skipped` 而非失败

所以：**深抓期间到点的 `stock` job 会静默跳过，这是设计而非故障**（深抓本身每只都带当日行情）。想立刻确认有没有卡在锁上：`.\ops\status.ps1` 看"抓取锁"一行，`已死(可删后重跑)` 时手动 `Remove-Item backend\collector\data\.fetch.lock`。

Windows 判活不能用 `os.kill(pid, 0)`——它走 `OpenProcess`，失败抛 `WinError 87` 且被 CPython 包装成 `SystemError`，会逃出 `except OSError`。实现统一用 `kernel32.OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` + `GetExitCodeProcess` 比对 `STILL_ACTIVE=259`（`fetch_data._pid_alive` 与 `run._pid_alive` 同口径两份）。

## 5. 数据库表内容说明（`db_va`，20 张表）

### 5.0 通用约定

- **`security.sid` 是唯一内键**，所有子表用 `sid` 外联，不用 `(code, market)` 复合键。
- **金额一律为元、比率一律为小数**（`0.35` 表示 35%），与原 JSON 服务口径一致。
- **中文长尾科目进 `extras` JSON**，核心评分/展示科目才建实体列——加字段优先塞 `extras`，别急着改表。
- **主键即幂等**：除三张标注"无自然唯一键"的表外，回灌都是 `INSERT … ON DUPLICATE KEY UPDATE`。
- 建表 DDL 存档在 [`docs/schema.sql`](schema.sql)，与 `app/models/entities.py` 同构。

### 5.1 主数据与行情

**`security` — 证券主表（全市场清单）** | PK `sid` | UK `(code, market)`

| 列 | 含义 |
|---|---|
| `code` / `market` | 代码 + 市场枚举 `A/HK/US` |
| `name` / `industry` / `exchange` | 名称（含 ST 前缀原样保留）、行业、交易所 |
| `currency` | `CNY/HKD/USD`（由 market 映射） |
| `status` | `active/suspended/delisted` |
| `list_date` / `updated_at` | 上市日（当前多为空）、行更新时刻 |

写入方：`import_index_snapshot`（每次 `stock`/`import` 全量 upsert）。退市股不会被自动删除——名单源只含在市标的，需要人工或后续加清理逻辑。索引 `idx_market_industry` 支撑行业筛选。

**`quote_daily` — 每日行情/估值快照** | PK `(sid, trade_date)` | `idx_quote_date(trade_date)`

`price, change_pct, pe_ttm, pb, market_cap, float_market_cap, turnover_rate, fetched_at`。八个字段全部来自腾讯批量行情（PE 为 TTM 口径、市值为**本币元**——A 股人民币、港股港元、美股美元，不折汇率）。**每票每交易日一行**，是"历史"唯一的积累处——本表从 2026-09-02 起才有数据，此前没有历史行情可回补（静态站只存最新快照），所以 K 线/回撤类功能暂无数据基础。

### 5.2 财务明细（报告期维度，`PK (sid, report_date)`）

| 表 | 内容 | 关键列 |
|---|---|---|
| `fin_indicator` | 同花顺口径摘要指标，**评分主要输入** | `revenue, net_profit, eps, bps, gross_margin, net_margin, roe, current_ratio, quick_ratio, debt_ratio, ocf_per_share, revenue_q, net_profit_q, extras` |
| `fin_income` | 利润表 | `revenue_total, operating_profit, net_profit, deducted_net_profit(扣非), extras` |
| `fin_balance` | 资产负债表，**评分核心科目全部实体化** | `total_assets, cash, trading_fin_assets, notes_receivable, other_current_assets, total_liabilities, equity_parent, equity_total, paid_in_capital, short_loan, long_loan, bond_payable, lease_liability, noncurrent_due_1y, extras` |
| `fin_cashflow` | 现金流量表 | `ocf, capex, cash_received_from_sales(销售收现), extras` |

`fin_balance` 里那一长串借款/债券/租赁列是为**净现金**和**格雷厄姆数字**服务的，别当冗余删。季度报告期统一按自然季末日（`03-31/06-30/09-30/12-31`）；港股/美股的财年被归一化映射到 12-31。**金额一律是本币原值不做汇率折算**（港股=港元、美股=美元，`security.currency` 区分），列表页现价/市值列对非 A 股带 `HKD`/`USD` 角标提示。

### 5.3 `score_daily` — 每日评分快照（本系统的心脏）

PK `(sid, trade_date)`，`report_date` 记录这份评分基于哪期财报。列表页所有筛选/排序/买卖点判定都在这张表 + `quote_daily` 上完成 SQL，因此**它的索引就是性能预算**：`idx_list_fraud/mgmt/cycle/graham_agg/graham_def/schloss/buffett`（均为 `(trade_date, 该列)`，让"取最新日 + 按某列过滤/排序"走覆盖索引，EXPLAIN 应为 `ref` + `Backward index scan`，不是全索引扫）。

| 列组 | 列 | 含义 |
|---|---|---|
| 四派分 | `score_graham_agg / _def / score_schloss / score_buffett` | 0~100，越高越符合该流派标准 |
| 辅助分 | `fraud` | 财报造假可能性（0~100，**越低越好**） |
| | `mgmt` | 管理层水平（0~100） |
| | `cycle` | 周期位置分；`cyclical` 是否周期股、`cycle_trend` `up/down/…` |
| 价值锚 | `fair_liq` | 清算价值/股；`net_cash_ratio` 净现金/市值；`net_cash_calc` 净现金计算过程 JSON（可复算） |
| 价格参考 | `buy_<派>` / `sell_cons_<派>` / `sell_fair_<派>`（12 列） | 买入价 / 保守卖出价 / 公允卖出价 |
| Wind 增量 | `wind_fraud_delta / wind_mgmt_delta` | 事件对基础分的加减 |
| | `wind_flags` / `wind_overlay` | 事件标签数组；`events/index.json` 的 `byCode` 条目全量透传（详情页 ⑥⑦⑨ 读它） |

**重要口径**：四派分与 12 个价格参考列是**财务的函数**，只在 `deep` 时重算；`stock` 只刷 `quote_daily` 的价。所以"是否触发买点"= 今天的 `price` 去比上周的 `buy_*`，这是有意为之（内在价值不随日内价格变化）。`wind_overlay` 只在 `events` 任务后更新。

### 5.4 报告与分红

**`periodic_report`** | PK `id` | UK `(sid, report_date, category)`  
`category` ∈ 年报/半年报/季报/业绩预告等；`pdf_url` 巨潮官方直链；`detail_url` 公告页；`audit_firm`、`audit_opinion`（标准无保留/带强调事项段/保留…）**只从年报 PDF 解析**，故覆盖率天然低于报告数（当前约 1/4 行有审计意见）。密度实测 **≈151 份/票**（2026-09-02：908 家 → 13.7 万行），全市场满量外推 **≈80 万行**，是库内最大的表——只按 `sid` 单家查，不参与列表 JOIN，所以不影响接口延时。

**`dividend`** | PK `id` | UK `(sid, div_year, div_type)` | `idx_div_sid_ex`  
`bonus_per_10`（每 10 股派息，元）、`transfer_per_10`（每 10 股转增）、`announce/record/ex/pay_date` 四个日期。密度 ≈14.5 行/票，满量外推 ≈8 万行。组合引擎用它做除权与分红入账。


| 形态 | 含义 | 处置 |
|---|---|---|
| `local` 明显大于 `api`（`diff` 全是 index 里有、库里没有的代码） | **库落后于源**——深抓还在推进，或该回灌了 | 跑 `import_legacy --no-clean`（不带 `--only-fresh`）后复验 |
| `api` 大于 `local` | 库里有源已删除的脏行，或口径漂移 | 全量 clean 重灌（源即权威） |
| 个别字段值不等（如 `('000001', 11.41, None)`） | 该列在库里为空，多为增量窗口没覆盖到 | 同上，全量重灌 |

深抓进行中 `verify_filters` 大面积 FAIL **属预期**（源已 2000+ 只而库还是上一轮回灌的子集），不要据此判定功能坏了。另外两条已验证过的口径不要改回旧写法：

- 行情/评分期望值以 `index.json` 为准，不是 `companies/*.json`——日更只刷 index 的 `quote`，明细会比 index 旧。
- 任何"逐只读文件"的验证逻辑在全市场下必须改为只读 `index.json`。

## 7. 运维手册：症状 → 处置

| 症状 | 根因 | 处置 |
|---|---|---|
| `[lock] 已有抓取在跑…` + 退出码 2 | 正常互斥 | 不用管。要强行接管：`status.ps1` 显示持锁 PID **已死** 时 `Remove-Item data\.fetch.lock` |
| 抓取落盘变慢/停止 | 先别当成“卡死”，**三种成因长得一模一样**（都是文件不涨 + CPU 低）：① 工人挂在第三方读上（akshare 内部 requests 不传 timeout，实测定点在 `stock_financial_report_sina` 的 `ssl.read`）；② **`--chunk` 是静态切块**，一个工人领完一块（默认 400 只）才领下一块，先跑完的就空转，尾巴压在少数人身上→整体速率可从 17 只/分钟掉到接近 0；③ 真在跑只是慢（`601xxx` 年报 PDF 单份 30MB+）。注意 **CPU 低不能证明挂死**（本任务是 I/O 密集型，正常时 CPU 也很低），**TCP 仍 `Established` 也不能证明活着** | 用 **py-spy 看栈顶**定性（唯一可靠手段）：`py-spy dump --pid <工人PID>`——停在 `queue.get`/`_recv_bytes` = **在等活**（降 `--chunk` 到 60-100 重跑即可）；停在 `ssl.read`/`read_chunked` = **真挂起**。传输层已补 `_force_default_timeout()` 给 akshare 的不带 timeout 调用注入 `(10, 45)`（`socket.setdefaulttimeout` 对这条路径无效，别依赖它） |
| 父进程没了但 CPU 仍在烧 | **孤儿 spawn 工人**——只杀父进程会留下它们继续打数据源 | `.\ops\stop.ps1`（`Find-JobProc` 已匹配 `multiprocessing\.spawn\|fetch_data\.py`） |
| 服务起不来、`run/api.err.log` 有连接错误 | MySQL 没起 / `.env` 密码错 | 启 MySQL 服务；`Test-NetConnection 127.0.0.1 -Port 3306` |
| 页面空白但 API 正常 | `frontend/dist` 不存在或过旧（uvicorn 启动时才探测 dist） | `.\ops\start.ps1 -Rebuild` 后重启服务 |
| 列表筛"创业/科创"数量为 0 | 深抓按代码升序推进，30/68 段还没抓到 | 等 `deep` 跑完，或 `fetch_data --all-market --codes …` 定向补 |
| 推送 GitHub 失败 | 需要本机代理 | `git -c http.proxy=http://127.0.0.1:1080 push origin main` |
| 某天财务数据看着没更新 | 财务按季披露，日更本来就不碰 | 看 `deep` 最近一次 `etl_job_log` |
| 想立刻补抓失败股票 | `data/crawl_failed.json` 有清单 | `fetch_data --all-market --codes <粘贴> --audit-scope annual` 再 `import_legacy --no-clean` |

日志位置：`run/api.{out,err}.log`、`run/scheduler.{out,err}.log`、`run/guard.log`、`backend/collector/data/crawl_all.log`（+ `.err`，tqdm 进度条会写 stderr 且用 `\r`，抓摘要看 `grep '^\[' `）。

进度体检 SQL：[`backend/scripts/progress.sql`](../backend/scripts/progress.sql)（7 条只读查询：回灌完成率 / 各表覆盖只数 / 缺财务明细的票 / 最近一次写库距今 / 报告期覆盖 / 运行记录 / processlist / 体量粗览）。
要记住的边界：**抓取过的是 JSON，SQL 只能看到已回灌的部分**；抓取实时进度看 `collector/data/index.json` 的 mtime、`.fetch.lock` 内容（持锁 PID）与日志尾部。
数文件的三条命令（比日志可靠）：

```powershell
cd backend\collector
(Get-ChildItem data\companies\*.json).Count                        # 已抓总数（不区分本轮）
$w = Get-Process python | Where-Object { $_.Id -ne (Get-Content data\.fetch.lock) }  # 工人（排除持锁父进程）
($w | Measure-Object CPU -Sum).Sum; Start-Sleep 25; (Get-Process python | Where-Object { $_.Id -ne (Get-Content data\.fetch.lock) } | Measure-Object CPU -Sum).Sum
```

要分得清“慢”还是“停”，得拿**本轮增量**而不是总数（总数会把上一轮的成品算进来）：

```powershell
cd backend\collector; $t = Get-Date '2026-09-02 20:41'   # 本轮启动时刻
(Get-ChildItem data\companies\*.json | Where-Object { $_.LastWriteTime -gt $t }).Count
Start-Sleep 90
(Get-ChildItem data\companies\*.json | Where-Object { $_.LastWriteTime -gt (Get-Date).AddMinutes(-2) }).Count   # 近 2 分钟落盘数，正常应为个位数以上
```

只确认要重启后才动手，且**只杀抓取进程组**（裸 `stop.ps1` 会连带关 API 与调度器）；**只杀父进程会留下 6 个孤儿工人**（它们要么继续挂在读上，要么攬着连接不放）：

```powershell
$lock = 'backend\collector\data\.fetch.lock'
$pp   = Get-Content $lock                                  # 持锁父 PID
$kids = Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
        Where-Object { $_.ParentProcessId -eq [int]$pp }    # 只挑它的 spawn 工人，不碰 uvicorn/调度器
Stop-Process -Id (@([int]$pp) + @($kids.ProcessId)) -Force
Remove-Item $lock
# CIM 被沙箱/权限拒时（实际会遇到）：先杀父，再按StartTime=同一秒的 PID 补杀工人
Get-Process python | Where-Object { $_.StartTime -gt (Get-Date).AddHours(-1) } |
    Select-Object Id,StartTime,CPU                         # 先看清单再 Stop-Process
```

参数上的两个坑：重启时把 **`--chunk` 降到 60-100**（避开上面成因②）；长任务必须**后台启动**（前台超时会被连带杀掉，且它会被同一命令行重跑——实测发生过）。

ETA 会随板块跳变：主板 `600xxx`/`601xxx` 段要下载并解析年报 PDF（单份 30MB+），实测速率从 ≈16 只/分钟掉到 ≈8.4 只/分钟，全量 4652 只留 **4-5 小时**比按首段速率外推靠谱。但**掉到接近 0 不等于停摆**：先用 py-spy 分清“等活 / 挂起 / 真慢”再决定重启还是降 `--chunk`。

## 8. 已知边界与限制

1. **行情历史自 2026-09-02 起**：`quote_daily` 之前没有逐日数据，港美股也只有最新快照，K 线/回撤/年化波动类需求暂时做不了。
2. **新上市标的要等周六 `deep` 才进池**：`--snapshot-only` 只对 `index.json` 已有条目刷行情，不拉名单（港股通名单也一样，靠 `universe.py --dump-hk --force` 或 `deep` 刷新）。
3. **审计意见覆盖率 <100%**：部分东财 PDF 会 `MuPDF error: cannot find object in xref` 静默解析失败；字段留空，不阻断抓取。
4. **港股范围 = 港股通（≈621 只），不是全港股**：名单来自东财板块码 `b:DLMK0146,b:DLMK0144`，不在名单里的港股（如大部分仙股、只合修订买卖的品种）需手工 `--codes HK.xxxxx --codes-market HK` 补；美股边界见第 14 条。`--all-market` 只作用于 A 股。
5. **日更快照只刷 A 股行情**：`--snapshot-only` 走的腾讯批量接口（`qt.gtimg.cn`）字段位是 A 股专用，`run_snapshot_only` 也只选 `|A` 条目——**港股/美股的现价会停在最后一次 `deep`（周六）**。要日更港股，可用东财 clist 一次请求拿 621 只的 `f2/f9/f20/f23`（现价/PE/市值/PB），本轮未做。
6. **港股没有定期报告与审计意见可抓**：东财不提供港股年报 PDF 入口，`companies/<code>.json` 里 `reports=[]`、`audit=null` → 详情页 ⑥ 审计口径缺失、⑨ 事件区空白（Wind 事件也是 A 股/部分港股口径）。
7. **金额不折算汇率**：列表页跳市场排序时，港元/美元数值与人民币直接比大小会误读（只有角标提示，没做归一），要跨市场比请用 `PE/PB/评分` 类比率列。
8. **Wind 事件/股东是手工一次性抓取**，不进调度；未抓的标的详情页 ⑥⑦ 只有量化分、⑨ 空。
9. **`companies/`（≈2 GB）与 `index.json`、`universe.json`、`universe_hk.json`、`universe_us.json`、`.fetch.lock`、`crawl_failed.json` 全部 gitignore**——MySQL 才是服务层，版本库不存可再生大数据。换机器靠“重新抓取 + 回灌”，不靠 git。
10. **深抓期间到点的 `stock` 会被锁跳过**，当晚行情由深抓自身覆盖。
11. **博客仓库 `stock-data/` 的 3 个 GitHub Actions 仍在产 54 只旧静态数据**（2026-09-02 明确决定暂不动），与本仓库数据会各自漂移；以本仓库 + `db_va` 为准。
12. **`import_legacy` 默认是"清空重灌"**，只有 `--no-clean` 才安全。`--only-fresh` 现在必须配 `--no-clean`（否则 argparse 直接报错退出）——这条护栏源于 2026-09-02 的一次误操作：增量 + clean 把 `periodic_report` 从 13.7 万行打到 1.1 万行。恢复方式：`python -X utf8 -m scripts.import_legacy --no-clean`（不带 `--only-fresh`）全量重灌。另：**财务四表（`fin_*`）走 `INSERT IGNORE`**，主键 `(sid, report_date)` 已存在的行不会被覆盖，所以只改采集口径（如 2026-09-03 去掉 BRK_B 的 A 类口径每股盈利）时，`--only-fresh` 增量回灌看不出效果，必须来一次不带 `--only-fresh` 的全量重灌。**农价/EDB 两族例外：`--no-clean` 下也会跟着源做删除**（`import_agro`/`import_edb` 按 `(product_id, price_date, source)` / `(edb_code, data_date)` 差集清掉源里已不存在的行，计数在 `agro_price_stale_deleted` / `edb_value_stale_deleted`）——采集端 `merge_prices` 会主动丢弃“本轮窗口内却没重新解析到”的日期（2026-09-03 对硝基氯化苯 08-03 那条），只 upsert 不删就永久背离、`verify_api` 常红。
13. **跨零点收口的轮次会让“快照日期”超行情日期一天**：`index.updated_at` 写的是墙钟时间，而 `import_legacy` 直接拿它当 `score_daily.trade_date`；行情行的日期来自各家 `quote.time`（收盘日）。所以夜里跑过午夜才收尾的那一轮，`score_daily` 会记成次日（实测 2026-09-03 00:03 收口的港股轮 → `score_daily@09-03` 6176 行，而 `quote_daily` 最新仍是 09-02）。不影响排序/筛选/评分（都取最新快照），只是列表页“快照 YYYY-MM-DD”会比行情日期大一天，下一次日间回灌自然归位；真要抠一致就改 `import_legacy` 用 `MAX(quote_daily.trade_date)` 兜底。
14. **美股范围 = 五大指数成分并集（≈765 只），不是全美股**：`--us-indexes` 拉标普500(503) + 纳指100(102) + 道指(30) + 费半(30) + NBI(248) 的并集（一只可属多个指数，存在 `universe_us.json` 的 `indexes` 字段）。名单外的美股（含 TSM/ASML 这类在美上市的外国公司，不在上述指数里）要手工 `--codes US.TSM --codes-market US` 补。成分源与踩坑（逐条实测，别再重新探一遍）：
    - **标普500**：`raw.githubusercontent.com/datasets/s-and-p-500-companies` 的 CSV（可直连，自带 GICS 行业，但行业不用它、统一用东财中文行业保持跟 A/港股同口径）。
    - **纳指100 / 费半 / NBI**：Nasdaq 官方 `POST https://indexes.nasdaqomx.com/Index/WeightingData`（表单 `id/tradeDate/timeOfDay` → `aaData[{Name,Symbol}]`）。**日频快照且带历史**，所以代码从当天往前逐日试、跳过周末即可；注意这是**逐日变动的真成分**（实测 NBI 248@09-02 / 251@06-30 / 256@03-31），不是固定名单。道指/标普属 S&P DJI，这个端点返回空。
    - **道指30**：无免费机读接口，取维基 `Template:Dow Jones Industrial Average companies`（注意主条目里**没有**成分表，已被拆进模板）→ 模板只给**公司名**，所以 `universe.DJIA_NAME_TICKER` 维护 30 条人工映射；**道指换成分时要同步改这张表**（名字对不上会显式报错，不静默漏股）。同理费半也可以用维基条目内的 bullet 列表，但既然官方端点可用就没用它（那页数据停在 2024-09）。
    - **代理**：维基与 `indexes.nasdaqomx.com` 直连必超时，必须走本机代理（`VA_OVERSEAS_PROXY`，默认 `http://127.0.0.1:1080`）；GitHub 可直连。`universe.py` 顶部设了 `no_proxy="*"`（国内源会被本机代理截断，不能删），所以海外源靠**显式传 `proxies=` 参数**覆盖（反直觉但有效），并缓存“只认代理”的主机名，否则逐日试错会每次白等一轮直连。
    - **行业与代码存在校验**：东财全美股表（`m:105/106/107` 分三段市别，13794 只 / ≈70 s；单页硬上限 100 行，所以要 140 页）。两个坑：**只有 `push2delay` 子域应答**（push2 / 33.push2 一律 RemoteDisconnected，跟三子域轮询等于每页白跑两轮退避）；**不能加 `t:1`（普通股）过滤**，否则 ASML/TSM/PDD/SNY 这批 ADS 存托凭证全被滤掉（当时表现为“东财查无 24 只”）。分页拉不完必须抛错不能返回部分——结果按代码倒序，断在中途等于整段字母区间的股票全没有。
    - **宁缺不残**：任一路成分源失败就整体抛错不落残缺名单（有旧缓存时直接读缓存，不影响抓取）；仅当名单完全缺失时才会去联网重拉。
15. **带级股票两套写法**：东财写 `BRK_B`、标普名单/腾讯行情写 `BRK.B`，互不认账（实测 `usBRK_B` 腾讯返回空、`BRK.B` 东财报 TypeError）。落盘统一用东财形态（五个数据项里四个走东财），只 `fetch_us_snapshot` 一处试写法变体；`--codes US.BRK.B` 会归位到 `BRK_B`，不会另存一份重复文件。
16. **美股财务只有年报口径，且指标分三张表**：东财美股指标接口无单季/季度值，报告期统一归一到 12-31（NVDA 财年 1 月落上年 12-31），单季字段留空 → 详情页季视图退化成报告期序列。指标表实际有三张：通用 G / 银行 B（券商也算）/ 保险 I（REIT 也算），列名还不一致（`OPERATE_INCOME` vs `TOTAL_INCOME`、`ROE_AVG` vs `ROE`），而 **akshare 只按“代码含下划线 = 保险”选表**：金融/地产类在通用表拿到 `result=None` 直接抛 TypeError（首轮实测 75 只中招，全是 JPM/BAC/GS/O 这种权重股），BF_B（酒类 B 类）则被错送去保险表拿回空。所以 `fetch_us_indicators` 在 akshare 失败/空时自己拼请求把三张表重查一遍（filter 用裸 ticker 即可，不需要 akshare 那个带交易所后缀的映射）。另：B/I 表的 EPS 按 A 类股本口径（BRK_B 会给出 46563 美元/股），而快照价是 B 类，两相除差 1500 倍——**所以不取 `BASIC_EPS_CS`**，金融/REIT 的美股每股收益留空（美股 EPS 只喂派息率，而美股无分红接口，无损）。美股也无分红/定期报告接口（`dividends=[]`、`reports=[]`）。
17. **美股快照没有 PB**（腾讯 `us` 接口不给市净率，而现价/PE/市值只能走它）：列表页 PB 列与详情页市净率显示 `-`，不影响评分——`scoring.py` 在 `pb is None` 时用财报每股净资产反推（股价 ÷ 每股净资产，缺则归母权益 ÷ 股本），前端 `stockLegacy.js` 同口径。要补真 PB：东财全美股表已在拉 `f12,f14,f100,f20`，加个 `f23` 即可（`universe.US_EM_FIELDS`）。
