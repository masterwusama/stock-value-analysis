# 行业聚合视角（Industry View）· 结构设计 v1

> 状态：待评审（2026-10-04）。实施口径以本文为准，实施后合入《使用说明书》。
> 一句话：在「全市场个股列表」与「单家详情」之间补一层**行业横截面**——每个证监会
> 大类一行（PB/PE/PB 分位中位、四派买点密度、gate 通过率、造假/管理/周期中位），
> 回答「现在哪里便宜」，一行点击下钻到带行业预填的列表页。

---

## 1. 背景与问题

现在的页面只有两个粒度：列表页是**个股**横截面（筛选/排序），详情页是**单家**纵深。
「银行整体打到 0.5 PB 了没有」「化纤的买点密度是不是全市场最高」这类**行业层**的问题，
只能靠用户在列表页手选行业再心算——而数据全都在库里：

- `security.industry`：证监会大类，A 股 83 类**零缺失**（实测最大类「计算机、通信和其他
  电子设备制造业」700 家），建库时就有 `idx_market_industry` 索引；
- 列表页 API 已支持 `industry`（单选）/ `ex_industry`（多选排除）/ `niche` 筛选
  （`app/api/securities.py:515`），前端筛选面板已挂这些控件——**缺的不是维度，是聚合层和入口**；
- 情绪日报的 broad 板块层（`sentiment_sector`）用的就是同一套证监会大类名，天然可同名互链。

投研库的研报反复手写「行业处于周期底部」（广信、中策、明泰），行业层把这类判断量化成
一行可排序的数字，也给了研报一个引用锚。

## 2. 总体思路：动什么、不动什么

**不动**：

- 零 DDL、零回灌、零新表——**读时聚合**，与情绪温度「存储层越薄越稳」同一哲学；
- 现有列表 API、筛选语义、`security.industry` 采集口径；
- `sentiment_sector` 及情绪页（那是「当日涨停效应」的脉冲视角，与本文「估值/质量的
  水位视角」是两个轴，互不取代）。

**新增**：

- `backend/app/api/industries.py`：单文件聚合接口；
- `frontend/src/views/IndustryView.vue` + 路由 `#/industry`（导航入口挂列表页旁）；
- `backend/scripts/verify_industries.py`：集合级对账。

## 3. 详细设计

### 3.1 口径：单日切片 + 进程内聚合

取一个交易日（默认最新，`?date=` 可回看）的 `score_daily ⋈ quote_daily ⋈ valuation_pctile ⋈ security`，
market='A'，约 5,500 行**拉进 Python 算**，不在 SQL 里玩 median（MySQL 无原生 MEDIAN，
单日切片行数小，Python `statistics.median` 又快又直白）。进程内缓存 60 秒
（同日重复请求零成本），`updated_at` 随响应返回。

行业家数 <5 的类目照常返回，前端打「样本小」标——不截断（证监会大类没有天然的
「太小」线，截断就是拍脑袋）。

### 3.2 每行指标（v1 定稿 11 列）

| 列 | 定义 | 口径说明 |
|---|---|---|
| 家数 n | 该行业 A 股只数 | |
| PB / PE 中位 | `quote_daily` 当日正值的中位 | pe≤0 / pb≤0 剔除后取中位（亏损股混入会把 PE 中位拉成负数） |
| PB 分位中位 | `valuation_pctile.pb_pctile` 中位 | 停更股照进（快照语义），列头注明数据日期 |
| 买点密度 ×4 派 | `price ≤ buy_*` 家数 / **该派有买点锚的家数** | ⚠ 分母不是 n：成长股多数派无锚（资产锚/盈利锚缺位时 buy 为 NULL）。响应里同列返回 `n_anchor`，前端 tooltip 写死「分母=该派有参考价的家数」——这是本页最容易被误读的数字 |
| gate 通过 | `gate=1` 家数 / n | 与列表页硬门槛同源 |
| ST 高危 | `st_risk>0` 家数 | |
| 造假 / 管理 / 周期中位 | `fraud / mgmt / cycle` 中位 | 周期中位仅对 `cyclical=1` 的子集 |
| 股息率中位 | `div_yield` 中位 | |

刻意不进 v1：净现金比中位（口径解释成本高）、行业市值加权均值（与中位并列会打架）。

### 3.3 API

```
GET /api/industries/overview?market=A&date=YYYY-MM-DD
→ { meta: {date, anchor_note}, rows: [{industry, n, med_pb, med_pe, med_pb_pct,
     buy: {graham_agg:{hit,n_anchor}, ...}, gate_pass, st_high, med_fraud,
     med_mgmt, med_cycle, med_div}...] }
```

market v1 只收 'A'（HK 的 industry 来自另一套采集字典、口径未验，传了报 422 并说明）。

### 3.4 前端

- `#/industry`：排序表复用列表页的排序交互模式（点列头切换、再点反向），默认按
  施洛斯买点密度降序——「哪里最便宜」就是本页的默认问题；
- 每行「查看个股 →」跳 `/#/list?industry=<名>`（列表页 onMounted 读 query 预填筛选，
  需加 3 行兼容）；
- 行业短名：证监会全名太长（「计算机、通信和其他电子设备制造业」），前端静态别名表
  83 条（`lib/industryAlias.js`），未命中回退全名，别名表只在展示层、不进数据层；
- 窄屏 ≤600px 切卡片（家规）；列头固定、表体横向滚动；
- （v1.1 可选，不做也自洽）行尾附「今日涨停效应」：同名 join `sentiment_sector`
  broad 层最新一行，没有则空。

### 3.5 时序曲线：等数据自己长

行业「买点密度时间曲线」很有诱惑力，但 `score_daily` 历史只有 1 个月，画出来是噪声。
v1 只做横截面，`?date=` 参数留好；不回补历史（与买点回测的点时重构是两回事，聚合
口径以当日快照为准），半年后数据自然够画，届时加曲线列不改任何存储。

## 4. 验证

`scripts/verify_industries.py`（对齐 verify_filters 的集合级比对风格）：

1. Σn = **当日 `quote_daily` 的 A 股行数**（对账基准不用 security 总数——停牌/缺快照的
   行天然少几行，用总数会把正常缺行误报成聚合丢行）；
2. 任选 3 个行业：逐指标用独立 SQL/Python 重算比对（含「剔除负值」「有锚分母」两个口径）；
3. 买点密度抽 1 行手工对列表页：同行业筛选 + 价格≤施洛斯买价条件，家数一致；
4. `?date=` 回看与当日快照在无新数据的日期上必须逐字节一致（缓存正确性）。

## 6. 边界与不做的事

- 不做行业指数行情/K 线（那是行情产品的活，EDB 已有行业量价）；
- 不做申万行业映射（引第三方字典就要养字典；证监会大类与情绪板块同源同名，是零维护的选择）；
- 不做「行业景气打分」之类的合成分（哪列重要是用户的事，排序权交给他）。
